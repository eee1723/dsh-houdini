# Houdini trace 审计判据

审计以用户目标和实际运行事实为准。根据问题选择以下链路，不要求每个任务经过固定阶段、合同表或验证动作。

## 全链路事实表

| 链路 | 必要对照 | 常见错误结论 |
|---|---|---|
| 安装/启动/客户端交付 | Host、Bridge、helper、client 的版本/加载身份；真实客户端模块或页面 | 工具注册成功即认为界面已加载 |
| 工作区/会话 | Host cwd、DSH 选中 workspace/session cwd、现场 HIP、产物目录与确认时间 | 请求打开或缓存目录即认为切换成功 |
| 模型输入 | 当时 preset、request/header、有效 surface、runtime-context、工具/skill 曝光 | 当前源码里的指令即认为旧运行收到 |
| 资料/现场 | 返回的用户原资料与分页范围；实际节点、参数、输出、版本与 frame | 索引已读等于全文已读；工具可用等于已获取 |
| 派发/执行 | callId、runtime、request_ref、execution sequence、preflight/dispatch/write 与事务 | HTTP 超时即未执行；查询逐项失败即事务修改失败 |
| 返回/长任务 | canonical 原结果、完整文件引用、排队/运行/结束/取消状态 | 外层成功覆盖子动词失败；查回当成第二次执行 |
| 观察/呈现 | 实际图片附件与文件，图像目标/版本/隔离/坐标空间，后续模型描述 | 文件存在/像素通过/模型描述即语义正确 |
| 交付/连续修改 | 对应用户目标的最终工程、参数、保存和已验证范围；终止原因 | 有最终话术即全部完成；无证据即结果一定错误 |

重要判断引用步骤、seq 或时间。构建通过只证明源码生成与编译；被运行加载和用户路径成功须分别有证据。

## 结果与错误

分别记录 tool 传递错误、verb/API 错误、事务状态、产物语义差距与交付缺口。catch 后继续的查询保留失败条目；修改失败是否恢复由执行事实决定，不依靠错误文本猜。Undo 有效范围与文件、库安装、Python全局状态等外部副作用分开。

同一 callId 的历史回放只计一次执行。canonical runtime/sequence 另用于识别查回和长任务结果；poll、资源读取和原始执行不可混算。运行换代、回执身份与作者身份冲突是独立问题。

完成判定按核心用户目标：证据支持且交付成立可判完成；已交付但核心维度未核实说明部分完成或完成范围；任务中止、provider失败或读数缺口保留原因和已有成果。todo 不代替原目标，也不自动推翻真实交付。

## 工具与能力

能力是否应该使用，先证明当时曝光、与当时意图匹配且会改善信息或操作；不能用后来新增动词倒查旧任务。隐藏输入协议、无完整返回形状、模型读源码才能操作等是可发现性缺陷。错误说明应准确指向实际失败与下一步信息，不强迫建模方法。

目录广度只说明触达能力。调用含动词率与密度描述组合形态；只读 query 的安全面、Gate拦截、成功裸修改候选、疑似外部副作用和未知动态调用分别列出。零裸修改不证明无修改，no_scene_change 不证明无外部副作用。

根据用户意图、输入合同、执行位置、副作用、返回语义判断保留/合并/拆分/删除。一次零使用不是删除证据；明确合同重复或实现冗余可直接提出调整，无固定 trace 数量准入门。

## 内容质量与观察

测量指标必须蕴含声称：bbox不证明接合，unsigned距离不证明插入深度，driver运动不证明最终几何运动。检查最终输出的数据流、稳定实体配对、局部坐标、真实面拓扑、覆盖范围与阈值来源。手写探针也是代码，数值/计数/总判定冲突时审查检查器，不能只挑有利字段。

图片按访问 → 送达 → 描述 → 同图内容核对记录。原生图片与独立 vision工具都能提供观察；自动脚本只关联描述，不裁决它正确。投影、隐藏分支、Object Merge坐标、构图与时间影响观察对象，需与实际交付一致。文件指纹或像素差异能证明产物变化，不能证明质量。

按用户意图选验证：动态任务观察相隔帧的最终输出；参数关系观察有代表性的修改与恢复；HDA功能核对实际实例/回调和依赖；教程对照实际读取的音画与阶段工程。不为非视觉任务强制渲染，不按节点数量要求早图，不要求所有任务加载同一质量合同或采用KineFX。

外部真实性声称核对用户来源、实际检索及假设边界；引用存在不等于来源已读或命题已支持。research已曝光却未用只能是候选，模型知识与来源支持应诚实区分，不强迫与任务无关的研究。

## 性能、因果与改动

拆分 provider usage、上下文字符、工具响应时长、Houdini实际计算与用户页面响应。call-to-result可能含等待与重叠；provider累计 usage重复包含历史；reasoning是output子集。未知字段保留未知，不补费用或节省百分比。

每项发现说明触发条件、实际影响、证据强度和可能反例；从客户端、Host、Bridge、工具合同、知识、模型和审计器中定位责任。优先改准确性与真实反馈，再看信息量和操作绕路。严重度由影响与确定性决定，不由是否跨三次任务决定。

修复验证覆盖已发现反例与一条正常用户路径即可；改变解析合同使用对应格式的真实小夹具，不只改旧预期。把无法由日志验证的部分明确列为剩余范围。不要用历史guard/流程守卫当默认解决办法。
