## 1. 从表示和构造选方法

原生/VEX职责与直接网格例外统一见[入口的构造分工](../SKILL.md#构造分工)。这里按需要保留的编辑入口选择组合：尺寸用参数、轮廓用截面、走向用路径、重复件用独立源与布局；装配共享尺寸、接合轮廓或局部坐标。

按结构关系选择模块边界，同一资产可混用多种构造：

| 当前编辑目标 | 有用的构造边界 | 需要共同保持的关系 |
|---|---|---|
| 重复件的样式与分布分开修改 | 完整源组件与布局，例如轮组、连接件、门窗 | 单件形态、实例身份与安装关系 |
| 装配中各零件独立细化或运动 | 独有零件/子装配与共享安装基准，例如机壳、支架、执行机构 | 接合、间隙、转轴和运动范围；不为只出现一次的零件制造Copy |
| 改变连续外形或过渡 | 共享轮廓/控制笼上的成形与局部加工，例如流线外壳、握柄 | 曲面连续、截面与厚度；局部工序可单独观察但共同消费形体 |
| 有机形体的比例与局部形变 | 共享形体/拓扑上的控制区域与细化阶段 | 整体轮廓、连接和形变连续；不因语义上有头、躯干和四肢就强拆成独立壳 |

分治的推进方法见[任务拆分skill](../../houdini-task-decomposition/SKILL.md)。以下组合解决具体构造问题；“完整源→布局→装配”适用于重复对象，不是所有模型都需要的固定层级。

**重复件：完整源组件 → 布局模板 → Copy。** 源的粒度由用户要一起修改或替换的对象决定，源内部保留局部工序；布局维护位置、朝向、实例身份和变体。单纯箱形件可直接复用Box，组合对象先形成完整组件，详见[完整源组件](#完整源组件与布局)。Copy会传播源错误，先检查源，再核对放置后的实际输出；单个连续网格的采样点不必套成Copy。

**连续管带：路径＋截面 → Sweep。** 原生曲线不易表达的路径或半径规律可由VEX输出；保持共享端点与连续切向，让成形节点处理截面连接。逐段带端盖的短杆会产生独立壳与内部端面，适合独立杆件，不是连续管路、卷曲浮雕的默认替代。

**代码节点的边界跟随编辑职责。** 布局、形变、属性各保留需要的中间输出，紧密耦合算法不按行数机械拆分。参数化轮廓也应能完成用户预期的局部编辑；若需要手调截面，提供曲线/轮廓控制。复用源节点与数据流，避免把同一成形函数粘贴到多个分支；确需源码库时按[外部代码依赖](execution-checkpoints.md#外部代码依赖)维护。

| 目标与编辑入口 | 可用组合 | 需要明确的输入关系 | 能区分效果的观察 |
|---|---|---|---|
| 对称构件，修改一侧或对称面 | 单侧源 → Mirror；接缝按意图合并 | 复制完整源还是先裁半边；对称面位置/方向、是否保留两半与焊缝 | 改源后对应点/部件位置；接缝重复覆盖、边界和法线；整体bbox对称不能证明局部对应 |
| 重复构件，替换一份源或调整布局 | 独立源 → 带身份/方向的模板 → Copy to Points | 源原点、轴向、单位；模板数量/朝向/变体；实例与展开输出 | 换源时布局保持，改数量/间距时单件形态保持；源变大不保证无碰撞 |
| 沿路径的杆、管、带，修改走向或截面 | 中心线与截面 → Sweep | 路径与截面职责不同；开放/闭合、切向、截面朝向与端盖 | 源路径、成形截面、扭转、端边界；不要把实体边倒角与曲线扫掠混为一种操作 |
| 轴对称部件，修改径向/轴向轮廓 | 截面 → Revolve | 旋转轴、轮廓方向、与轴连接或保持开放；螺旋推进需额外构造依据 | 轮廓变化是否传到表面、边界/绕序；周向闭合不证明两端封闭 |
| 板、壳、开孔面板，改轮廓/厚度/局部边缘 | 轮廓或表面 → PolyExtrude → 孔槽/倒角 | 薄片厚化与已有实体挤出不同；保留可选的前/后/侧面 | 截面实际厚度、内面与局部间隙；平面厚化示例不保证任意曲面无自交 |
| 多截面过渡形体，局部改一个截面 | 有序截面 → Skin；已有边界间接合另按现场选择Bridge类操作 | 截面顺序、方向、接缝位置、连接方式；开放面与闭合体意图 | 截面变化和局部曲率/扭转；输出非空不证明截面正确对应或自动封口 |
| 已有形体沿曲线路径变化，保留源细节 | 源形体与目标曲线 → Path Deform | 源纵向轴、捕获范围、路径方向/起点、长度适配与截面朝向 | 路径改变后的标记点、截面与局部伸缩；这与从路径新建管面不同 |
| 弯曲/扭转/渐缩，改变幅度或作用区 | 足够采样的源 → Bend或合适的局部形变 | 作用轴、原点、捕获区、模式与输入/参考形态 | 有意选中的点如何移动，区外行为和表面形态；写角度成功不证明几何处在作用区 |
| 切除或融合体 | 先验源表示 → 单个切割/融合原型 → Boolean → 接缝与效果检查 | 分别声明Solid/Surface、输入顺序和运算意图 | 查源边界/朝向和实际切除或融合，见下节；Merge非Boolean，Fuse非实体并集 |
| 需贴合的分层外壳 | 共享接合轮廓/截面 → 各自厚度/偏移 → 壳、边框、盖面 | 共同轮廓、壁厚/间隙、各层连接方向 | 主尺寸扰动后查真实接合面；独立离缝造型或现成外部资产不强求同一生成器 |
| 平滑设计曲面 | 低密度控制笼 → 支撑结构/crease → Subdivide | 哪些曲率连续、哪些边应保持；交付拓扑要求 | 轮廓收缩、折痕和高光；细分不会自动设计孔槽、壁厚或支撑结构 |
| 有机融合 | 允许体素近似时才用VDB → 重建表面 | 体素尺寸与最小需保留结构，后续属性/UV恢复 | 薄缝/尖角保留；精密接缝和规定拓扑通常不走此路线 |

静态不变的平面无需为“高精度”均匀加密；曲线/圆弧的分段数应由轮廓误差或目标观察尺度决定。

### 完整源组件与布局

本节适用于需要重复放置或同源复用的对象。源组件表达用户希望一起修改或替换的一份完整对象：轮组可包含轮胎、轮毂和必要连接结构；铰链组件可包含叶片与销轴；门窗可包含框、面板与格栅。先在约定局部坐标中形成组件输出，再由布局放置。源内部按编辑用途保留子部件，基础Box/Tube可以共享，各组件自己的截面、加工和细化分支保持可修改。

“完整”以当前要求和编辑用途为准，不要求补齐所有不可见内部零件或在试装前完成最终细节。只出现一次的独有零件可以直接进入装配；有相对运动的内部零件保留身份、控制和变换关系，整组刚性复制不能代替其运动设计。

| 层 | 拥有的变化 | 输出与编辑入口 |
|---|---|---|
| 组件内部构造 | 轮廓、截面、厚度、局部结构与加工 | 可继续修改的源网络；内部重复结构也可使用Copy |
| 完整源组件 | 单件尺寸、局部装配与公开变体 | 例如`OUT_COMPONENT_SOURCE`，按用途命名，保留内部部件选择与材质分工；合并不要求焊成一个壳 |
| 布局 | 放置数量、位置、朝向、实例身份和变体选择 | 独立模板；组件内部各零件共同消费实例基准，不分别复制整套全局布置公式 |
| 父装配 | 与邻接件的安装关系、共享尺寸及连接件 | 消费组件的公共输出；连接件归实际共同依赖的装配层 |

源需要明确局部原点、轴向、尺寸和安装基准，内部结构相对该基准构造。完整组件外可按下游需要Pack后复制；Pack是表示/性能选择，不能代替源的可编辑结构或内容检查。局部部件身份与实例身份分别保留，复制后在实际输出核对传播，避免只凭模板点的`id`声称已能选择整件或其中零件。

形状参数与放置变换分工：改变支架跨度或面板宽度时，可以移动安装位置并重排内部结构，同时保持规定的孔径、截面或厚度；直接非均匀缩放会同时拉伸这些细节。只有设计允许整体形变时才用实例`scale`解决；不同尺寸或结构可由参数化源生成变体，确实需要逐实例构造时用相应循环，避免复制维护多份生成逻辑。单纯长方体原料仍可用Box加缩放。

按组件建立有意义的观察：先看一份源的完整形状和内部关系，再看代表性实例的朝向、尺度和装配接点。需要与邻接结构配合时，先试装少量实例或接口代理，再扩展分布。单件细化后复查受影响实例，扩大数量前解决会被共同复制的缺陷；整体远景无法说明源中的细节已正确。

后续修改可以验证边界是否有用：替换源时保留布局；改变数量或分布时保留单件形态；只细化一个部件类别时保留其他类别；调整共享尺寸时复查实际接合。检查需要符合任务范围，不要求每次执行所有修改。若这些动作需要同步改多份全局公式，先追查应共享的布局、尺寸或组件来源。

组件层次不强求固定深度。独立装饰可以在父级附着，连续曲面或跨件成形可以保留共同构造；任务只需简化代理时，源也可以是基础形体。完整源的范围以用户要编辑和观察的对象为准，容器选择见[逻辑模块](#逻辑模块与容器选择)。

依据：SideFX [Copy to Points](https://www.sidefx.com/docs/houdini/nodes/sop/copytopoints-.html)的源/模板与Pack and Instance分工，以及[实例属性](https://www.sidefx.com/docs/houdini/copy/instanceattrs.html)的变换规则。具体节点版本与参数通过`node_info`确认；方法适用不等于任意组件已验证。

### 重复规律与代码生成

数量增长应增加模板数据或运行迭代，而非成比例增加编译指令。Python负责节点、参数和接线；重复几何的公式留在VEX循环中，共用数量、间距、采样、种子等控制。形体由可替换的源与Copy/Sweep处理，复杂度来自实际输出和算法，而不是把每个点的常数坐标写成独立语句。已测得更合适的原生节点、专用算法或外部数据方式仍按编辑目标选择。

例如多条起伏中心线可用一个Detail Wrangle；`count/samples/spacing/length/amplitude`在该节点创建对应spare参数，参数引用与控制来源由当前工程决定：

```vex
int count = chi("count");
int samples = max(2, chi("samples"));
float spacing = ch("spacing");
float length = ch("length");
float amplitude = ch("amplitude");
for (int piece = 0; piece < count; piece++) {
    int vertices[];
    for (int sample = 0; sample < samples; sample++) {
        float u = float(sample) / (samples - 1);
        vector pos = set(piece * spacing, amplitude * sin(2 * M_PI * u), length * u);
        int point = addpoint(0, pos);
        setpointattrib(0, "id", point, piece * samples + sample);
        append(vertices, point);
    }
    addprim(0, "polyline", vertices);
}
```

上例修改数量或长度无需重新生成源码；曲线身份、点序和参数变化仍需按交付用途核对。大批不规则实测数据可以作为几何属性或显式文件输入，不必为每个样本生成代码；小型固定轮廓、算法所需静态表或非重复的大型代码不因长度自动无效。跨样本数修改时，上例的point `id`对应关系会变化，不能据此声明稳定拓扑形变。

H21.0.440/H22.0.368已复现：大量展开的点构造可单独计算成功，随后接属性处理时却在原生VEX编译器中崩溃；相应重复构造改为循环后，完整网络可计算。源节点单独cook或独立编译不能认证下游安全，字符数也没有已验证的通用安全阈值。观察实际源→成形→属性→最终输出；若遇到同类原生崩溃，检查重复展开的生成来源，保留有效数据流并改变生成方式，再验证完整消费者。单纯缩小Python调用批次、拆文件或换短属性语句未必改变实际编译输入。

本机已验证的循环方式不证明全部资产、版本或任意VEX安全；原生崩溃的内部根因与厂商修复版本分别核实。不得将进程退出当作普通可捕获节点错误，或自动重试结果未知的修改。H21/H22方法验证见`tools/tests/dsh-repeated-layout.test.py`；独立原生展开/循环对照见`tools/reproduce-vex-codegen.py`。VEX循环语法与属性操作依据SideFX[语言参考](https://www.sidefx.com/docs/houdini/vex/lang.html)和[addpoint](https://www.sidefx.com/docs/houdini/vex/functions/addpoint.html)。

### 源构件与成形检查

复制、成形与后处理会传播源错误。大量复用前在一个代表性源单元核对所需的形状、朝向与端口，再检查实例变换后的结果；只有相关源或变换改变时刷新这些检查。

| 要区分的问题 | 证据与处理 |
|---|---|
| 闭合、面间一致、整壳朝外 | 分别读`boundary_edges`、`orientation_conflicts`、`shell_orientation`。简单独立闭壳结合HOM面法线与已知外表面判断；嵌套空腔、开放面和自交不靠体积符号裁决 |
| 几何绕序与着色N | Normal只处理法线属性，不修多边形顶点顺序；确认整壳反向后修源绕序或方向设置。混合正反向输出不整体Reverse，双面预览也不能排除反向面 |
| Revolve输出看似封闭却朝内 | 读`node_info(parent,'revolve')`；轮廓点序与方向设置共同影响朝向。按节点卡单项修正并复验，不把`reversecrosssections=True`当默认处方 |
| 共用源/函数已发现错误 | 定位同源分支及拷贝，修维护源并检查实际消费者；一块栏板或单组通过不能覆盖柱头、浮雕等不同构造。用明确组/源分解超预算检查，未覆盖处保留未验证 |

`geo_piece_stats(..., inspect=True, integrity_only=True)`提供这些有界表面事实；`verify_network`的计算成功不代替它们。需要源替换/路径修改的行为证据见[验收](#4-停止与验收)。

### 高风险成形的最小检查

适用：结果依赖输入实体条件、节点模式或相邻件贴合的产品构造。先选当前风险对应的一行，
在单元上完成一次「前提→操作→实际效果」；不要求每个简单编辑跑全表，不把这些检查当成制造认证。

| 风险 | 最小检查与失败转向 |
|---|---|
| 参数写入但模式不使用 | 先读模式与参数适用条件，再作一个有明确预期的单变量扰动并读实际输出。细分看采样/拓扑与轮廓，厚度看截面；未响应先查模式、接线或选择，不继续增大同一无效值。恢复后才扩建。 |
| Boolean源不满足实体前提 | Solid输入先查边界、共享边方向、整壳朝向；旋转/扫掠接缝核对是否真实连接。只有证据显示意外重复接缝才Fuse，朝向错误才Reverse；不对合法Surface或设计间隙盲修。失败先定位源，不能反复切换布尔菜单。 |
| 运算完成但形状相反 | 对声明为Solid的A−B，结果超出A包络且超过量测容差可否定减法效果；包络未超出仍需孔轴/截面或局部图证明切除了目标。融合另查实际连接，不能用减法判据。读取成形节点自身warning，最终Null的无warning不替代上游证据。 |
| 相邻层只有视觉靠近 | 先共享接合轮廓与局部frame，各层从它派生厚度/允许间隙；改变一个主尺寸，量测最终接合表面。独立外部资产保留各自构造，以明确接口适配并验实际关系，不为贴合强制Fuse。 |

图像暴露凸起/开缝等反例后，先在原型定位源或依赖，再修复并重看；提高分段数不修接合设计。

### 逻辑模块与容器选择

模块用于解释输入、处理和输出；容器由复用、替换与接手需要决定。同一SOP网络中的平铺分支适合快速观察，源、局部处理、放置/复制与组装沿数据流相邻。重复组件尽量共享构造来源；稳定的`OUT_<MODULE>`或`OUT_ASSET`可作为消费者接口，但不要求每条短链添加Null。Network Box改善可读性，不代替真实端口。

独立复用、导出、替换、少量稳定公共端口或用户明确要求层级时可使用普通SOP Subnet，也可在构建时直接选用。整理已有网络时核对输入、消费者和参数依赖，按实际风险选择原地调整或候选分支；发布原生Output并复验消费者。强耦合连续曲面、跨模块Boolean、接口频繁变化或短链通常适合同层。HDA用于用户需要共享类型或安装分发的交付。

私有细节留在组件；跨组件连接件归最低共同装配层。模块内部不保留OBJ/工作区绝对路径，同层优先相对兄弟引用，Subnet只经公共输入/参数连接外部。全局自由量只有一个维护源，组件公开局部量仅在改变外包络/接口时提升给父级。
纯控制生成点用detail(foreach除外)的Wrangle：`addpoint`一次生成全部实例点；point class的Wrangle
按输入点逐点执行，空输入即零执行，不会凭空生点。同层读共享控制优先相对路径，
例如`chf('../CTRL/wheelbase')`；跨Subnet经公开输入/参数传递，不把当前OBJ绝对路径写进内部。
相对路径也可能因移动节点而失效，写后须cook回读实测点值，不只看snippet无语法错。

## 2. 选择先于倒角与局部操作

优先复用构造节点生成的front/back/side/边界组，必要时与部件身份、位置、方向、夹角条件组合。
Group Create可按几何条件生成组；组的class要与消费者匹配。改变上游拓扑后重新生成并回读组，
不要长期保存某次观察到的边号。一个命名组存在但为空，不算选中了目标。

硬表面圆角先区分构造边界与用于逼近曲面的分段边。例如圆柱端盖的边沿与侧面的分段边承担不同职责；需要光滑筒身时优先选择边沿，不把整圈分段都细化。角度过滤按实际相邻面夹角选择，输入分段数变化后复查；仅开启Ignore Flat Edges但沿用小阈值，仍可能保留所有分段边。节点卡维护开关/角度的精确含义，避免把某个案例的角度写成通用默认值。
角度阈值不是零件语义，不同级别的圆角分组执行。
窄槽、薄壁、拐角密集处按局部间距限制宽度。全部边、点倒角、开放轮廓的圆角也可能是用户意图，
不能因为常用路线是硬边筛选就禁止这些情况。

最小路径：明确目标边 → 建组/角度策略 → 读PolyBevel操作卡 → 小宽度构建 → 查真实边与角部 →
必要时提高截面分段。失败先区分选错、宽度冲突、输入非流形/方向不一致，不反复增加divisions。
checkpoint是选择范围、局部轮廓和输出拓扑；cook成功不能保证无自交。朝向与着色的区分见[源构件检查](#源构件与成形检查)。

## 3. 一个模块分层细化

先确定交付距离/分辨率、几何用途和显著细节；无参考时把构造选择标为设计假设，不冒充工程认证。
预算用该模块的面数、cook时间、最大细化级别和可见贡献约束，不用固定全项目面数指标。

从模块用途选择有意义的细节：操作/握持需要什么，零件如何定位和紧固，薄壁或安装处如何支撑，
孔槽与边缘怎样形成近景层次。复杂设计可在现有计划中记下用途、依附关系、控制与观察方法，
不需要另填固定字段；用实际局部原型判断方案。

| 设计问题 | 可选择的结构 | 必须一起考虑 |
|---|---|---|
| 用户怎样操作 | 握持轮廓、防滑纹、刻度、调节空间 | 尺度、运动避让及实际可见性 |
| 零件怎样安装 | 孔/沉孔、螺钉座、定位台阶、配合槽 | 连接双方共享位置，孔/杆/座的实际配合 |
| 局部怎样支撑 | 带厚度的肋板、根部过渡、支撑座 | 从真实承接面生成，检查整个脚面与邻件 |
| 形体如何制造和拆分 | 壁厚、分件缝、孔口处理、局部避让 | 不同部分的构造一致，不能把穿插说成接合 |
| 近景需要哪些层次 | 主轮廓圆角、中尺度边、微倒角和纹理 | 按观察距离和局部间距选尺寸，不全边同宽 |

只选择与对象用途一致的项，不按固定数量塞满细节。用户未规定的设计可由作者选择并记录假设，
不把自行选择的孔距/紧固件规格冒充外部事实。毫米输入先统一转米；几何细节要在最终输出存在，
不能以文字说明、节点名称或材质颜色代替。已有共享模板按procedural-recipes选择，局部表面不适配时回到原型。

以下层次帮助选择细节的表示和观察范围，可按任务交替推进：

- **主形体**：代理体、主要截面或接口，用于观察比例与位置。
- **构造细节**：分件、厚度、安装座、孔槽、筋。尺寸引用共享控制与接口；改主尺寸仍需成立。
- **边缘层次**：主要轮廓圆角与微小边缘可分组控制，检查整体和局部高光。
- **重复细节**：可替换的源单元配合第1节的Copy结构；细化源资产时复用布局、稳定身份与种子。
- **微表面**：不影响轮廓/接触的细纹可按用途放材质、法线或位移；显著视差/投影/轮廓需几何。制造/测量交付不能用贴图替代实际要求的几何；渲染位移仍需对应的细分与包络检查。

### 表面表示与外观制作

新模型和部件的外观使用[表面外观skill](../../houdini-surface-workflow/SKILL.md)，统一维护参考图分析、几何/图案分工、表面细化程度与来源选择。新SOP资产从COP Preview Material与小尺寸纯色COP输出开始，按需求丰富图层；不因统一预览而烘纯色文件或重建有效旧材质。
有方向纹理的重复源，先完成代表性单件的几何、UV和表面采样观察，再扩展布局；未检查的映射会随Copy一起复制。UV有效性与缩放规则见表面资料，不在这里维护另一份展开方法。
需要空间图案时，在源组件与形变构造阶段按[SOP应用与UV](../../houdini-surface-workflow/references/sop-preview-and-uv.md)确定坐标、方向及尺寸修改规则。布局权重、构造mask与调试色仍是几何属性职责；连续涂装由材质采样，不量化为逐面分色或删面。正式渲染才按需接Solaris/Karma，建模观察不强制创建stage。

在高成本分支前保留简模/精模选择，主控制与接口不因选择模式漂移。细节attach到语义表面/局部frame，
不要维护另一套独立世界坐标常量。精模完成后集成到实际OUT，检查必需分支而非只查独立模块。
代表性调参同时检查细节响应和应保持的壁厚/接口/数量；没有适用测量就写未验证。

## 4. 停止与验收

主比例或接口有误时，回到影响它的构造定位原因；重复失败可用最小单变量诊断或换方法。
整体图回答比例/分件，局部图回答轮廓/边缘/细节；没有成功semantic inspection则视觉未验证。
最后一次相关修改后刷新受影响检查，不能沿用细化前的闭合/接口结论。面数增长不是验收结果。

观察应能区分具体原因，再选择修改；已有正确信息不必重查整个网络。以下是诊断例子，不是每件资产的固定检查表：

| 症状 | 能区分原因的观察 | 修改方向 |
|---|---|---|
| 统计存在的部件在图中看不清 | 隔离该部件与邻接面，检查局部截面、深度与实际连接位置 | 区分被包埋、遮挡和轮廓层次不足，修改相关截面或放置关系 |
| 细杆出现宽片、尖刺或不正常接头 | 先看成管前的线段、共享端点与急转弯，再看局部截面 | 按独立杆件或连续管路的实际意图处理连接，不先靠加面或材质掩盖 |
| 数量、尺寸能变但形体关系失效 | 在改变的状态检查实际成员、厚度、间距与承接面 | 调整共享参数关系；件数变化和bbox变化不能替代这些观察 |
| 模式正确与否不确定、输出为空 | 对照当前解析类型的菜单token与实际输入元素；用一个可观察单元验证 | 修正模式/输入后再判断节点能力，不从错误模式推断平台不支持 |

`render_view`的命名方向是固定世界空间预览，`side/front`带轻微仰角，不自动识别对象正面。
检查沿轴轮廓时使用对象实际世界轴对应的方向向量；正交投影本身不保证沿轴。疑点尚未解释时，
用聚焦观察或局部修改继续判断，最终表述保留实际未覆盖的范围。

重复资产交付先回读模板点的实际位置、首尾跨度与相邻间距，再核对复制后各件中心；Line SOP 的 `dist` 是整条线长度，不能把它直接当相邻点距。检查源入口与模板数据独立；用一个遵守相同原点/轴向/单位合同的不同源形状做替换测试，
确认实际Copy输出随源变化，模板数量/id/位置/朝向/变体规则保持，随后恢复源接线并复验受影响关系。
源尺寸变化可能需要预先声明的适配，不能把物体必然不相交当作Copy保证。VEX拆分按中间输出能否独立
观察与局部修改验收；有spare参数、能cook或拆成更多节点本身均不证明人工易接手。
