# 程序化 SOP 质量合同

## 何时使用

当任务开放式、依赖真实世界参考、包含多个相互连接的部件、要求可调资产，或“高质量/细节丰富”
会显著改变建模路径时，用这里的问题帮助选择构造与检查。它不是操作前要填写的表单；简单修改、
抽象探索和一次性可逆 probe 只需检查本次目标。

## 理解交付

需要回查原始资料时，用`houdini_resource(kind="source", ref="index")`列目录，再按ref分页读取。
以下是理解要求的角度，按任务取用。复杂要求可在DSH计划或工作区文件中记录，已有清楚要求时直接推进；
插件没有产品定义、覆盖绑定或阶段审批工具。

- 对象用途与观察距离决定哪些轮廓、结构和细节应真实建出，哪些可简化。
- 参考与场景给出单位、尺寸、方向和部件关系；缺失的重要规格可按任务明确假设。
- 用户操作决定自由参数；名称、单位、范围和默认值应与实际输出对应。
- 部件共享的轴、端点、基准面与尺寸应有同一来源，关键关系用合适的观察核对。

引用外部真实性时要记录来源；没有来源时只能报告“内部一致/基于假设”，不能升级成“符合真实范围”。
厂家照片配工程图时，核对图/页、标注位置、所属零件、尺寸性质和冲突；实际图片需从原材料读取，
Host来源文字标记不等于像素恢复。需要多个运动状态时，明确对应控制值及预期关系，例如闭合接触和打开分离。
期望来自用户要求、参考或明确的设计选择，不能从当前模型里幸存的部件反推要求。

直接消费工具回执，需要详细事实时回读保留结果。局部成功不代替最终输出，控制响应不代替部件连接；
测量覆盖范围与未测部分一同报告。最后相关修改后刷新受影响的检查，保留仍有效的工作。
续接时结合原要求、新增资料和实际输出继续，不另建定义修订、覆盖绑定或完成账本。
只有会改变构造且不能自行查清的选择才需要向用户提问。

## 检查与所声称的性质

先把用户要求或准备交付的描述转成可观察的性质，再选择能区分“实现了”和“只是看起来像”的证据。
名称只表示意图：`thickness`、`spacing`或`alternating`参数存在并不证明生成规律正确。

| 要判断的性质 | 有区分力的观察 | 容易误判的替代证据 |
|---|---|---|
| 计算与表面完整性 | 明确输出的cook/非空状态；相关组的边界、方向、退化与连通性 | 没有warning不证明结构符合用途；闭合材料表面不证明内部空腔或通道存在 |
| 尺寸、厚度、间距 | 在实际部件、局部方向或截面上量测；单位与容差来自要求 | 整体bbox响应不证明壁厚；数量正确不证明间距或重叠正确 |
| 排列、交错与配对 | 按稳定身份/侧别分别检查成员、邻接和对应关系，再看实际空间交错 | 两组投影相交不证明组内交错；角度偏移改变不证明所声称的编排规律 |
| 接触、插入与净空 | 明确真实承接面和成员范围，使用适用接口方法或局部几何观察 | 半径范围重叠、中心点靠近、共享anchor公式不证明表面接触；抽样接近不证明整面配合 |
| 外观与细节 | 当前输出的可辨认整体/局部图，视角与疑点对应 | 件数、面数、闭壳和图片送达不证明可见层次或成功识图 |
| 可编辑性 | 实际尝试任务需要的路径/截面修改、源替换或局部工序调整，观察受影响输出 | 节点数量、暴露参数、注释或可改源码不证明接手修改容易 |

例如开口槽的材料表面也能完全闭合，声称“封闭空腔”时应看截面内外边界；
阵列从6件改为12件后计数正确，仍要按设计含义检查间距或间隙。
若检查结果无法区分这些反例，换观察范围或方法，不把更多同类统计当作更强的证明。
已有工具不支持某项语义时，可从最终几何做有界只读查询或局部图像判断，并说明覆盖范围；
不让能测到的指标反过来缩小用户要求，也不为简单任务跑完此表。

参数行为用`test_controls`在代表性状态读取实际值、响应及相关关系，并消费恢复结果。
采用稳定case名称区分参数状态与执行次数：未运行不是通过，同一状态修正后的重试也不是新增覆盖。
汇报当前最终输出上实际通过的状态，保留尚失败、未执行和未覆盖的范围；改变测量方法后重新验证受影响状态。

## 观察冲突的处理

当当前图像疑似漏件、脱离或断口，而cook、计数或尺寸检查通过时，两者检查的性质可能不同。
先确认图像对应的输出、状态与可见范围；然后选择能区分原因的局部观察：隔离该部件、换能暴露接点的视角，
或查询最终实体的成员和连接范围。裁切/取景问题按[观察边界](execution-checkpoints.md#观察与关键方法)检查。

“太细”“被遮挡”“透视造成”“只是着色”都先作为候选解释。用对应观察支持后才能排除缺陷；
上游中心线或定位点存在，不能证明下游实体仍在最终输出中。修改成形、分组或删除节点后尤其要看实际幸存的实体。
若确认问题则修构造并更新受影响检查；若工具/图像不足则保留具体未验证范围，不能据其他通过项宣布此处正确。

测试的测量对象应能反驳所声称的性质：例如整体宽度随控制变化，只证明包络响应，不能证明目标管面连续或接点保持。
已经得到足以解释疑点的证据就继续任务，不强制每个部件固定拍摄次数或遍历全部关系。

## Anchor 与依赖

共享尺寸和定位基准可以形成以下数据流；按资产选择有用的层次：

```text
controls / reference dimensions
  → named anchors and local frames
    → module generators
      → relationship checks
        → integrated output
```

- 一个会影响多个模块的量只有一个维护位置；下游用引用、属性或表达式派生。
- 模块输出保留稳定的 `part_id/module` 等标识，便于局部统计和关系检查；标签的具体名称可按资产约定。
- 绝对坐标不是禁用项；只在它确实是局部常量且不会与其他模块重复表达同一事实时使用。
- 合理调参后仍需手改多个代码字符串才能恢复连接，说明共享依赖未接通，应修构造或如实说明控制范围。

## 常见模块关系

只选择任务相关的关系，不要求每个资产套满：

| 关系 | 需要证明什么 | 反例 |
|---|---|---|
| coincident axis | 两个部件共享或按偏移共享轴线 | bbox 重叠但轴向错误 |
| anchored endpoint | 端点位于命名 anchor 的容差内 | 视觉靠近但实际悬空 |
| contained/inserted | 部件进入目标范围并保留正确深度 | 全部穿透或只擦边 |
| clearance | 最小间隙在允许范围内 | 为消除一处冲突而制造另一处冲突 |
| forbidden intersection | 不允许的部件对没有相交 | “被遮住所以可接受”但合同未允许 |
| contact/grounding | 接触位置和法线符合用途 | 只用全场 bbox 推断接触 |
| symmetry/pairing | 对称或成对件共享规则且允许指定差异 | 分别硬编码后逐渐漂移 |
| attribute continuity | 下游所需属性 class/value 连续 | Merge 无 error 但属性默认化 |

现有词表不能直接给出关系时，可用只读 HOM/局部几何 probe 建立证据，并把重复出现的通用意图
记录为工具候选；不要为单个资产发明专用 verb。

## 选择检查

这些检查可以穿插进行，顺序取决于本次改动和未知问题。

| 当前问题 | 可用方法 |
|---|---|
| 比例、轮廓或接口仍不确定 | 用中心线、截面或代理体尽早观察，降低返工成本 |
| 局部构造难以从整体判断 | 隔离相关模块，看中间输出、几何与参数响应；见[模块合同](module-quality-contracts.md#模块聚焦与交接) |
| 集成后是否漏件或脱离 | 检查最终输出中的期望成员、数量和实际实例关系，局部cook成功不能替代 |
| 外观是否符合要求 | 整体图看轮廓，近景看细节与连接；有参考时使用可比较视角 |
| 控制是否有用且可恢复 | 选择代表性值与相关不变量运行`test_controls`，消费实际值和恢复结果 |
| 是否可以交付 | 对照原要求检查最后相关修改后的输出，说明实测、视觉观察、失败与未验证范围 |

视觉判断需要有效图像及实际识图。`render_view.check`/`render_check`反映像素与取景问题；
近黑、空白、目标缺失或裁切会限制对应判断。模型图像能力不明时可查`houdini_capabilities()`，
能力元数据本身不证明渲染或识图成功。

## 边界与反例

- 风格化或抽象任务可以由用户授权 agent 自选比例；仍要把该选择写成风格假设，而非真实规格。
- 低 LOD 允许省略内部机械结构，但不能破坏用户要求的轮廓、连接或运动语义。
- 用户说“你决定”时由作者选择合适方法，说明影响结果的重要假设。
- 更多节点、更多 primitives、无 cook warning 或能渲染，都不是“细节丰富/高质量”的充分证据。
- todo 完成、旧截图或修改前的点数不能证明最终状态；最后一次 mutation 会使依赖它的旧证据失效。
