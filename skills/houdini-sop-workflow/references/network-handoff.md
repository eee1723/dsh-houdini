# 网络交接布局

目标是让用户一眼分清控制、放置、可替换源、处理/装配和输出，同时保留足够空白供人工审查与继续编辑。它是交付展示层，不替代几何、关系、控制或视觉验收。

## 阅读顺序与编辑入口

先让用户看到控制入口、组件地图和最终输出，再能进入某个组件顺着工序修改。控制区单独位于顶部偏左，检查区在侧边，总装与输出在构造区下方。不要把控制、检查和输出混在同一框，也不要把所有零输入节点当同一行的源。

组件框回答“这部分是什么”，框内工序回答“从哪里改、怎样形成”。同一条连续主输入链上下对齐，侧输入、切削体、复制模板从旁边合流；不同独立管线分别占列，较短的辅助支路靠近使用它的节点。路径、截面、重复源等真实编辑入口保留在其管线头部，标签说明用途。原生节点名保持稳定，框标题用可读短标签；不为排布改接线、改表达式或折叠Subnet。

大组件可按实际工序用叶子框组织，再用组件大框包含这些叶子框。框数与层数由复杂度决定，不把每个节点包一层，也不把几十条独立管线横排进一个宽框。比如轮组可分轮胎、轮圈、花鼓、辐条；传动可分牙盘、飞轮、链节、后拨、曲柄踏板。跨框引用仍是实际引用，不以假数据线冒充参数依赖。

用`network_controls(parent, [{'node': controller, 'label': '工程控制'}])`明确声明真实用户控制入口；声明随节点保存在HIP，改名后仍可发现。交付时用`present_nodes`将控制、输出和其他明确编辑入口作为节点卡片发布在回复下，点击直接定位并打开参数页；文件仍用DSH的`present`交付。控制区单独使用`role='controls'`，不靠CTRL前缀、Null类型、颜色或参数数量猜控制。声明只说明导航用途，未测试的联动仍需明确。

## 何时执行

节点卡片的`label`说明用户用途，`description`用一句话说明可改的量或下一步操作；真实节点类别、完整路径和工程留给可展开详情，不把`null`类型当用户说明。

按用户接手动作选择交付：保留工程及必需依赖；视觉任务可把已经核对的整体图、关键局部图随工程交付，让用户先看到结果。材质、灯光/相机、渲染或缓存配置确实属于任务时，可把相应真实节点作为编辑入口，不新增卡片类型或自动执行按钮。不把每个中间节点、检查分支、缓存和临时图片全部推给用户，也不把导航入口标成质量通过证书。工程文件名在用户授权另存时表达资产用途；未授权的现有文件不为改名而另存。

最终整体图、局部图使用`render_view(..., picture='asset_overview.png', output_policy='delivery')`，落到实际已命名HIP旁的`dsh-render/`，再核对并`present`返回的实际文件路径。`picture`只给安全basename，分配器追加帧和唯一捕获标识；不自行猜文件名，也不从会话工作目录拼路径。需要交付用户屏幕截图时，`viewport_screenshot(..., output_policy='delivery')`采用相同目录规则，但截图仍只证明当时屏幕内容；`delivery`是文件用途，不是质量认证。参数以`verb_help`为准，用户明确目的地使用`explicit`。

正式ROP渲染也在生成前选择交付位置，例如`render_frame(rop, picture='$HIP/dsh-render/asset_final.png')`；新建且由本任务负责的ROP，其持久图片目标也应按授权设到这里。临时`picture`覆盖不等于已经保存ROP设置。已有用户ROP或明确的用户目的地优先，不为统一目录而默默覆盖它；消费实际渲染输出并核对文件后再发布。

`managed`观察图继续放在`dsh-visual-checks/<run-id>/`供当前诊断和已有对话引用；不把这些目录整体当垃圾删除。收尾时只清理本任务创建、已确认不再用于运行/恢复/交付的明确临时文件和探针节点，不按扩展名、前缀或“看起来像测试”推断归属。保留公开交付源、用户参考、必要外部依赖及未确认完成的捕获预约；测试图仅被`read_image`读取或在日志中提及，不使其成为永久交付物，DSH已保存的执行归档则不属于此类清理。默认保留旧交付入口仍依赖的文件；用户明确要求迁移时核对新文件并发布新路径，说明旧历史入口的地址不随移动更新，不重写历史来伪造新回执。普通文件操作走DSH通用文件工具，Houdini节点修改仍走Bridge动词与现有ownership；不删除持久渲染服务。任务内这类明确的例行清理随已授权工作完成，不逐个要求用户确认；未知归属或用户内容保持原状。

需要用户接手或继续扩展的SOP网络，可在功能和输出稳定后整理。短链、诊断探针或仅维护节点时无需制造Box。已有用户网络沿用其结构；明确授权整理时再选择实际成员与范围。

## 分组

先区分逻辑模块与技术阶段。可独立替换、细化或重复的组件，让源、局部处理和稳定输出相邻；不因为模块化自动创建Subnet。Network Box表达同一parent中的编辑器分组，支持子箱；它不提供数据流端口或写入权限。小模块可以用一个清楚的Box，较大网络按用户接手方式组织。

- `controls`：用户控制、共享参数和驱动入口。
- `component`：某个可独立理解或修改的组件。
- `placement`：点流、方向、尺度、随机化与装配位置。
- `source`：可独立替换的源几何/原型。
- `assembly`：处理、复制、合并和最终装配。
- `output`：稳定输出、显式公共输出或交付检查点。

这些role是可选的阅读注解，也可用任务自己的role或省略。一个节点只能属于一个直接Box；标签省略时使用名字。名字保持稳定，配色帮助辨认即可，不能替代成员、接线和输出检查。

需要同时呈现组件与技术阶段时，组件容器包含阶段小框是一个常用方法。`network_boxes`允许同次声明子箱、向前引用以及节点和子箱混合成员；选择多少层取决于可读性，不设固定层数。后续自动布局按实际结构选择：`handoff`处理扁平叶子框，`component`处理一层组件容器内的叶子框；更复杂的结构可局部布局或手工定位，不把这些布局算法的范围当作分组能力限制。

需要快速观察不同组件时，可给同一组件的大框和叶子框使用同一低饱和色相，以轻微明度差区分阶段；相邻组件避免近似色，控制、总装和最终输出仍保留稳定的中性色/角色色。颜色必须与组件标签、几何`part`/piece身份保持可解释对应，不按创建顺序随机分配，也不能用“颜色不同”替代实际成员、接线和输出验证。已有用户自定义配色默认保留；只有用户要求重配或新建交接布局时才覆盖。

## 操作与预览

分组和布局可以直接应用。需要先观察变化范围时使用`dry_run=True`；可传回`expected_plan`核对计划是否仍新鲜，这不是执行准入条件。
建好成员Network Box后，不能再对整网调用`layout_nodes(mode='children'/'flow')`：
它会把框内节点重新打散而不验证框间排布，工具现会写前拒绝这种调用。
要整理框之间的关系，使用适用的`handoff`或`component`；只调整单个框内
少量节点时，传明确的`nodes`列表。

```python
network_boxes(parent, groups)

names = [group['name'] for group in groups]
layout_nodes(parent, mode='handoff', boxes=names, profile='readable')
```

`readable`按真实输入端口组织主链和侧支，为原生类型/名称/锁标记保留上下空白，并为标签预留估算空间。框底色使用低亮度、低饱和颜色，让连线与节点保持对比；未知role默认使用同样深的中性色。先整理扁平叶子框，再声明组件容器，最后用`mode='component', profile='readable'`排组件；它整体移动叶子框，不改框内工序。`comfortable`保留原有分层排布，适合只需净距的网络。声明的role只参与呈现，不扩大ownership；标签净距估算和线交叉减少不替代真实网络编辑器核图。

handoff默认只移动当前session自有Box及其完整自有成员。未选节点、foreign/service/未选Box、Sticky Note和Network Dot是固定障碍；不能仅为整理美观使用`allow_foreign`越权。用户明确授权修复某个已命名既有网络时，可对精确列出的旧Box及成员传一次性非空`allow_foreign`理由，并在dry-run与apply保持同一授权；持久render service永不豁免。若返回`blocked`，缩小显式Box范围或由用户处理固定障碍，不删除/移动未授权内容。

`handoff`只接叶子框，`component`只接其支持的组件大框；不能把父子框混在同一次布局。变更嵌套成员时查看返回的实际affected范围与包含关系，必要时明确指定最终`boxes`列表。

## 验收

查看`layout_status`、节点/Box/障碍重叠、`containment_failures`和`clearance_failures`，比较声明净距与回读的`achieved_clearances`。这些事实解释编辑器布局，不证明接线、几何或视觉质量；按实际变更检查用户关心的输出。

节点入口首次声明会将持久标识保存在真实节点上；声明后保存同一HIP，再交付文件。卡片读取原始成功回执，点击由当前任务绑定的执行端核对HIP及持久标识；改名/同HIP重开可继续定位，缺失或复制导致重复时保持明确失败，不按旧路径猜目标。标识用于导航，不授予修改权限。
