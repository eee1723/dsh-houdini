# Houdini Task Decomposition

降低构建、检查、返工和后续修改的总成本。以用户会修改的对象或功能划分模块，让局部结果决定下一步；具体节点、构造和检查方法由对应领域skill维护。已有工程沿有效结构局部推进，教程任务保留作者已明确的方法与依赖。

## 按变化和依赖划分

按用户会修改的内容和反馈范围划分模块：经常一起变化的内容放在一起，可独立替换、细化或排错的内容分开。同层展开妨碍浏览时，按共同修改或复用边界收进Subnet，上层保留必要输入、控制和输出；短链和强耦合构造可以同层。执行分工不决定工程层级。

模块也可以是同一连续对象上的局部工序、控制区域或处理阶段，不要求拆成互不连接的几何零件。独立修改指有清楚的编辑职责；共享曲面、运动或状态仍保留必要依赖，局部观察在整体关系中判断。是否重复、是否需要连续表面、哪些部件相对运动，比“建筑/机械/道具”等对象类别更能决定构造边界。

先识别整体尺度、空间/时间约定、共享控制与依赖。只需少量信息就能稳定接口时直接构建；整体比例或连接尚不明确时，用简单代理或最小贯通原型确定接口，再逐个替换为正式模块。代理与正式输出保持可辨认，整体草模的观察只覆盖它实际表达的性质。

当前焦点应能说明它负责的要求、实际输出、输入依赖、编辑入口和仍未解决的差距。几何关注坐标与安装位置，模拟还关注字段、时间和状态，图像关注层与分辨率，工具关注输入、行为和副作用。共享量只有一个维护源，消费者通过明确输入或控制取得；强耦合的过程可以共同构造和验证。

在DSH已有计划中保留当前焦点、未解决问题和下一次有用观察；“完成并检查源件，再验证布局”比把全部构建与全部检查分成两大任务更容易减少返工。不另建模块完成账本或规定模块数量。

重复组合对象以完整源和布局为两个编辑职责，源内部可批量组合基本几何。共享连续边界的相邻模块优先从同一曲线、表面或接口输出派生；复制相似公式会让修改后边界分离。分组服务真实依赖，最后加几个Network Box不能代替这种划分。

## 围绕反馈逐个推进

优先处理依赖已具备、又最影响质量或返工的部分。把当前模块当成一件小交付：在实际输出上判断它负责的要求，再决定修源、改接口还是接入消费者。批次大小以能回答当前问题为准，模块内部可以批量建节点；局部构造不必等同整个模块一次做完。

观察范围跟随当前问题：源件的轮廓、装甲或图案用能看清该部位的局部图；安装、遮挡和整体比例用装配图。贴图源还要观察坐标、端面/侧面与采样尺度，方法由表面workflow维护。只检查代表性源及有差异或风险的实例，无需逐个检查相同副本；整体图中被遮挡或像素太少的部位仍未验证。

局部缺陷先定位到源、布局、连接或消费者。用一次相关修改检验这个解释，再决定是否扩大范围；源本身不能表达所需形状或功能时，替换该局部方法并保留稳定接口。单件成立后仍需看接入后的关系。布局探索可以先用代理，但源的已知缺陷不能靠复制或总装后的装饰核销。独立模块可继续推进，依赖未验证假设的部分保持试验状态。

检查方式随所声称的性质选择，以下是拆分与反馈的例子，不是固定流程：

| 任务 | 可独立推进的单元 | 决定下一步的证据 |
|---|---|---|
| 重复件建模 | 完整源组件、布局、装配 | 源的局部图与几何；实例朝向/成员；邻接关系与改源后的消费者，构造见[SOP方法](../houdini-sop-workflow/references/modeling-methods.md#完整源组件与布局) |
| 模拟 | 发射源、碰撞准备、求解、后处理/缓存 | 源字段与代表性帧；求解器实际消费的碰撞表示；短区间预览与行为；缓存回读。节点和字段以当前求解器接口为准 |
| COP处理 | 输入层、遮罩/处理、合成、输出 | 中间层及通道观察，再看最终合成；按[COP skill](../houdini-cop-workflow/SKILL.md)选择关系和控制检查 |
| Rig或动画 | 控制、求值、变形与交付输出 | 有意义的姿态/时间变化及最终形体，按[Rig skill](../houdini-rig-animation-workflow/SKILL.md)检查 |
| 工具开发 | 输入处理、核心操作、界面与交付入口 | 先跑通代表性操作与失败反馈，再从实际界面调用同一功能，按[工具skill](../houdini-tool-development/SKILL.md)检查 |

数值/属性或功能任务使用相应数据与行为证据，动态任务使用时间范围；不为所有模块强制艺术渲染。涉及求解历史、缓存或外部副作用时，恢复与重算按实际能力处理，不能套用只恢复静态参数的假设。单个简单编辑无需建立整套模块过程。

## 独立计算与团队分工

输入和接口已明确、能从文件复现的工作，可以交给DSH团队成员独立准备、构建并自验证；需要Houdini计算时按需加载[独立执行skill](../houdini-isolated-execution/SKILL.md)，调用`houdini_isolated`。它运行一次性hython，不自动获得或修改当前live现场，也不自动合并结果。

独立调用可以只发现接口、返回builder事实或运行相关断言；几何、控制、缓存和图像检查按当前问题选择，不要求每次调用都造出SOP或渲染。完成一个独立步骤不能替代该模块仍需满足的实际要求。

委派时交清相关原始要求、接入位置、共享输入／坐标和要观察的结果。涉及外观时，按[表面方法](../houdini-surface-workflow/SKILL.md)交清结构、图案与材质响应的分工，保留用户指定方法及作者试验空间。子任务交回输入版本、输出和检查范围，主作者接入后复查消费者；仍在变化的强耦合部分可由同一作者推进。同一live现场保留单作者，不共享身份或用allow_foreign绕过归属。

团队默认交付builder文件，说明实际调用入口、依赖、本次输入版本及检查范围；主作者使用`houdini_exec`的`script`入口在当前工程执行并接入，方法见[模块文件与复用](../houdini-sop-workflow/references/module-design-collaboration.md)。builder可以只负责当前局部，不要求完整重建工程或重复执行同一构建。简单现场编辑继续直接使用`code`；已有有效网络和用户修改沿本次目标局部推进。实际节点快照和显式迁移按需要使用，不另立团队交付协议。

## 把构建边界交给用户

围绕真实模块保留明确输出与需要的编辑入口。将一个节点声明为模块出口后，核对实际消费者经过这个出口；在出口前新增清理、UV或细化时，不能只验证该支路而让总装继续引用旧中间节点。有意消费中间结果时明确其用途；输出名称不证明接线，已有graph或只读输入/输出查询足够完成核对，不另建依赖账本。
构建中已经明确“哪些节点一起编辑”时，按[网络交接skill](../houdini-network-handoff/SKILL.md)局部组织。主作者统一资产入口、总装和受影响的上层导航，让用户能找到模块、共享表面与输出；局部整齐不能代替整体接手。容器选择服务于实际依赖，不要求单一Geo、每个模块一个Subnet或HDA。

修改源或共享输入后，沿实际消费者更新相关单件/集成检查；保留其他有效工作。交付入口让用户能够继续完成预期修改，未测范围与当前阻点留在现有计划/交接中。方法本身不增加执行准入、用户审批或独立评审agent。
