# 参考工程与质量迁移

用于已有HIP、资产或场景的变体、同类制作和跨任务接续。目标是让下一位作者理解哪些性质要保持、哪些应变化，并能在自己的输出上判断差距。沿现有DSH任务说明、文件和原生图像传递，不新增质量账本、会话压缩器或执行前置门。

## 确定参考范围

区分用户指定要求、来源中观察到的事实、作者建议和未知。用户指定的质量参考与可复用的草稿或构建源码可以来自不同版本，不能用方便复用的实现替代要求。只参考质量或风格时，不把原对象种类、尺寸或布局强加给新任务；需要复用构造时再读取相应源网络、输入和依赖。旧工程的错误、缺少的控制和未验证范围不能变成质量标准。

视觉特征如何转成当前对象的形体、表面表示和观察尺度，由[跨场景的风格与质量基准](../../houdini-surface-workflow/references/appearance-and-sources.md#跨场景的风格与质量基准)维护。跨模块传递还需保留图片不能证明的工程意图：

| 需要保留的性质 | 传给消费者的证据与要求 |
|---|---|
| 几何精度 | 已知单位、具名部位的尺寸或间隙、测量范围与容差来源；不从图像、面数或小数位补造毫米精度 |
| 关系可信度 | 部件之间的支撑、连接、附着、间距与共享来源，以及修改后应保持的关系；源对象正确不证明新的布局正确 |
| 可编辑性 | 用户预期的改稿动作、实际入口与受影响消费者，例如改尺寸后接点和附件随动；面板项数不能代替传播检查 |
| 构造与方法 | 用户指定的方法、可以替换的局部、需要复用的原生网络或文件依赖；区分交付要求与源工程恰好采用的实现 |
| 视觉标准 | 能看清相关性质的原始整体或局部图，以及该图用来判断什么；具体特征选择沿表面方法，不用“同样精细”代替 |

来源能提供具体尺寸时保留原测量，转用到不同大小资产时明确哪些是绝对量、比例量或仅外观例子。参考中的未知保留范围，不能通过重复传递变成事实。

## 传给后续任务

当前任务只保留足够用的简短说明：原始要求中相关部分、源HIP或输出的明确版本与帧、必要输入、实际原图路径、要保持及要改变的性质、用户需要的编辑动作、已知缺陷与未知。直接沿DSH已有任务说明传递；需要稳定交付文件时用[文件交付方法](../../houdini-network-handoff/references/file-delivery.md#作为后续任务的基准)，不注册永久资产或精度状态。

负责外观的作者通过原生读图工具读取与自己工作有关的原图，文字解释该看什么。主作者读过图、已加载HIP或已读builder，均不等于消费者看到参考。路径使用已有回执的实际文件，保持文件可用；跨机器时显式携带必需输入。源码或节点片段按实际复用需求另行交付。

不要求每个子任务读全部历史、所有图片或全工程：材质作者需要相关表面局部，布局作者需要整体与占地，曲线作者需要接点、路径关系和净距。无视觉需求的数值任务沿其数据证据。原图不可读时保持对应视觉性质未验证，继续不依赖它的工作；已有足够证据时不反复索取同一资料。

接续时读取当前任务要求与引用原证据，不把一轮最终回复的“已完成”或“高质量”当成新任务的要求或验证事实。源版本改变后只更新受影响的引用和消费者，不反复重扫全部会话。

## 在新结果上判断

先用能代表关键关系或细化程度的局部结果检查理解，再扩展到相似消费者；可以按新任务选择不同构造，不要求复制源网络。视觉比较使用可比的观察尺度与清晰度，结构关系使用对应实体检查，控制关系实际修改并观察最终消费者。图片送达、计算正常、参数响应和审美符合分别判断。

将源工程已修正的问题转成当前任务可执行的关系，例如共享端点、线径与螺距、承载面与贴花、堆叠厚度与支撑，并在新结果上重新检查。源件正确不证明不同布局、数量或控制状态正确；不靠固定通过次数或一张总体相似图结束仍有明确差距的任务。

方法资料和原生图片的按需送达由`tools/tests/dsh-context-loop-fixture.mjs`的`--surface-method`场景核对真实提供方输入；它不证明作者理解、自然采用或新结果质量。这些性质需要实际任务中的相关观察与控制检查。
