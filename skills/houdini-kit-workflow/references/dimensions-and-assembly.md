## 尺寸来源与接口

区分三项事实：**设计目标**（用户要多大）、**源测量**（部件实际多大）、**构造结果**（当前装配做到多大）。Houdini共享控制维护目标和依赖；生成图片中的尺寸文字、自动缩放和总bbox不能把后两项变成前一项。

按任务选取真正影响构造的接口，不另立固定schema：

- 统一单位、局部轴与安装原点；已有工程沿现场，新SOP默认约定见[SOP工作流](../../houdini-sop-workflow/SKILL.md)。导入变换与装配变换分开，避免单位适配执行两次。
- 安装主体／接触面与总外观包络分开，记录允许的外挑、穿插、缝隙及不得侵入的洞口。安装基准可以在几何之外；屋檐不能决定墙体的模数。
- 区分外部跨度、表面长度和部件有效节距：坡屋面的斜长不等于水平投影，瓦片总长不等于搭接后的露出长度。
- 公开用户确实要改的尺寸、坡度、厚度、排布、源选择和边缘处理；说明各自连续范围、离散规格和联动条件。不同时把长度、数量、间距全部设为互相冲突的独立自由量。
- 相邻构件共享接合尺寸／轮廓和方向基准，不能在各分支手抄相似常数。左右端、内外角、屋脊、檐口和终止位置有不同作用，不能只做中间重复段。

多层、渐缩或嵌套建筑应同时定义**建筑比例**和**各部件的变化方式**。层宽变化通常重排柱位、开间、楼板、檐口与栏杆数量。哪部分尺度联动由任务决定，例如柱身只跟层高拉伸，铜箍及柱头由两端控制，柱径仍服务真实截面和接点。层高、收分与层数的组合受内廊、楼梯和支承共同约束。跨层改稿测最终截面、安装位置和间隙，再恢复已认可状态。

为关键部件定义安装给定的原点、目标接点和允许变化。尺寸可调的件指定局部轴、允许比例和必要的保护区。从实测尺寸算局部 `scale = target_extent / source_extent`，围绕安装端点或中心应用；在边界内由尺寸运算吸收余量，超界就重选排数、规格或处理接头。保形件使用固定比例的刚体放置，数量及位置可调；接入宿主的承托、插入面或挂接件与饰件从同一安装基准生成。轻微穿插可以作为接合设计，需要确认实际几何存在接触，且穿插只落在预期区域。

[SideFX Building Generator Utility](https://www.sidefx.com/docs/houdini/nodes/sop/labs--building_generator_utility-2.0.html)允许显式模块宽高，以免外挑影响自动bounds；这是名义安装尺寸与几何范围分离的依据，不保证声明尺寸会自动改好网格。

## 重复件的尺寸域与余量

以实测源为起点，结合数量、间距、搭接、合法局部尺度和连接构造吸收余量。先判断哪些尺寸可变、由谁吸收：

| 情况 | 优先方法 | 不能隐含的代价 |
|---|---|---|
| 瓦片、叠板等允许搭接 | 共享承载面；按有效宽度、露出和搭接定数量与节距，可用限定的宽长适配收口 | 过大搭接会埋住细节；坡度变化后复查支承、侧缝和露出 |
| 有间隙的板列、栏杆、柱列 | 定位置和合法间距，明确从哪端或中心增长；尺寸变化按组件设计分配 | 固定一端与居中拉伸的结果不同；核对端头接点和纹理密度 |
| 连续且要求精确长度的主体 | 限轴拉伸合适的源，或用可调中段＋保形端头 | 浮雕、纹样和五金变形过大时改用分区适配、独立零件或另一规格 |
| 仅特定尺寸能成立的部件组合 | 暴露离散模数或合法规格 | 要求任意尺寸时需重新选构造，不默默改变目标值 |
| 边缘残余 | 合理收边件、边框、端盖或设计允许的局部空隙 | 不能靠遮挡证明实体严密；不得堵洞、重复屋脊或夸大外挑 |

对沿一条直线排列、相同朝向和宽度的刚性部件，可用以下关系判断一组候选是否可行：

```text
L = e0 + e1 + n*w + (n-1)*g
```

`L`是该轴目标跨度，`w`是沿该轴实测的部件占用宽度，`e0/e1`是明确的两端余量，`n`为正整数；`g`为有符号间距，允许搭接时为负。`n>=2`时计算`g=(L-e0-e1-n*w)/(n-1)`，只接受符合本任务间距／搭接范围且节距`w+g>0`的候选；`n=1`没有间距自由度，须单独检查`L=e0+e1+w`。无可行候选时改数量、合法端部处理、来源或规格，不把越界的g夹回范围后仍报告目标已满足。

这只是等宽直线布置的尺寸模型，不是3D碰撞、曲面覆盖或装配求解器。异宽变体需累计实际宽度和间隙；交错瓦、曲面、转角和坡向交汇另按其真实几何组织。不要为通用性提前造覆盖所有情况的填充框架。

长刚性部件放到弯曲承载面上，要用实际支承跨度检查两端和中段，必要时用两接点求安装方向、增加垫件或选较短规格。一个落在曲面上的模板点无法排除饰件的底面悬空或一张瓦的另一端穿出。装饰端的外挑与承载面上的搭接分别测量。

数量切换会导致离散变化。说明锚定边、对称方式和实例身份的有效范围；行列／槽位身份可帮助保留变体，但换排数、改变拓扑或镜像不保证所有用户覆盖仍成立。随机选择尽量由稳定槽位和独立外观seed派生，避免只改长度就无故洗牌全套外观。

## 可编辑构造与性能

默认数据流是源入口 → 一次坐标适配与测量 → 带身份和朝向的装配点／曲线 → 原生Copy等构造 → 独立边缘／连接结构 → 完整构件输出。它是职责划分，不强制每项一个Subnet或Null；共享控制、公共输出与局部原生方法见[SOP完整源与布局](../../houdini-sop-workflow/references/modeling-methods.md#完整源组件与布局)。

将可回退的原型与实例变换分开。小幅局部轴缩放通常可作为实例变换保留UV；改切面、沿曲面形变或实际重建时，检查纹样、法线、接合区与新面材质。多个模块合并的结果只按预期视觉或制造用途验收。

确需修整已有生成构件的接口时，可将原型分成固定接合区、吸收误差的过渡区和保留细节区；由同一安装轮廓重建接合带，核对端面厚度、完整轮廓、UV和新切面材质。只把点压到一个平面并不保证两边吻合；任意切块也不会自动产生可平铺周期。修整在源上做一次，再测最终输出；优先检查代表性相邻组合的全高接缝与孔洞净空，几何成立后再判断材质接边，不逐实例隐藏补洞。

用少量共享原型、原生实例与按需缓存控制成本，不为每个副本重读文件或生成独特网格。[Packed primitives](https://www.sidefx.com/docs/houdini/model/packed.html)共享原型引用；Pack不是压缩，每个实例都唯一时不能指望同样的内存收益。先测实际导入、cook、显存／内存和预览，再决定工作代理、LOD或减面；代理不替换最终高模，也不以固定面数判断质量。

[Copy to Points](https://www.sidefx.com/docs/houdini/nodes/sop/copytopoints.html)可按Piece Attribute选择不同原型，Pack and Instance共享源几何；已打包的输入避免无意重复嵌套。[实例属性](https://www.sidefx.com/docs/houdini/copy/instanceattrs.html)有明确优先级，位置、朝向、pivot与尺度应来自同一装配关系，不能叠加两套隐含变换。保留源UV与材质声明后，还要检查实际渲染消费者，打包成功不证明贴图已经显示正确。

构件内部和总装可以有不同的实例层级；检查目标消费者是否保留嵌套实例、材质与身份，必要时仅转换交付支路。网页中的Mantra材质细节不直接当成Karma合同，具体消费按[资产接入](../../houdini-asset-integration/SKILL.md)与[渲染方法](../../houdini-solaris-karma-workflow/SKILL.md)。

## 变体和换源

一图取得的一组变体也需逐件核对实际尺寸与安装面；同图、同材质或名称相似不保证可互换。分件与纹理保持见[成组变体](style-and-sources.md#成组变体参考与多组件取得)。

| 修改 | 应更新的内容 | 应保留或重新确认的内容 |
|---|---|---|
| 颜色／粗糙度等材质编辑 | 对应材质消费者 | 几何、构造参数和布局；除有实际依赖外不重生源 |
| 同接口部件变体 | 共享原型与使用该源的实例 | 构件目标尺寸；检查新外挑、材质、碰撞及实际覆盖 |
| 部件有效宽度／搭接变化 | 部件测量、排数／间距及边缘构造 | 不复用旧间距当作新尺寸证明；需要时缩小合法参数范围 |
| 构件宽高／洞口／坡度变化 | 构件几何、相关接口与父装配 | 若上层占位或兼容性改变，更新上层规格，而不只换外观文件 |
| 布局位置或整体朝向变化 | 布局变换及受影响接点 | 已认可的部件源与材质，不重新提交云生成 |

生成器网络保留共享源到最终输出的真实依赖。缓存及导出模型必须能关联其输入版本和参数；源变化后更新受影响缓存，不让视口显示新源而最终消费者仍使用旧文件。相关事实留在已有工程和DSH任务中，不另建构件发布状态机。

## 可选布局与WFC

单个模型、确定性建筑或曲线装配可直接交付，不需要求解、catalog或WFC JSON。有明确邻接选择才进入[WFC工作流](../../houdini-wfc-workflow/SKILL.md)。

已知要WFC时，先设计完整构件的安装尺寸、占位、方向、接口、开口与可旋转范围，再让构件生成器消费同源规格；用代表部件测量回验这个规格能否实现。部件尺寸与规格冲突时显式调整设计或来源，不在resolver里暗中修高模。源资产先行的任务则先测量再设计兼容规格，两种入口都合法。

WFC消费完整墙段／屋顶段等构件，不直接管理每片瓦的风化变体。外观变化若不改占位与接口，可复用结构layout；改变兼容性时更新结构规格并重新求解或重建相关布局。已按规格构造的源通常不需再作轴向bbox拟合；当前resolver的精确字段与边界只在[WFC规格](../../houdini-wfc-workflow/references/spec-format.md)维护。

## 用实际结果验收

观察与声称的能力对应，不把全套清单变成每次编辑的固定门：

- **形体与接口：**检查最终输出的接触面、端边、洞口、薄件和允许外挑；总bbox和模板点只能回答各自问题。屋顶同时看中间重复段、檐口、屋脊及终止边，不能只看顶视瓦面。
- **参数范围：**选择名义状态、有关边界和数量变化处；确认尺寸、搭接、支承和边缘仍满足意图。实际不支持的范围给清楚反馈，而不是空模型、静默改值或默认切源。
- **源与材质：**原始文件未覆盖；变体确实独立可替换，最终消费者保留正确UV、纹理、法线及材质。观察近景纹理密度、重复裂纹、色差与材质过渡；无成功识图则视觉未验证。
- **持续编辑：**在同一工程累计改尺寸与换源，确认用户锁定部分和公共控制仍有效；不以重搭整网冒充原位修改。
- **交付：**工程重开后资源可解析，工作代理与最终高模可辨；明确已验范围、依赖和未完成部分。需要HDA再验证新实例，不仅验证作者现场。

合成源可检验节点与尺寸机制，不能认证真实Tripo外观、任意脏网格、所有风格或未测参数域。数值、结构回归和实际材质画面分别报告。

## 屋面铺件与收边

用同一屋面或控制曲线派生瓦列、檐线与脊线。先在实物上测覆盖与露出量，按坡面实际长度排搭接，沿横向保持合理的列或接缝关系。面宽变化时从边界引导列到脊端，在转角用相应瓦型、局部拟合或压边吸收余量。每排独立均分可能使相邻列错位；实际瓦型需要错缝时保留这种关系。

选能同时看出支承、搭接和边缘收口的小片试装。以板瓦和筒瓦的屋面为例，沿坡的排水沟与盖缝件承担不同作用，外露端部用瓦当收口，各家族内再选微差变体。观察斜视和檐下的实际接件，调整节距、承托或源。其他屋面按其本身的瓦型、连续方向和边界处理。[板瓦与筒瓦研究](https://discovery.ucl.ac.uk/id/eprint/10170787/1/s41598-023-35299-x.pdf) · [瓦当馆藏](https://umma.umich.edu/objects/roof-tile-1979-2-7/)
