# Houdini Network Handoff

交付的起点是用户下一步要在哪里操作。文件说明工程在哪里，节点入口说明从哪里开始，网络分组与注释说明怎样继续编辑。这些呈现不证明功能、几何或视觉正确，仍由对应领域方法检查。

本skill只维护跨领域的导航与网络交接。参数布局及面板判断用houdini-parameter-ui；HDA定义、原生工具入口、依赖和通用界面观察方法用houdini-tool-development；SOP/COP/LOP/rig和教程的构造与验收保留在各自skill。

## 主动交付实际入口

新建或明显扩展工程后，主动用`present_nodes`发布用户最需要的入口，不等用户追问节点位置。按接手动作选择，例如：

| 用户下一步 | 可交付的真实节点 |
|---|---|
| 找到本次新增资产或示例 | 新建Geo、资产容器或目标网络，role='node' |
| 调整行为 | HDA实例或真实控制节点，role='control' |
| 编辑路径、源或上游材料 | 实际曲线、源几何、图像输入等，role='node' |
| 继续消费结果 | 稳定公开输出，role='output' |

新增增强版示例与原工具并存时，提供新示例容器和增强实例，让用户能分清原版与新增内容；原版仅在需要比较或维护时再提供。一个入口已足够的小改动无需重复交付全工程。不是按类型、前缀或参数数量自动推导角色，也不把每个中间/检查节点都推给用户。

`label`写用户用途，`description`用一句话写可改的量或下一步动作。使用真实路径，类别由回执提供，不新造context角色。例如：

```python
__result__ = present_nodes([
    {'node': '/obj/asset_demo', 'label': '新建示例网络',
     'role': 'node', 'description': '定位本次新增容器；进入后编辑输入与工具实例'},
    {'node': '/obj/asset_demo/tool_instance', 'label': '调整工具参数',
     'role': 'control', 'description': '调整当前工具的公开控制并观察输出'}
])
```

入口声明需要已命名HIP并写入持久节点标识；按本次保存授权保存同一HIP后再交付文件。未命名或未获保存授权时说明当前路径与保存缺口，不擅自Save As。点击卡片只导航，不执行按钮、改变参数或证明完成。

用户复制节点会复制持久标识。重复时先确认原节点与复制品，对明确复制品用`new_identity=True`重新声明，保留原节点标识；先续新复制品，再重新发布原节点，保存后交付新的入口。它会使该复制品的旧引用失效，不按旧路径猜对象，也不从父容器继承写权限。

## 主动组织用户要接手的网络

新建多用途、多支路或需解释的网络，主动考虑Network Box分组和短Sticky Note；不限定程序化建模。COP可区分输入、处理、输出，LOP可区分资产、材质、渲染，HDA示例可区分可替换输入、实例与消费者。分组按真实职责选择，不套统一建模流水线。

Box回答“哪些节点一起编辑”，Note回答“从哪里开始、输入什么、有什么特殊限制”。短链可只用清楚命名或一条Note；只改标签、诊断探针和临时测试无需制造框。保留已有用户布局、说明和配色，新增内容局部整理；不为美观借`allow_foreign`扩大范围。

需要分组、嵌套或布局时读[网络说明与布局](references/network-layout.md)。Note只记稳定用途、编辑入口、必要依赖和特殊规则，不写另一份“已完成/全部通过”状态账本。

## 观察与交付

布局有拥挤、标签或线交叉疑问时观察相关网络，具体目标选择见[网络布局观察](references/network-layout.md#布局观察)。实际读图后再说明可读性；截图不证明数据流和业务输出。无需观察的小维护不追加固定截图流程。

文件、图片的实际路径与用途见[文件与图片交付](references/file-delivery.md)。最终回复先说新成果及最直接的操作入口，再说明原内容保持、依赖和未验证范围。节点卡、文件卡和文字应对应同一实际成果。
