# Houdini Asset Integration

把已有资产变成能在当前工程中继续修改的组件。提供方成功生成、导入成功、消费者正确和用户可继续编辑是不同事实；方法按当前差距选择，不要求固定建网顺序或新的完成账本。

## 确定接入边界

结合原要求与当前现场，明确允许改变的形状／细节，以及仍需保持的布局、功能状态、安装基准、控制和渲染方法。先读实际源出口、模板与材质消费者；用户已经改过的尺寸和参数以当前值为准，不恢复旧任务的初始常量。

生成、授权、费用与下载使用提供方skill和当前CLI/API合同；不在本插件复制账号系统或厂商默认参数表。取得原任务回执后沿原结果继续，不通过重复生成修复本地导入或显示问题。已有本地文件时直接处理它，不为了采用本skill再提交云任务。需要按风格组织部件变体、分配生成与原生来源并构造完整模块时用[程序化部件构造](../houdini-kit-workflow/SKILL.md)，不必先加载WFC。

## 按当前问题选择工作

外部预览被读图工具以格式不符拒绝时，按文件签名识别编码，保留原件，创建后缀正确的副本或转换，再读取副本。不重新生成模型，也不把未读到的预览当作外观证据。

| 当前决定 | 使用的事实与方法 |
|---|---|
| 新源能否承担旧组件的功能 | 看实际形状、安装锚点、功能面、伸出范围与必要的代表性试装；整体bbox或提示词里的米数不是安装关系 |
| 尺寸／朝向如何适配 | 读取资产单位、节点变换与当前源基准；保留独立适配节点。需要延长某段时保留硬件尺度，非均匀缩放的取舍见[完整源与布局](../houdini-sop-workflow/references/modeling-methods.md#完整源组件与布局) |
| 同物体的状态／外观变体 | 先判断能否共享几何与UV，再改变实际功能区域；重新随机生成不保证形状一致。换颜色不能自动改变灯位、动作或受控部件；未标注RGB只能提供候选遮罩 |
| 材质、贴图或法线不正确 | 先读文件中的材质声明、UV集、纹理及因子，按[外部材质接入](../houdini-surface-workflow/references/sop-preview-and-uv.md#外部资产材质接入)追到真实消费者；原图与SOP预览、Karma显示分别判断 |
| 高低模与操作负担 | 根据观察距离、后续编辑和实测成本选择细节级别；先核对共享源／packed表示，再决定是否减面。保留有用途的原始源，面数目标不代替薄件、轮廓和UV检查 |
| SOP与USD实例接入 | 按[Solaris方法](../houdini-solaris-karma-workflow/SKILL.md)核对实际原型、材质绑定和属性类；同名point/primitive属性的默认值可能覆盖有效身份，模板ID存在不证明最终实例ID正确 |

保留原件的网格、UV 和材质，安装适配放在可编辑分支上。根据零件的用途决定适配方式：板件、瓦件、柱身等可在明确的轴向及控制范围内适度缩放、伸缩或搭接，独立雕饰保留造型并以安装点定位。量测实际源件再决定哪些空间留给接头和收边。把导入、坐标适配、形变、材质和公开输出按用户的修改职责组织。需要新建 SOP 结构时用 houdini-sop-workflow，用户界面用 houdini-parameter-ui。

简单替换先读旧源出口和实际消费者。新源对齐安装原点和方向，再使用与零件用途相符的尺度适配，接入共享原型后检查代表实例。固定截面、孔径和其他功能尺寸应从实际接触关系决定约束，必要时独立处理。材质沿有效的导入链延续，修改已定位的通道。保留有效源法线与切线，法线贴图和切线基底一起判断。

源替换保留有效布局，优先消费布局源已有的稳定ID。共享替换不需要增加实例身份机制；用户需要独立实例覆盖而现有数据不能维持身份时，再在实际布局源中建立可维护的标识，或说明当前覆盖的有效范围。点序、最近位置或包围盒不是跨编辑稳定身份；新增实例、删除实例和拓扑重建后的覆盖失效规则须清楚表达。

## 先跑通一个真实消费者

先用一件代表源验证导入、安装、所需材质通道和少量最终实例。按计划交付的输出观察这个结果，随后将相同路径用于其他兼容部件。按[外部资产材质接入](../houdini-surface-workflow/references/sop-preview-and-uv.md#外部资产材质接入)选择保留原生覆盖或绑定持久材质。启动批量缓存前，确认缓存前后的实际材质、UV 和安装坐标仍成立。有多个材质的网格按实际材质身份分区，变体只有在实际分离并可独立接入时才计作可替换的源。

先量测首次读入、源件加工和重复编辑各自的成本。保持一份高质量原型供 packed 或实例消费者共享，把源准备与频繁变化的布局分开。尺寸或排布控制只应让需要改变的部分重算；高密度读入或切分确实反复耗时，可将适配前、带所需 UV／法线及材质身份的几何一次缓存为项目内 `.bgeo.sc`，以 File SOP 或支持它的延迟读取接入。保留可替换的导入入口。缓存源文件、分件规则或需烘入的属性变更时，更新对应缓存，再核对真实消费者。把构建与必要检查合并到少量批次，避免循环启动进程和暂存同一份大型依赖。 [File SOP](https://www.sidefx.com/docs/houdini/nodes/sop/file.html) · [Packed primitives](https://www.sidefx.com/docs/houdini/nodes/sop/pack.html)

默认的交付分支要满足用户要求的观察距离与细节。只有共享实例仍带来实际操作或显示负担时，才按角色做工作代理，量测真实收益，以相同构图对照原件和代理的剪影、安装面、薄件与贴图接缝。若另有正式优化网格预算，按交付平台和画面差异确定减面量；高、低分支各自沿用一致的接缝和材质语义。工作代理的用途与切回正式细节的入口清楚标在控制节点上。 [PolyReduce SOP](https://www.sidefx.com/docs/houdini/nodes/sop/polyreduce.html)

自包含 GLB 中的 PNG/JPEG/WebP 内嵌资源，可通过[离线准备工具](scripts/prepare-glb.mjs)一次导出为 `scene.gltf`、原始 BIN 及图像，再使用当前 Houdini 原生导入器。命令为 `node <本skill目录>/scripts/prepare-glb.mjs --input <模型绝对路径> --out <工程内新目录>`。用 `--inspect` 代替 `--out` 可只读查看材质声明、图像清单和 `mesh_primitives` 中各 primitive 的声明三角数、材质索引与 UV 集。用各 primitive 的 `position_bounds` 查看 POSITION accessor 声明的局部范围，结合节点变换选择需要展开观察的对象。一件可能跨多个 primitive，同一网格也可被不同节点复用；变体边界、单位与安装尺寸从实际几何确认。工具保留原始拓扑、坐标、材质因子与色彩数据，遇到外链或不支持的图像会报告原因。其他文件格式使用对应原生导入器，运行沿 DSH 文件政策。

## 让反馈推动下一步

优先观察会改变方案的局部：形态／功能不合适时先修源或重新选择来源；纹理连接错误先修消费链；共享实例需要查看展开后的实际几何及材质，不能用外壳面数或保守bbox证明细节缺失。只有取得新的事实、修改或尚未回答的关键问题时才扩大验证，不以检查数量证明质量。

只有接口明确、能独立验证且确实减少总成本时才委派；共享输入和消费者仍在一起变化的替换工作由同一作者连续推进，独立资产准备或接口试验可按依赖分工。需要委派时交付明确输入版本和变化范围，同一模块的构建与普通验证由其作者负责。接收方检查自己的消费者与受影响控制，不复制生产实现来构造“通过”的测试。协作粒度与接续沿[任务拆分](../houdini-task-decomposition/SKILL.md)。

对同一回执的多个小字段使用houdini_resource的select一次读取；大字段再按其指针分页。实际结果已有明确结论时，直接用于下一项决定，不把完整目录、数百条成功断言和重复日志全部搬进上下文。原始事实仍保留在DSH回执／执行归档中。

## 接入与交付

将组件级默认与用户明确需要的实例例外放在已有控制入口。实例身份来自当前布局的稳定来源；拓扑重建后的身份语义若不能维持，应明确失效范围与重选方式，不能用位置相近猜回用户选择。安装点保持与实际功能覆盖分别检查。

独立副本只验证其输入，主作者接回现场后观察必要消费者；验证范围跟随本次修改，不反复重跑已不受影响的全套检查。长任务沿DSH作业等待／查回，当前差距与下一步保留在原生任务中；中断后不重付费获取已有资产。

保存前检查当前结果、有效控制和必要模型／贴图依赖。临时诊断的机位、显示与材质实验按其用途保留或恢复，不能因一次观察成为默认交付状态。用户需要的入口和文件说明沿[网络与文件交付](../houdini-network-handoff/SKILL.md)。无实际识图时保持视觉未验证；本skill不作几何制造或法规认证。
