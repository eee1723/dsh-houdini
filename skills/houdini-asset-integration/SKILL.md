# Houdini Asset Integration

把已有资产变成能在当前工程中继续修改的组件。提供方成功生成、导入成功、消费者正确和用户可继续编辑是不同事实；方法按当前差距选择，不要求固定建网顺序或新的完成账本。

## 确定接入边界

结合原要求与当前现场，明确允许改变的形状／细节，以及仍需保持的布局、功能状态、安装基准、控制和渲染方法。先读实际源出口、模板与材质消费者；用户已经改过的尺寸和参数以当前值为准，不恢复旧任务的初始常量。

生成、授权、费用与下载使用提供方skill和当前CLI/API合同；不在本插件复制账号系统或厂商默认参数表。取得原任务回执后沿原结果继续，不通过重复生成修复本地导入或显示问题。已有本地文件时直接处理它，不为了采用本skill再提交云任务。

## 按当前问题选择工作

| 当前决定 | 使用的事实与方法 |
|---|---|
| 新源能否承担旧组件的功能 | 看实际形状、安装锚点、功能面、伸出范围与必要的代表性试装；整体bbox或提示词里的米数不是安装关系 |
| 尺寸／朝向如何适配 | 读取资产单位、节点变换与当前源基准；保留独立适配节点。需要延长某段时保留硬件尺度，非均匀缩放的取舍见[完整源与布局](../houdini-sop-workflow/references/modeling-methods.md#完整源组件与布局) |
| 同物体的状态／外观变体 | 先判断能否共享几何与UV，再改变实际功能区域；重新随机生成不保证形状一致。换颜色不能自动改变灯位、动作或受控部件；未标注RGB只能提供候选遮罩 |
| 材质、贴图或法线不正确 | 先读文件中的材质声明、UV集、纹理及因子，按[外部材质接入](../houdini-surface-workflow/references/sop-preview-and-uv.md#外部资产材质接入)追到真实消费者；原图与SOP预览、Karma显示分别判断 |
| 高低模与操作负担 | 根据观察距离、后续编辑和实测成本选择细节级别；先核对共享源／packed表示，再决定是否减面。保留有用途的原始源，面数目标不代替薄件、轮廓和UV检查 |
| SOP与USD实例接入 | 按[Solaris方法](../houdini-solaris-karma-workflow/SKILL.md)核对实际原型、材质绑定和属性类；同名point/primitive属性的默认值可能覆盖有效身份，模板ID存在不证明最终实例ID正确 |

输入资产可以保留网格，并不要求重建其程序化历史。把导入、坐标适配、必要形变、材质和公开输出按修改职责组织；不要因接入资产而重写已有有效路由或整件工程。需要新建SOP结构时使用houdini-sop-workflow，用户界面使用houdini-parameter-ui。

简单替换优先走最小路径：读取一次旧源出口和实际消费者，导入新源，统一安装原点，以刚性旋转／均匀缩放匹配尺寸，接入共享原型后检查代表实例。只有用户明确要求保留会改变局部形状的参数关系时才增加局部形变；不要用拉伸灯头、灯罩、五金或座椅来代替整体尺寸适配。材质导入可用时保留真实材质链，只修复已证明缺失或错误的通道，不默认手写整套shader。保留有效源法线与切线；法线贴图必须和切线基底一起判断，不能靠删除N/tangentu或提高金属度掩盖错误。

源替换不要顺手改造路网或另建身份系统。优先消费布局源已有的稳定ID；没有时先完成共享默认选择，并明确单实例覆盖尚不支持任意拓扑编辑。点序、最近位置或包围盒不是跨编辑稳定身份；新增实例、删除实例和拓扑重建后的覆盖失效规则必须对用户说清楚。

本地导入和小范围现场接线不需要为每一步启动独立进程。把构建与必要检查合并到少量有明确问题的批次；同一份回执已经回答的问题直接用于下一步，不为重复读图、接口查询或验证未受影响部件再跑一轮。

自包含GLB中的PNG/JPEG/WebP内嵌资源，可通过本skill的[离线准备工具](scripts/prepare-glb.mjs)一次导出为`scene.gltf`、原始BIN及图像，再使用当前Houdini原生导入器。命令为`node <本skill目录>/scripts/prepare-glb.mjs --input <模型绝对路径> --out <工程内新目录>`；只读发现用`--inspect`。它不联网、不改拓扑／坐标／材质因子、不转换色彩空间、不覆盖现有目录；返回实际路径和原始材质声明。外链资源和未支持图像格式明确报错，不猜依赖或默默下载；其他格式使用对应原生导入器。运行沿DSH终端与文件政策，不能以本工具绕过权限。

## 让反馈推动下一步

优先观察会改变方案的局部：形态／功能不合适时先修源或重新选择来源；纹理连接错误先修消费链；共享实例需要查看展开后的实际几何及材质，不能用外壳面数或保守bbox证明细节缺失。只有取得新的事实、修改或尚未回答的关键问题时才扩大验证，不以检查数量证明质量。

只有接口稳定、能独立验证且确实减少总成本时才委派；三类同源替换及其共享消费者默认由一个作者连续完成，避免重复研究、验证和互发大回执。需要委派时交付明确输入版本和变化范围，同一模块的构建与普通验证由其作者负责。接收方检查自己的消费者与受影响控制，不复制生产实现来构造“通过”的测试。协作粒度与接续沿[任务拆分](../houdini-task-decomposition/SKILL.md)。

对同一回执的多个小字段使用houdini_resource的select一次读取；大字段再按其指针分页。实际结果已有明确结论时，直接用于下一项决定，不把完整目录、数百条成功断言和重复日志全部搬进上下文。原始事实仍保留在DSH回执／执行归档中。

## 接入与交付

将组件级默认与用户明确需要的实例例外放在已有控制入口。实例身份来自当前布局的稳定来源；拓扑重建后的身份语义若不能维持，应明确失效范围与重选方式，不能用位置相近猜回用户选择。安装点保持与实际功能覆盖分别检查。

独立副本只验证其输入，主作者接回现场后观察必要消费者；验证范围跟随本次修改，不反复重跑已不受影响的全套检查。长任务沿DSH作业等待／查回，当前差距与下一步保留在原生任务中；中断后不重付费获取已有资产。

保存前检查当前结果、有效控制和必要模型／贴图依赖。临时诊断的机位、显示与材质实验按其用途保留或恢复，不能因一次观察成为默认交付状态。用户需要的入口和文件说明沿[网络与文件交付](../houdini-network-handoff/SKILL.md)。无实际识图时保持视觉未验证；本skill不作几何制造或法规认证。
