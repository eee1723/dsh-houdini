# Houdini Parameter UI

把艺术家要完成的操作转成易发现的原生控制，分开控制含义、UI布局、写入载体、绑定与领域结果。参数界面可以先于模型，也可以从现有模型提炼，不规定固定顺序。

## 按任务选择起点

| 任务 | 起点与推进 |
|---|---|
| 从零且核心控制明确 | 用户操作/约束→核心参数与最小UI→领域网络/绑定→输出验证→完善布局 |
| 技术路线尚不明确 | 最小可行模型→确定稳定控制→界面/绑定→集成验证 |
| 已有场景总控 | 明确用途→有界读取相关节点参数与已有驱动→筛选/抽象控制→UI/绑定→回归 |
| 只改标签或布局 | 读取参数身份/当前状态→小范围修改→确认绑定和状态保持 |

简单一步编辑直接处理，不强制建立总控、长计划或封装HDA。复杂任务在现有计划中记录意图、控制含义/单位/合法域、目标路径与完成判据；不另造需求账本。
按用户实际要做的操作选择自由度，把自由输入、派生量和内部构造常量分开；不以控件数量衡量程序化程度。
有互相制约的控制时指定自由输入与派生量，或设计显式工作模式，不能把全部变量同时当独立输入。
界面label、help、操作提示和错误默认中文，SOP/VEX/UV/USD/Ramp等专业术语保留；内部name、menu token与已有引用保持稳定。原生菜单的ASCII兼容限制按仓库要求执行，不外推为参数面板必须英文。界面规范与真实SideFX设计参考见[参数界面与交互](references/hda-ui.md)。
技术路线不确定时，用一个核心操作观察主体、附属件与接口的联动。用户必需操作尚未实现时明确部分交付，不能靠隐藏控件掩盖错误。已有接口/动画按绑定迁移合同保护。

## 载体与实现

- 单个SOP产品的控制默认放在该产品的Geo内部（如`/obj/product/CTRL`），让参数和可编辑网络一起交付；先建Geo，再在其中建Null或选已有合适SOP载体。跨多个OBJ的真实场景总控才放`/obj`层，并说明所控对象。create_spare_parms(layout=...)复用组件，默认只追加，拒绝同名覆盖；已有默认值修改走update_defaults。
- 用户明确需要共享节点类型或安装分发时选择HDA，按名联用houdini-tool-development；可调参数或独立保存HIP本身不要求HDA。hda_set_interface(layout=...)是整组重建，已有实例状态需要保留时选择受支持的edits路径。
- parameter_ui提供通用节点参数树、可选状态与结构建议；不要求目标是HDA。只取相关节点，不为做总控默认扫描全盘/全场景。
- [组件参考](references/ui-components.md)与[界面设计](references/hda-ui.md)维护分组、条件、标签和画廊；可以混用普通spec或完全不用组件。
- [控制与绑定](references/control-bindings.md)维护来源/目标选择、绑定计划、持续引用与动作的区别、已有驱动保护及完成门。

组件只组织UI，不猜测目标路径、不注入业务回调。标签/分组变化不得隐式改变内部名和绑定。SOP/rig/Solaris网络和最终输出按名联用对应领域skill。

交付用户要继续操作的控制面板时，按名联用houdini-network-handoff提供实际入口；此处只维护控制含义、布局与观察，不复制节点交付或网络分组方法。

## 验证与停止

涉及组件展开或绑定时先预览对应树/映射，检查已有值、keys、表达式及目标ownership；未知API先verb_help或公开参数自省，再做隔离最小探针。
重复失败且没有新信息时定位载体、参数、绑定或求值层，回到已验证状态，不继续猜参数拼写。
UI回读、绑定表达式、参数响应和最终产物分别验收。按控制的实际含义选择代表性状态与相关部件；相互依赖时再验组合及真实接口，不能仅测整体bbox。具体选参、派生、已测状态与未测范围见[控制与绑定](references/control-bindings.md)。最后改动使受影响证据失效，只重查对应范围。
已有场景明确用户目标后才单次allow_foreign；不能由选择、父网络或路径推断授权。所有live HOM仍经Bridge主线程；外部文件、任意回调和solver副作用不在参数恢复保证内。

## 看实际参数面板

新增或改变分组、条件、多分量或较多控件时，主动核对实际布局。按[通用界面观察](../houdini-tool-development/references/evidence-and-validation.md#观察实际工作界面)发现可见参数页并用返回target捕获，先核对目标节点与当前页；截图保持用户滚动、标签页和窗口状态。需要打开节点、另一页或检查宽/窄布局时，先按任务做明确的界面交互，再观察实际显示；已有交付入口可用focus_node定位。宽度按预期使用条件选择（例如窄至420px），只是测试条件，不是统一设计规格；截图工具不调整面板尺寸。

实际读图看标签与帮助入口、常用控制顺序、重复提示、显隐/禁用、向量右侧字段、水平滚动和裁切。宽面板可读不能证明窄面板可用；长界面和其他参数页不因一张首屏图就算通过。tuple并排导致字段不可见时，优先缩短冗余提示、改善分组或采用实际支持的纵向/折叠呈现，保留内部name与引用。

用`parameter_ui`核对模板、条件与状态；数值/绑定检查证明行为，截图证明当时显示，作者读图才判断合理性。显隐结果与预期不符时先核对模式实际值、条件和求值状态，再选择有新信息的画面，不反复拍图代替行为诊断。相关视觉改动后更新对应观察；只改一个无布局影响的值无需重复拍全套图。捕获、附件与识图能力、失败查回和临时路径规则在通用观察方法中统一维护。

## 证据状态

来源包括用户明确的跨场景管理需求、两种公开HDA界面的抽象模式、SideFX官方机制及H21/H22隔离回归。组件机制不等于未见自然任务泛化。
共享skill整体为candidate；迁移保留旧工具开发reference的名称路由。机制测试、GUI示例、新session曝光和领域结果互不替代。
UI/绑定改变不自动触发艺术渲染，未检查实际布局时明确视觉未验证。治理与回滚沿用houdini-skill-governance；只回退相关注册和文件，不覆盖其他工作。
