# 控制定义与参数绑定

定义先回答“用户想做什么”，再选已有参数或新的抽象控制。控制参数记录稳定内部名、标签、含义、单位、合法域、默认及依赖；不把内部节点目录直接当用户界面。

## 已有场景与从零任务

已有场景只读查相关节点的node_info/list_parms/read_parms/parameter_ui，核对表达式、keys、锁定和现有控制器。
控制范围依据当前请求，不依据当前选择自动授权。优先复用已有上层控制；同名字段不一定同单位，不把数值原样复制给不同含义的目标。

从零可先建立少量核心控制，再创建目标网络和绑定。方法未知先做最小模型。总高度/级数/级高等关系须选定自由变量；绑定工具不决定算法约束。

跨模块使用同一份有效控制：输入值、合法域检查、派生坐标/尺寸分别命名，不能每个模块各自钳制同一个用户值。
横向范围与法向偏移分开；声明“最大值”时用满足不等式的分段规则并验实际输出，不以四舍五入近似上限。
单项滑条范围不保证组合合法；接近耦合边界时检查真实接口与净空，而不只检查参数之间的大小。

## 选择能保持关系的自由度

适用于需要反复调整尺寸、姿态或布局的程序化产品。只改标签/布局、单次独立赋值不必重新设计参数；已有动画或外部消费者也不能因精简面板被默认删除或改义。

复杂控制可在现有任务计划中说明依赖：`自由输入 → 有效值/派生尺寸与锚点 → 受影响实体和附属件 → 保持的关系`。简单直接的绑定靠参数帮助和接线即可理解。

| 类型 | 处理方式 |
|---|---|
| 自由输入 | 用户有理由独立改变的量；声明含义、单位、可用范围与作用对象 |
| 派生量 | 从自由输入求得的尺寸、端点、轴与局部坐标；共享一个来源，需要展示时用只读说明而非第二个可写输入 |
| 内部构造常量 | 当前无需独立调整的工艺或实现选择；留在可编辑网络中，不自动升为公共控件 |

例如总尺寸、分段长度和姿态同时受约束时，选择一组足以确定结果的自由变量；其余从它们求解。只有确有两种用户工作方式时才增加显式模式，并说明切换如何处理已有值；不要用多个互相回写的回调维持表面一致。

尺寸、轴心、端点和接合轮廓由同一来源派生，主体及螺钉、盖板、线缆入口等附属件消费同一当前状态；不是只在默认值下重复写相同数字。具体几何表示与连接方法联用houdini-sop-workflow，不由UI层猜测。

控制方法尚不确定时，可用一个核心操作的小型贯通网络确认主体响应、附件跟随与接合关系。复杂关系尚不能稳定求解时可固定非必需自由度，或使用更直接的用户操作；参数少不免除结构与外观检查。
必需控制未完成时报告缺口；已有公开参数保留身份、值、表达式和keys，缩小范围或改变语义须有兼容迁移依据。不能事后把失败的测试值移出原先承诺范围就宣称修复。

## 公共控制的验证范围

针对最终输出选择少量有区分力的状态，不穷举所有组合：

- 基准检查回答默认结构和关键接合是否正确，避免把已有错误当成正确参照。
- 单项变化回答控制是否按名称与单位承诺的方式工作；关系还取决于其他输入时选择代表性组合，例如短尺寸加大附件、折叠姿态加宽构件。
- 共享同一控制的附件进入相关检查范围，同时观察应保持的关系。参数叫“净距”就量承接面间隙，叫“壁厚”就看相应截面；bbox变化只证明范围响应。
- 用现有`test_controls`执行适用的指标与接口检查，消费实际设置值、case结果及参数/动画/几何恢复证据。最终汇报已测状态与未测控制，不把重试次数、未运行项当作通过数。
- 新建资产另核对约定交付状态，相关外观修改后更新对应图像。有限样本不证明连续全域；没有适用测量时记录未验证范围。

基准通过而组合失败时，回查共享来源、自由变量冲突与构造方法。不能通过删接口检查、放大容差或隐藏控件变成通过。检测方法不支持的关系保持unverified；用户必须依赖而仍无证据的操作不能声明可靠。

上述设计引导为candidate：既有隔离机制覆盖真实表面关系、组合数值输入和状态恢复，不证明agent会自然采用、GUI易用性或未见产品质量。自然任务仍需在新session验证。

## 首版持续数值绑定

bind_controls接受controller和1..32个明确bindings：每项source是控制节点上的参数名，target是精确目标参数绝对路径；可选scale/offset表达线性换算。
dry_run=True返回映射、旧状态与plan_sha256；应用必须提交该expected_plan。计划绑定源/目标identity、值/keys/锁定及表达式，过期后重新预览，不盲目重试。
默认保护已有动画/表达式；replace_existing=True是明确替换现有驱动，仍受目标ownership约束。第一次采用前应由现有场景需求确认替换意图。

当前只支持数值通道与直接/线性HScript引用。源可为字面值或原生插值动画；任意表达式驱动源、源/目标互相交叠的批次、字符串/菜单/按钮/Ramp/multiparm、循环或复杂混合表达式不走此路径。
每通道最多256个keys；超出时先缩小验收范围，不静默截断计划。

原生Switch的模式选择不必使用按钮回调。菜单源不走`bind_controls`，先用`parameter_ui`/`read_parms`核对真实求值类型、索引和选项；
数值索引菜单可用`set_parms`给已发现的selector参数设置HScript引用，例如`{'expression':"ch('../CTRL/mode')",'language':'hscript'}`。
这里路径只是同parent示例，采用实际控制与目标路径，string token菜单需显式映射到目标所需索引，不把标签当索引。
回读表达式并在最终消费者检查两种状态和切回；确认未选分支保持、保存重开后绑定仍在。涉及缓存/反馈的切换按领域方法处理，不能只改选择值就声称输出已切换。

整数目标要求整数源和整数scale/offset，避免悄悄取整。复杂派生关系由领域网络实现，再将稳定输入映射到它的接口。
重新预览后，相同已安装表达式不会重复写入；旧plan直接重提仍因版本过期拒绝，断联遵循原request_ref回执流程。改变已有驱动仍需显式replace_existing。失败恢复本批目标通道，不承诺源表达式或外部副作用恢复。

## UI与绑定独立

明确controller与target之后，最小调用如下。target是已核对的精确参数路径，不通过名称相似度推断。

```python
bindings = [{'source': 'width', 'target': target_parm_path, 'scale': 1, 'offset': 0}]
plan = bind_controls(controller, bindings, dry_run=True)
# 核对来源、目标、旧驱动和映射，再使用这份计划。
result = bind_controls(controller, bindings, expected_plan=plan['plan_sha256'])
```

控件创建与绑定调用之间可以建立模型，也可以读取现有网络；预览和应用之间若有源/目标状态或帧变化，应重新预览。

- section/row/remap/repeater只负责参数呈现，不创建绑定。
- 改label/help/分组不改内部name；目标网络重构时显式更新binding。
- 重建节点会丢弃未纳入构建入口的绑定步骤；先回读本次新identity的表达式及定义保存证据，再判断序列化或求值故障，不能引用旧节点上曾经成功的绑定。
- 导出/缓存/重建属于按钮动作，走工具开发回调合同；普通滑条不默认触发网络重建。
- 绑定完成证据至少包括实际表达式回读和求值；任务还需改变控制并测领域输出。关系未验证时不能宣称总控完成。

## 完成门与反例

先UI任务：新控件→新模型→绑定→调值后最终输出按预期变化。
后UI任务：相关场景扫描→选择明确目标→总控初始化→预览→绑定→旧状态/未涉及参数保持。
反例：只改一个参数值不建立面板；已有动画不被默认覆盖；错路径/锁定/过期计划/自绑定和其他session目标在写前拒绝；中途写失败恢复先前目标。
本实现只覆盖上述接口合同。未见自然任务、交互设计质量和跨多个系统的自动选参仍需另验，不因几何bbox变化证明所有控制有效。
