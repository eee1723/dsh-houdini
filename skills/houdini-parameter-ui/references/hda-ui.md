# 参数界面与交互设计

适用：程序化模型控制节点、场景总控或HDA公开参数。单实例控制默认考虑spare parameters；共享类型和分发才选择HDA定义。

## 先确定接口合同

- 记录完整类型名、命名空间/版本、实际定义库、输入输出及用途。区分内部参数 name 与用户 label；已有 name、menu token 和引用是兼容接口，改标签无需顺带改内部名。
- 区分定义级界面与实例 spare parms；前者影响使用该定义的实例。新增 HDA 的内部网络封装、公开输入/输出和参数驱动先走最小闭环，再考虑布局。
- 最终业务面板不暴露subnet的Input #n Label管理字段；保留端口名和接线语义，隐藏管理参数，不删除用户需要的分区标题或普通Label。SOP标准label1..label4由hda_set_interface隐藏，已有资产仅调呈现时用增量hidden更新并回读。
- 设计建议：按用户操作顺序组织常用控制、可选功能、输出；低频控制按需放进折叠区。无需强制固定 folder 名称或层数。
- 对每个核心控制说明含义、单位、默认值、有效范围及受影响输出。滑条建议范围与硬限制按真实算法边界选择，不把便于拖动的范围当成所有合法值。
- 能用原生参数、ramp、multiparm 和节点/文件选择器表达时优先使用；自定义 Panel 需要独立工作流理由。

## 面向艺术家的界面

首屏用输入、核心操作和主要结果解释工具，顺序由任务决定。连续调节与生成/更新/导出等显式动作分开；普通数值变化不隐式覆盖文件、重建无关网络或重置选择。长操作显示实际状态、目标与取消结果，不能以窗口置顶代替反馈。

按真实含义选组件：一个值用数值参数，分布用范围/Ramp，变化来源用模式菜单，重复模块用可命名条目，空间位置/方向用视口handles。不要为了显得高级给全部参数加预设或做自定义图表；高级交互应减少解释与操作。常用调节直接可见，模式无关项隐藏，需要解释为何暂时不可用的项禁用。标题开关可在折叠后保留主控。

中文标签保持短且有动作意义，单位与合法域放帮助；保留专业术语和稳定内部身份。使用Houdini的主题资源、图标、字体和DPI布局；Qt面板优先hou.qt的选择器、搜索、颜色、TreeView与原生ParmDialog，避免独立网页式皮肤。样式之外保留参数表达式、动画、焦点和用户快捷键习惯。

参考选择、模式或属性菜单必须只读且有界：打开菜单不做场景修复、不写盘、不联网，也不默认扫描整个HIP。Attribute列表来自明确输入和类别；无输入、空属性及旧选项失效有可理解的状态。Group视口拾取需要真实soputils/state入口及取消测试，不能把一个String字段或图标当作选择器完成。

[官方交互参考](artist-ui-patterns.md)给出七种可借鉴的操作结构，以及原生参数/Viewer State/Panel各自适用面。它们是参考与本项目建议，未形成SideFX统一UX强制规范。

## 控件行为

需要快速组织标题开关、紧凑行、按需Ramp或重复条目时按需读[可组合UI组件](ui-components.md)；
组件与普通spec混用，不规定整套布局。parameter_ui(analyze_ui=True)可辅助找悬空引用和可疑菜单条件，建议不自动修复。

参数提升/引用用于稳定数据驱动；回调用于需要明确事件动作的操作。新增“生成/更新/导出”按钮时说明写入对象与反馈，避免调普通数值时隐式重建网络或写盘。

Disable When 适合当前不可编辑但仍需解释的选项；Hide When 适合当前模式无关内容。这是设计建议。规则使用 Houdini 条件语法，不能直接塞 Python 或表达式函数；复杂求值单独实现，再由条件引用结果。实际语法在目标版本验证后使用。

条件要覆盖真实模式依赖：细节模式关闭、重复条目停用、可选子功能关闭时，不相关参数不继续呈现为有效输入。
长度/角度/比例的单位与有效域写入帮助，避免把全部解释挤进长标签。重复条目的显示名与稳定内部身份分开；
名称冲突、越界和重叠需明确拒绝或约定合并，不静默丢弃。只读派生值要能解释有效结果与输入的差异。

动态菜单要区分显示label、存储token、参数类型与默认值；展开菜单不作为修复参数的隐藏写操作。空菜单、无效选择、已有用户选择和新增实例分别处理。业务回调及HDA依赖验证按名联用houdini-tool-development。

## 验收

已有HDA做小改动时，先用parameter_ui(include_state=True)读取实例/定义界面与interface_sha256。
支持范围内用hda_set_interface(edits=..., expected_sha256=..., dry_run=True)预览，再按同版本应用。
update支持label/help/default/范围/条件等；add可追加到已存在folder。缺少字段时查verb_help，
不要把整组spec重建当增量更新。当前拒绝删除/改名/移动/类型转换、ramp/multiparm和实例界面覆盖；
已有菜单/回调的默认值修改也不在此路径。所有受影响实例需要对应ownership。
此增量路径在H21.0.440/H22.0.368隔离测试覆盖旧通道值/表达式/keys/locks与新实例默认；
不验证实际GUI布局、回调或输出。系统自动补齐页签可能仅存在于展开后的界面，原始定义不存在的目标须拒绝。

新实例检验默认值、模式切换、边界值、禁用/隐藏状态和最终输出；修改既有定义时另查已有实例的参数值、关键帧、表达式与连线兼容。multiparm/ramp 涉及时覆盖新增/删除项和保存重开后的值，不能只检查模板存在。

布局改动需在目标 GUI 核对长标签、窄参数面板、帮助说明和可发现性。headless 参数回读不能证明界面可读；Engine 是单独宿主兼容范围，不由 Houdini GUI 成功推断。输出验证只覆盖当前任务的领域，不强制每个工具渲染。
控件机制、中文字体显示、模式切换后的实际显隐和艺术家能否理解任务分别确认；截图文件存在不证明语义可读。通过真实按钮、选择器或视口入口操作后核对最终结果；用户取消与工具关闭不能留下未解释的修改。
