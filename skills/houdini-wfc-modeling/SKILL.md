# Houdini WFC 建模

把用户希望探索的差异落实为可选择的状态，把必须保持的关系落实为约束。模块、规则与求解共同决定生成范围。先用小输入打通实际装配和反馈，再扩展到用户要求的规模与内容。

## 设计生成范围

- 将算法要求和成品要求一起带入小样与分工。任务指定 WFC 或 Model Synthesis 时，在对应结构层让位置候选在选择过程中按约束传播；分层和混合方法要说明各层实际决定什么。开放任务可选择更适合的算法，并准确说明交付采用的方法。
- 明确哪些位置、占用、连接、方向或数量可以改变，哪些由用户锁定。固定模块库、规则及上游输入，只换求解种子也应能产生所要求的差异。检查自由度是否在进入 WFC 前就被固定，或只剩预置槽位的开关。
- 分别选择求解状态、装配单元和公开源的粒度。WFC 决定受约束的离散选择，SOP 装配已确定的结果。一个公开源可以是单件，也可以是整段套件。原生与外部源沿用同一[接口与装配方法](../houdini-sop-workflow/references/modeling-methods.md#完整源组件与布局)。保持求解约束的外观或局部几何变体可在解后选择。
- 有代表样本且希望复用局部模式时考虑 overlapping WFC。已有模块、尺寸与连接定义时考虑显式有向邻接的 tiled WFC。全局关系可用图约束、分层构造或其他约束求解器表达，明确各层保留的自由度和失败反馈。

## 建立清楚的编辑入口

新建生成器的顶层默认从上到下组织为 **模块库 → 规则编辑与观察 → 求解与成品**。每区有可识别的编辑入口和公共输出，区内按用途横向排列短支路。区域使用 Network Box 或 Subnet，按编辑需要选择，模块源保持可直接找到。接入已有工程时融入其布局。

通用 Subnet、Null 与 Object Merge 的取舍由 [SOP 容器与引用](../houdini-sop-workflow/references/modeling-methods.md#逻辑模块与容器选择)维护。三块区域的具体数据流和观察入口见 [Houdini 工作流](references/houdini-workflow.md)。

模块图册、规则试拼、候选观察和成品共享适用的源与规则。观察只读生产数据，成品出口保持独立。用户编辑的端口、配对例外或锁定进入实际求解输入，并能追踪到受影响的候选和实例。

## 持续推进与验证

从最影响成品的未知关系开始做可运行的小样，形成模块、规则、求解、装配的完整通路。整合已有实现或分工产物时，沿实际消费者核对算法、输入和生成范围，再扩展模块和表现。失败时定位到负责该决定的数据或阶段，修复后重跑受影响的输入，并继续完成原目标。任务中的尺寸、配方、试验结果和待办留在工程或原生任务上下文。

用实际输出判断三件事是否同时成立——解满足硬约束，几何满足所要求的拼接关系，结果体现用户期望的变化。选择能推翻当前成功结论的反例，核对改源、改规则和换种子是否影响正确的消费者。性能优化依据正常编辑触发的计时与 cook 次数。
