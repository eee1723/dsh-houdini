# Houdini 工作流

## 顶层网络与公共输出

新建生成器按下表从上到下排布，区内横向展开模块或观察支路。三个区域表达用户的编辑任务，按网络规模选择 Network Box、Subnet 或现有 HDA 组织。具体封装、短线与跨区引用遵循 [SOP 容器与引用](../../houdini-sop-workflow/references/modeling-methods.md#逻辑模块与容器选择)。

| 区域 | 用户操作 | 实际数据和可查看输出 |
|---|---|---|
| 上部模块库 | 改源、规格、允许方向和端口 | 局部坐标原型、模块定义、陈列图册 |
| 中部规则编辑与观察 | 改连接条件、权重、边界或锁定，检查试拼 | 编译规则、目标域、局部试拼与候选观察 |
| 下部求解与成品 | 换种子、求解、选解、查看装配 | 解、安装点、实例成品、诊断 |

公开输出按用途命名，例如 `OUT_PROTOTYPES`、`OUT_RULES`、`OUT_SOLUTION`、`OUT_FINAL` 和 `OUT_PREVIEW`。顶层保留用户要编辑、观察或引用的入口；导入适配、图册排版、实例成形等内部支路随职责归入相应网络。按 [公共出口与几何引用](../../houdini-sop-workflow/references/modeling-methods.md#跨功能区的几何引用)维护成品与预览边界。

模块区的源子网可平铺排列，几何图册从同一批公共源生成。图册标出可区分的 ID、实际尺寸、原点、朝向和端口，按所选模块显示详细信息。图册位移留在展示支路，成品装配引用局部源。

中部的候选或冲突观察可只读引用下部的诊断出口。试拼读取生产规则与原型，自行提供试拼安装点。查看哪一对、哪一格是观察操作；提交禁配或锁定时才改变求解输入。规则编辑与可视化见 [规则设计与观察](rules.md)。

集中暴露正常使用需要的控制，例如求解种子、范围、锁定和显示模式。调试预算、完整事件记录和昂贵检查放进按需区域。参数真正控制相应阶段，详细规则保留可追踪的编辑入口。导航、分组与节点交付沿用 [网络交接](../../houdini-network-handoff/SKILL.md)。

## 实现选择与数据接口

- Labs 2D Wave Function Collapse 适合从二维样本提取局部模式。按实际任务核对已加载节点的全名或类型名、输入与约束，必要时小样验证。安装库中的节点描述可能没有 WFC 缩写。需要显式端口、三维或全局约束时选择能表达这些条件的实现。 [SideFX Labs WFC](https://www.sidefx.com/docs/houdini/nodes/sop/labs--2d_wavefunctioncollapse.html)
- 自定义求解代码尽量将候选与约束运算和 Houdini 几何读写分开，便于重现和定位耗时。Python SOP 可作为读取输入和输出状态的边界，cook 内仅生成其输出几何与属性。复用已有可满足要求的实现，版本化源文件作为明确工程依赖或 HDA 内容。 [Python SOP](https://www.sidefx.com/docs/houdini/hom/pythonsop.html)
- 安装点按消费者需要携带稳定实例 ID、原型 ID、来源位置及 `P`、`orient` 等变换。Copy to Points 的 Piece Attribute 连接点与原型的对应值。声明属性所在元素级别，保留旋转后的端口和源状态追踪。 [Copy to Points](https://www.sidefx.com/docs/houdini/nodes/sop/copytopoints.html)
- 原型、安装点、packed 实例和父对象均可能影响最终变换。列清需要保持规格的源族及允许连续生成的部分。刚体验证按固定源族覆盖最终有效变换的尺度、正交性和按策略允许的手性。同接口换源另查实际转接与最终实例。数据点通过 Object Merge 引用时，核对所需点属性仍可被直接读取。 [实例变换优先级](https://www.sidefx.com/docs/houdini/copy/instanceattrs.html)

## 重算与交互响应

先测正常编辑触发的求解、装配、诊断与绘制。记录冷启动、后续操作和输出规模的条件，用 Performance Monitor 的 cook 耗时及次数找实际瓶颈。分别标明纯算法时间、改参到读出最终几何，以及可测的视口刷新时间。分阶段计时时说明各段是否包含上游 cook 或额外诊断。 [Performance Monitor](https://www.sidefx.com/docs/houdini/ref/panes/perfmon.html)

按真实输入依赖控制失效。求解器消费已编译的规则，换种子复用未变的模块与邻接。改有效规则使相关编译和解失效。同接口换源更新几何消费者，改动求解所用接口则更新约束。切换试拼对象或预览模式时复用生产规则与解，无需改写成品。缓存键覆盖相应阶段的有效输入。用实际输出和 cook 次数同时验证。

交互默认显示满足判断需求的轻量结果。重复资产共享 packed 原型，实网格消费者按需展开。逐步传播记录、全量几何检查与多种子批检可用独立诊断出口或显式操作。轻量输出保留基本有效性与失败状态，最终交付在当前输入上运行用户要求的检查。

求解慢时检查域大小、约束覆盖、传播与回溯。装配慢时检查逐点 HOM、重复采样和解包。先消除重复工作，再依据实测采用批量属性读写、原生 SOP、VEX 或适当实现。Object Merge 保留上游依赖，使用它整理线路后仍需检查 cook 行为。

## 从真实消费者验证

选择与本次能力相称的检查，覆盖正常修改及能推翻成功结论的反例。

- 按 SOP 的同接口换源方法检查实际实例，核对图册与试拼也读取新源。切换纯观察控制时复查成品出口和求解输入仍保持其语义。
- 改一个实际参与的规则或锁定，观察候选与输出响应，并在恢复后重跑原输入。冲突、预算耗尽和旧结果分别显示其真实状态。
- 固定其他输入换种子，观察同条件的结构和成品。按任务查看实际接触、接缝、净空或覆盖，证明范围落在末端消费者上。
- 交付需要独立重开时，保存工程和必要依赖，重开副本复跑代表控制。依据当前工具合同恢复验证涉及的状态。输出同机位对照和能解释关键关系的近景，实际识图后记录视觉结论。

布局效果需要观察受影响的网络，核对编辑入口、标签和引用能否读懂。新建生成器检查三块区域的纵向组织，已有工程检查本次接入与原布局的衔接。展示数据流也应可逐段检查。源码、节点存在或图片已生成只证明相应事实，交付说明写明已验证范围与仍待验证的行为。
