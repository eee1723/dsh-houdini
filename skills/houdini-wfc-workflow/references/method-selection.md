# 方法与规则设计

## 先确定哪些变化需要求解

WFC选择局部兼容的离散状态，不能独自保证建筑合理、轮廓好看、屋顶闭合或模型能走进去。把用户明确的入口、层高、轮廓、主道路和功能分区当作输入；让随机性用在仍然自由的选择上。复杂建筑可先规划体块和通路，再求解立面或区域，但简单房间不必强加多级生成器。

用户明确要求WFC时，说明哪一层实际进行候选选择和约束传播，普通随机散布不能冒充WFC。检查可变化部分是否符合用户期待：如果换seed应改变建筑轮廓、房间占用或道路结构，就不能在上游先固定它们，只留下几个门窗开关。比较不同seed的实际结构差异与用户锁定部分，不能用随机数变了证明生成范围足够。

| 需求 | 最小充分方法 | 需要确认的边界 |
|---|---|---|
| 明确模块接口、门窗数量、固定单元 | 随包simple-tiled脚本，输出普通数据再实例化 | 单格状态、四向yaw；没有从图片自动学规则 |
| 从二维图案／布局样例提炼局部模式 | 当前安装的Labs WFC Initialize Grid、Sample Paint、2D WFC Solver | 样例网格和求解网格分别输入；学习局部模式不保证全局功能 |
| 给既定建筑体块铺墙、窗、转角 | Labs Building Generator或原生分层／分面SOP＋模块库 | 先核对安装版本和模块坐标，不能直接套本skill的Y-up/+Z接口 |
| 同一布局大量风格／外观变体 | 复用layout，更换catalog或外观seed | 不增大结构状态空间，不重求布局 |
| 地形曲线、随机散布、规则重复 | 原生SOP、曲线框架、Copy to Points | 无邻接选择就不需要约束求解 |
| 球面、六边形、全3D旋转或跨格大模块 | 先核对适配该拓扑的现成求解器，如DeBroglie；或任务确需时编写小适配 | 显式图不等于实现了任意局部坐标、24种立方旋转或跨格占位 |

SideFX [Labs 2D WFC](https://www.sidefx.com/docs/houdini/nodes/sop/labs--2d_wavefunctioncollapse.html)提供样例模式大小、旋转、边界平铺、用户固定和重试设置；更大的模式会提高求解成本。[Building Generator](https://www.sidefx.com/docs/houdini/nodes/sop/labs--building_generator-4.0.html)从体块分出楼层和结构区域再放模块，更适合已知体块的立面任务。先查询当前节点合同，不为安装／版本未知猜参数。

随包小求解器的价值是零外部依赖、明确约束与可检查结果；这不构成重做Labs或完整CSP框架的理由。需求超出上述边界时比较现成工具的安装成本、实际约束和编辑方式；不要为了沿用已写代码把所有问题编码成大量特殊模块。[DeBroglie](https://boristhebrave.github.io/DeBroglie/)已有多拓扑、回溯和全局约束，采用前验证其目标环境与转换成本，本插件不隐式安装它。

## 模块接口先于外观细节

WFC模块是能独立生成和替换的完整功能构件，不必是整个房间，也不意味着一块资产占很多格子。窗墙可以包含墙面、窗框和窗台；一段屋面可由共享瓦片源经Houdini装配成完整瓦面与檐口。部件可以很小，布局状态仍按构件组织。风格、部件来源和生成参考沿[Kit风格与来源](../../houdini-kit-workflow/references/style-and-sources.md)，不让WFC承担构件内部每片瓦的排列。代理只表达安装轮廓和影响布局的洞口，已有合格构件可以直接试装。

用项目里的规格／源节点表达以下相关事实，按任务取舍：

- 安装轴和原点、连接平面、墙厚／层高、门窗开口、屋面坡度／檐口线；尺寸只维护一处，图像和测量从该源派生。
- 占位与实际表面分开。墙有两侧安装端面，外侧窗台可越出占位；屋檐可外挑，但入口净空不能被遮住。用明确缝隙、搭接或封边定义允许误差，不靠无限放大bbox。
- 能连的接口才共用socket：例如墙端、门通路、屋面坡向、屋脊和封闭端分别表达。默认同名socket兼容；`socket_pairs`只是额外匹配对，不能取消同名匹配。需要严格公母方向时，把方向角色纳入模块规则或选择表达能力足够的求解器。
- 只有物理接口相同的差异才是外观变体。改变窗洞位置、门宽、屋顶坡度或占位的资产不能只换贴图式地塞进同一asset_key。
- 标准四向旋转仅用于可旋转的模块。非方形网格中的90°旋转要检查占位；解析器不会自动扭曲源来填格。镜像会改变手性、法线／UV及功能，不等于yaw。

内角、外角、边缘、端盖、层间和顶部的连接要在相应代表区域出现。屋顶不靠随机墙顶贴片自动合理：可由体块派生坡面／脊线后布置屋面模块；若确实用WFC生成屋顶，则坡向、檐口、屋脊和支承关系进入规则。共享高质量瓦片与原生结构组成可编辑屋面段，再由WFC布置完整屋面段，是有效路线。连续结构内壳按实际支承和封闭需求选择，不能堵住门窗或代替缺失的可见构造。

可编辑规则应改变真实候选或兼容边，不能只改展示颜色或标签。需要图册／试拼时共用生产模块和规则，在独立观察支路展示，把它们与成品输出分开；一次规则修改后检查受影响的候选与最终实例，不另维护一份仅供展示的邻接表。

跨多格的资产可以采用宏格，或由成熟求解器处理占位。随包脚本没有多格原子状态；把相邻格各放一次同一大模型会重复重叠，不是大块支持。任意图的edge表示已声明的逻辑关系，不从coord猜实体接触；跨越远距离的边仍需独立的空间实现。

## 可解性、可达性与效率

先确认规则允许代表接口，再增加随机变化；边界和用户固定是硬约束，概率不是需求保证。用明确反例区分“没找到”与“无解”。`budget_exceeded`说明本次搜索没完成，不应反复换seed后宣布规则正确；检查约束冲突、状态数量和实际统计，再决定缩小问题、改变规则或提高预算。

相邻道路格可能通过封闭侧靠在一起。随包`connectivity.sockets`指定通行接口后，必须双方对应接口均可通行才算连接；每个模块被视为一个内部连通区域。立交、互不相通的交叉管道、单向交通或房间内多个隔离通路需要更细图／专门路径模型，不能用一个tag证明通行。逻辑可达仍不证明实际人物净空或管径，实体另测。[DeBroglie路径合同](https://boristhebrave.github.io/DeBroglie/articles/path_constraints.html)也区分单元邻接与成对出口连通。

大量结果优先复用合格资产库和packed原型，只计算轻量布局；先测求解和导入／渲染分别耗时，不以节点数推断性能。按区域求解需要共享边界并复核跨区约束，全局门窗数量和通路不能在各区独立满足后直接相加称为通过。当前脚本不提供无限世界或自动增量重解；需要稳定局部编辑时，可先固定不变区域尝试，冲突后明确允许改变的范围，不承诺局部一定有解。

[原始WFC实现](https://github.com/mxgmn/WaveFunctionCollapse)区分simple-tiled与overlapping；[Model Synthesis](https://paulmerrell.org/model-synthesis/)说明基于局部约束组合复杂3D结构的来源。[Editable WFC](https://www.boristhebrave.com/2022/04/25/editable-wfc/)展示保持旧布局需要额外策略，也建议先比较更简单的自动铺块方法。这些是选型依据，不是随包脚本已实现的功能声明。
