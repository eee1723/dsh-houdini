# Houdini Tool Development

交付用户能找到、使用并持续维护的工具。先确定工具用途与归属，再选择实现；普通模型默认保留网络与HIP，用户要求可复用类型或可安装资产时才封装。

## 先明确会改变交付的选择

默认帮助用户持续积累自己的工具体系。**先发现已有Package和工具，判断归属并给出具体建议，再确认尚未明确的选择。** 不先把“独立OTL/自动加载”作为抽象二选一，也不把自动加载等同于另建Package。用户已指定包、工具或独立文件时直接沿用，仅核对相关来源。

| 当前决策 | 默认动作与判断 |
|---|---|
| 现场已有哪套工具体系？ | 用package_catalog有界查看配置和实际加载记录，用tool_catalog查相关已加载工具；再对候选package_inspect/tool_inspect核对资源根、定义来源和代表性命名。不要仅按新工具名称过滤Package；通用个人工具包可能没有同名功能。 |
| 新工具适合归入哪里？ | 优先建议加入用途、维护归属和依赖相容的已有个人/团队工具包，在其真实资源根的otls等对应目录新增工具。官方或第三方包不因已加载/可写就成为个人工具存放处。说明具体包、目标文件、类型名与适合原因；仍有实质歧义时再询问。 |
| 用户不需要加入已有包？ | 用户选择独立OTL时再选择工程目录或当前Houdini用户文档下的otls/hda。需要单独维护一套工具集且没有合适已有包时才建议新包，不为每个工具另建包。 |
| 原位维护还是独立衍生？ | 维护原HDA保留实际源库，以原生类型版本维护指定实例；独立衍生用hda_fork。发现同类工具先判断能否扩展，避免换名重复制作。 |

资源位置、维护归属和加载范围分别说明。已有Package搜索路径已覆盖新资源时通常只新增资产文件，不修改JSON。项目中的资源也可被用户级Package引用；个人otls通常供当前用户/版本跨工程使用，不等于所有版本或整机全局安装。实际个人目录读HOUDINI_USER_PREF_DIR，不硬编码Documents或版本。

沿用目标工具包的命名和组织方式，具体核对见[既有工具包的归属与命名](references/scripts-and-packaging.md#既有工具包的归属与命名)。不因当前工作区可写就把它选为最终工具库；暂存原型不代表交付归属。已确认的目标不重复询问，加入一个工具不授权修改包内无关内容；发现、创建文件、持久注册和当前进程加载分别核对。

## 实现与验证

按用户动作选择入口：持续数值/模式用参数面板，空间编辑用Viewer State/handles，一次动作用Shelf/Tab，跨资产批处理用Python Panel。原生参数不能充分表达工作方式时再引入自定义窗口。Houdini原生Tab、Shelf、菜单标签使用ASCII英文；参数label/help、Qt和网页可用中文。

未知接口先查verb_help或实际节点参数；重复失败时检查原生机制、载体、绑定与业务层，按具体问题选择最小探针。原型通过后逐步扩展，保留可继续修改的结构。新建/维护范围、文件来源和调用上下文需要跟踪时使用DSH现有计划，不另建流程准入。

| 要声称的结果 | 对应证据 |
|---|---|
| 功能可用 | 从公开实例/按钮/工具入口执行，观察实际输出、相关边界输入及需要保持的用户状态 |
| 参数或Qt界面可用 | 真实绑定与值回读；实际界面布局及相关交互。没有成功识图时说明视觉未验证 |
| 下次启动可用、可分享 | 按声明加载方式在隔离新进程发现正确资源、创建新实例并运行；Package必须通过交付JSON加载，临时installFile不代替它 |
| 可继续维护 | 唯一资源来源、更新方式和依赖明确；源文件更新、当前进程加载与窗口/模块生命周期分别核对 |

最后修改只重验受影响行为。HDA写入/恢复按维护reference执行；场景undo不保证资产库或外部文件恢复。精确节点归属由执行层判断，不能以父容器、审计标签或自写理由代替用户授权。

## 交付与边界

提供工具本体或Package配置与唯一资源目录，说明实际入口、当前加载及启动状态、依赖和未验证范围。示例工程同时交付用户需要的实例/输入/输出；节点卡与文件应指向同一成果。临时验证材料按[收尾规则](references/scripts-and-packaging.md#交付与验证)清理，保留依赖和恢复资料。

agent操作HOM走Bridge与动词；交付的Shelf/回调不是绕过Raw Gate或所有权的入口。live重启和HIP保存沿用执行授权；不默认改$HFS、全局启动脚本或向Houdini自带Python安装依赖。项目内部PYTHONPATH兼容布局不是其他工具的目录模板，用户工具采用目标解释器约定。
