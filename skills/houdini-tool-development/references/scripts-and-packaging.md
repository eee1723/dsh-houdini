# 原生Package、源码归属与生命周期

适用：制作或维护可复用工具，确定HDA/Python资源位置、Package注册及实际加载方式。普通建模、使用现成工具或单参修改不触发建包盘点。

## 先发现，再选择归属

先verb_help核对package_catalog/package_inspect与tool_catalog/tool_inspect。只读发现分为两份事实：搜索目录中已配置的原生JSON，以及当前Houdini进程实际加载的包和工具。先给有界列表，再针对相关候选读配置、资源来源和代码；不递归扫描所有用户目录或全盘源码。用户已指定准确工具/包时只核对相关来源。

- package_catalog查默认搜索目录及明确追加的目录；不能把任意子目录JSON当已加载包。package_inspect提供脱敏配置与path/env路径语义观察，不是可直接写回的原文件；修改前通过通用read完整读取目标JSON，保留原字段结构、enable、条件和依赖。多资源根正常保留，不强行解释成一根。
- tool_catalog查相关node_type/shelf/panel/viewer_state/radial；tool_inspect核对精确标识、生效定义、文件或模块来源。包名、目录位于$HFS之外或路径可写都不是发行方或修改授权证据。来源无法关联时标unknown。
- 区分磁盘配置、原生条件/加载报告与当前资源来源；不自行计算未知条件或依赖表达式。磁盘有JSON、Active=True、HOUDINI_PATH含目录、HDA在loadedFiles中，都不能单独证明某项资源来自预期包。原生报告缺失时明确实际加载未验证。

用途、维护归属与加载范围的选择只在[工具开发入口](../SKILL.md#先明确会改变交付的选择)维护。确定需要Package后，一次明确**唯一源码/资源目录**和**JSON注册路径**；注册目录采用当前版本用户packages或用户指定搜索目录。资源目录可以位于项目下，两者不必相邻。

维护已有包/HDA时保留实际来源。已有搜索路径覆盖新资源通常无需修改JSON；选定包不授权修改无关资源。新建工具不强制DSH前缀或版本目录。原库HDA版本追加、独立衍生与定义保护见[HDA维护](hda-maintenance.md)。

## 既有工具包的归属与命名

选候选包时看工具用途、用户/团队维护归属、依赖和更新方式。以实际Package加载记录、资源路径和工具定义来源交叉核对；仅有包名、可写目录或已加载状态不证明适合存放用户新工具。优先读取包内已有说明和少量同类工具元数据，必要时才读实现代码；列表截断且候选未明确时继续有界分页，不把首屏无匹配当成没有工具包。

| 需要沿用的约定 | 核对来源与处理 |
|---|---|
| 资源目录、资产文件名和扩展名 | 实际资源根及已有otls文件；沿用目录层级、前缀和文件组织。新增独立库文件不覆盖旧文件，不把所有工具合进一个库。 |
| HDA内部类型名与版本 | 相关已加载类型的完整名、namespace/base/原生版本后缀；稳定工具身份与功能对应，不用本次任务名、日期或默认DSH前缀另造体系。 |
| Tab/Shelf分类、显示名和帮助 | 代表性同类工具的入口和分类；菜单标签保持ASCII英文，中文用于参数、help及Qt说明。 |
| 重复功能或名称冲突 | 核对现有定义及所有来源，区分原位维护、独立衍生和新工具；不覆盖或遮蔽已有同名类型。 |

依据已有事实给出具体目标，例如包内目标库路径、完整类型名和入口标签，并简述为何归入该包。存在多套规范时沿用最相关子目录/工具族；没有可确认规范时提出最小一致命名，不批量改名旧工具。选定文件路径后显式传hda_file，避免默认路径代替已经作出的归属决定。

独立OTL的两种常用位置是随工程携带的项目目录，以及用户明确选择的当前Houdini个人otls/hda目录。说明各自发现/安装方式和版本范围，不为独立文件强行注册Package；实际加载与后续启动可用性分别验证。

## 直接开发与注册

唯一源码/资源目录就是后续维护和分发的目录，不另外复制一份安装树或生成ZIP。按需建立`otls/`、`toolbar/`、目标解释器的`pythonX.Ylibs/`、`python_panels/`、`viewer_states/`、径向菜单等资源；不预建无用途目录。目录必须采用目标Houdini解释器约定，本库兼容PYTHONPATH布局不自动成为用户工具模板。

机制探针、一次性测试脚本、测试画稿和截图默认放在选定源码之外的任务临时目录；最终源目录只保留工具运行、维护和明确交付所需内容。正式图标、帮助插图、测试用例或示例画稿可能就是所需资源，不能按图片/缓存扩展名或目录名一概清除，也不为临时材料建立另一份安装源码。

已有包扩展优先在已注册资源根新增明确文件。外部脚本、帮助、图标和JSON沿用DSH通用文件write/edit能力；HDA内部网络、界面、section与保存用对应Houdini动词，不建立另一套文件写入入口。确需修改旧JSON时先完整回读，只修改本次所需字段，保留未知条件、依赖、顺序及其他包配置；不套新模板重写旧配置。不了解其加载条件时查原生报告或帮助，不能丢字段兜底。

新包用tool_package_create创建一个此前不存在的原生JSON，指向选定的已存在resource_root；可配置启用意图和可选版本加载条件，精确签名以verb_help为准。它只创建注册配置，不复制资源、不改已有JSON，也不证明当前进程已加载。需要资源变量、多根或更复杂条件的包直接采用完整原生JSON，通过通用文件编辑维护，不把复杂用户配置挤进单根模板。

一个简单新包可以采用下面的布局。变量名和文件名按用户项目选择；本机绝对路径是明确配置，分享时需改为接收者实际目录或经验证的相对布局。

```text
E:/HoudiniTools/MyTools/              唯一源码与资源
  python3.11libs/mytools/             仅建立实际需要的目录
  toolbar/mytools.shelf
C:/Users/<user>/Documents/houdini21.0/packages/MyTools.json
```

```json
{
  "enable": true,
  "env": [
    {"MYTOOLS_ROOT": "E:/HoudiniTools/MyTools"},
    {"HOUDINI_PATH": {"value": "$MYTOOLS_ROOT", "method": "append"}}
  ]
}
```

Package是搜索路径与环境声明，不是任意代码沙箱。追加路径仍可能遮蔽同名Python模块、HDA、Panel或Viewer State；检查实际源路径和独立标识。默认不改$HFS、自带Python/site-packages、全局123/456启动脚本、系统环境变量和无关偏好。依赖放进选定资源目录；二进制依赖明确ABI和安装范围，不直接向宿主pip install。机制见SideFX [Houdini packages](https://www.sidefx.com/docs/houdini/ref/plugins.html)。

## 当前进程动作与持久配置

tool_package_action只通过原生Package接口执行load、activate、deactivate或unload，动作及真实前提以verb_help为准。它不编辑JSON的enable、不删除注册文件或源目录、不清sys.modules，也不保证任意工具的窗口、监听、后台任务或Python缓存已释放。当前进程停用/卸载不等于下次启动停用；源文件更新不等于已加载对象更新。

启动配置变更通过明确目标JSON的通用编辑处理。移除注册与删除源目录分别确认用户意图；存在旧HIP依赖时保留资源。对已有复杂包不能把运行动作当持久安装器，也不接管DSH自己的安装与修复合同。创建资源、注册JSON、当前会话加载、启动发现、重启是不同事实，沿用会话中的授权分别执行和回读。

更新前核对目标源文件、加载定义/模块和已打开工具的状态。开发reload区分模块缓存与旧回调引用，不能强设dirty=False关闭画稿、删缓存来宣称无损热升级。需要重启时先交付可检查结果，并遵循仓库live重启边界。

## 脚本与交互生命周期

| 用途 | 合适位置 | 注意事项 |
|---|---|---|
| 跟随资产类型分发的逻辑 | HDA PythonModule或内嵌section | 显式传入实例上下文，不把类型模块当每实例私有状态 |
| 多工具共享逻辑 | 已选包中目标版本的pythonX.Ylibs或已有PYTHONPATH布局 | 验证ABI、导入名和实际来源 |
| Shelf/按钮/Panel/State入口 | 薄入口转发至模块 | 保留kwargs/context，避免复制业务实现 |
| HIP专用原型 | hou.session | 明确随HIP，不用作共享工具隐式依赖 |
| 创建/加载/升级事件 | 对应HDA事件section | 仅处理该事件，不混入每次cook逻辑 |
| 启动或场景脚本 | 对应pythonrc/ready/uiready或场景脚本 | 仅在确有生命周期需求时采用，核对版本和触发频率 |

参见SideFX [Python script locations](https://www.sidefx.com/docs/houdini/hom/locations.html)及[HDAModule](https://www.sidefx.com/docs/houdini/hom/hou/HDAModule.html)。模块导入不自动改场景、开窗口或写文件；参数菜单保持只读低成本。纯数据转换与HOM/通知层分离，GUI回调不阻塞socket或进程探测；后台只处理非HOM工作，结果回到受控主线程应用。

工具生命周期同时保护原Houdini内容和工具新产生的文档。窗口只是视图，未保存内容不应只存在临时宿主控件里；核对宿主销毁、场景加载、关闭/重开、取消、重复进入、监听释放和异常。键盘动作验证真实焦点与context，保存点和当前文件路径按实际文档状态维护；内部undo/save函数成功不证明用户按键或连续工作流正确。

保存或导出使用本次调用唯一的暂存文件；成功、取消和异常都精确回收本次未发布的暂存内容，不扫目录里的全部`.tmp`。失败保留原始错误、既有作品和恢复所需内容；多文件输出发生部分写入时如实报告，不能以清理暂存文件冒充完整恢复。

源码与内嵌section只选一个权威维护源；有生成器时说明同步命令，避免手改section被下次构建覆盖。声称可再生成时，入口包含完整接口、内部网络、绑定、端口和定义保存；隔离环境重建不能依赖会话全局变量或历史exec。原型/probe与有效构建入口分开，现场修补同步回唯一源后复验。

## 交付与验证

交付实际JSON路径、唯一资源目录、公开入口、依赖、简短中文使用说明和已测/未测范围。分享以复制资源目录并配置JSON路径为基础；不以归档存在、生成成功或Active=True代替入口验证。

最后一次受影响的公开入口验证后，按本次操作记录回看实际文件，清理这次创建且已确认不再需要的探针、测试图片、草稿或可再生成缓存。只处理明确文件，不整目录递归删除已有包、不推测其他插件的归属；运行依赖、恢复所需备份、公开交付源、用户参考/文档和在途捕获继续保留，DSH执行归档不作清理。测试图片被`read_image`读取或记入临时日志，不等于用户要求保留；是否删除仍以本次来源和实际用途为准。清理本身不改变Package加载配置或关闭窗口/移除模块，若清理触及运行资源需复验受影响入口。普通文件清理使用DSH通用文件工具，HDA内部或场景节点仍使用Bridge动词；不另建交付清单账本或完成闸门。已授权工具任务包含这类明确的一次性材料收尾，无需逐文件再问；来源或用途不明的文件保持不动，确需处理用户内容时才对齐范围。

在声明版本的隔离偏好目录/新进程，通过交付JSON真实Package启动发现资源，核对实际模块/定义路径、新实例和公开入口。直接installFile或sys.path加载只证明局部能力，不能证明包条件、加载顺序或移机。按工具副作用检查原节点/参数/选择/帧/视窗以及工具文档，测试缺依赖失败、重复打开/调用、关闭和取消；不扩大到无关全套验证。

保留源目录和旧HIP依赖的恢复路径；本调用回滚只恢复明确文件或注册变更，不覆盖其他在途修改。现场尚未加载、条件不符或旧缓存保留时诚实报告，不能用创建JSON来宣布工具已可用。
