# 教程转录的按需引导

只在`video_models`报告缺项、用户要换服务或实际调用失败时读本页。配置不是建模准入计划，也不要求每次任务重新问一轮。

## 先读事实，再问缺项

1. 调`video_models`：区分服务配置、凭据存在、本机依赖和实际转录结果。聊天模型目录、已存key和HTTP地址不证明ASR可用。
2. 已有信息足够就直接配置；缺少时用DSH原生提问收集非秘密选择，不要求用户知道JSON协议名称。
   - 解析文字还是复现工程、所需视频/时间范围：优先沿用本次目标，不再重复问。
   - 音频必须留本机，还是允许发送给指定网络服务；已有授权覆盖该服务和范围时继续。
   - 沿用哪个已有DSH提供方，或官方/中转/本机服务的准确地址与文档。Agent据原始文档识别接口，不要求用户自行拼端点。
   - 服务公布的准确模型ID。ASR/STT是同一用途，TTS不是本任务所需；不为语音模型造聊天模型目录项。
   - 额度/并发/速率是否已知。不知道时用默认2并发、每秒1次；本机可先1，不把上限64当套餐能力。
   - 语言、说话人、精确词句时间仅在目标确实需要或识别失败时问。自动语种和分片级时间已有意义，不能伪造精确时间戳。
3. 确认实际接口能力后用`video_configure`保存非秘密配置。可以分步补齐；换服务后不沿用旧模型/协议/无认证模式来猜新服务。
4. 若服务需要密钥，告诉用户打开「设置 → 教程视频 → 安全录入或更换密钥」。该输入只调用DSH原生credentials/set，
   Agent只重新读取configured布尔值。不要请用户粘贴key到聊天、ask_user_question答案、代码或环境命令。
   既有DSH服务商的明确API-key引用可复用；OAuth聊天登录不代表获得转录授权。
5. Python/FFmpeg由插件检查和自动定位；不让普通用户配PATH或pip依赖。只分析教程不必先绑定一个Houdini场景。
   画面语义识读沿`houdini_capabilities`核对当前主模型；缺少图片能力时引导原生模型选择，不另建识图账户系统。

## 协议边界

| 实际服务能力 | 处理方式 |
|---|---|
| 兼容OpenAI文件转录的multipart请求/JSON正文 | `openai-transcriptions`；支持明确的自定义端点路径与本机无key服务 |
| 同步音频Chat、input_audio JSON | `qwen-chat-asr`；模型ID独立，要求服务实际提供此请求/响应合同 |
| DashScope同步音频JSON | `dashscope-asr`；词表/说话人与时间信息仅按实际支持处理 |
| 实时WebSocket/WebRTC或异步job提交+轮询 | 需要专用适配器；不能改模型名或把file协议指向流式地址冒充支持 |

新厂商只要兼容已有协议，通常不需要改skill。新协议的请求、取消、费用和恢复属于执行适配器，不把厂商分支堆进提示词。
自建服务只需其真实兼容端点，不将GPU/推理依赖安装到Houdini Python。需要部署本地模型时，先确定硬件、资源下载和独立环境，
参考实际项目官方文档；不能默启DSH语音bundle、修改用户默认听写提供方或下载大模型。
DSH自带的可选短录音服务不等同于教程文件接口，其WAV格式、时长和返回值边界须另外验证。

## 小额验证与续跑

网络试段前，已有授权必须覆盖目的服务、音频范围及费用。只有localhost地址不能证明其后端没有再转发，隐私要求以服务实际部署为准。
用已有prepare目录中的一个有讲解片段执行`video_transcribe({work:实际目录,max_chunks:1,allow_upload:true})`；
本机loopback无需额外的外网上传确认，但服务自身是否联网仍需按用户要求核对。
检查原文、语种和错误，再在同一任务目录继续；有字幕时可直接复用经核验字幕，不强制付费转录。
并发会在过载后排空、降低并只处理未尝试的新片，最低1再失败停止；已经失败/未知的片不自动重发。
`max_chunks`控制本次提交总量，并发和每秒速率不限制总费用。用户明确授权完整范围时可整批，不把试段做成永久执行门槛。
换配置不会改既有任务的endpoint/model/protocol/auth或结果；身份不符应使用原配置续跑或明确新建独立任务，不混写账本。
