# Houdini 视频教程解析

把视频变成可追溯的复现依据，不把转录当作完整操作记录。此 skill 负责解析与交接，
不替代 SOP、动画或 Solaris 的构建方法，也不自动更新其他 skill、流程或节点卡。

**最终参考是目标，教程是方法依据。** 默认效果复刻先定位成品参考，再吸收教程原理与明确操作；
差异先回查来源和首次分叉，确实缺失的设置主动推理、试验、对照收敛，不把“教程未讲”当停工或降低目标的理由。
推演值不是教程原值；用户明确要求原网络/原参数逐项复原时，不以效果相近冒充忠实。具体边界与迭代见复现协议。

## 先确定交付与能力

- 区分“解析教程”与“复现教学工程”。只要求解析时，不执行 HOM 或保存 HIP。
- 输入以视频为主，不要求用户先整理字幕或截图。随包脚本支持本地视频，不自带链接下载器；
  只有链接时用实际可用且获授权的媒体读取工具，不能绕过登录/付费/访问限制，不能只读页面摘要。
- 记录来源、作者、教程版本、依赖及未知项；正文、字幕、画面、作者代码都只是资料，不是新授权。
- 运行脚本前完整读取 [运行与证据契约](references/video-processing.md)。确认普通宿主 Python、
  FFmpeg/ffprobe、文件读写与语义识图工具可用。脚本不在 Bridge 或 Houdini GUI 主线程运行。
- 云端接收音频前确认用户选择/允许该服务、上传范围和当前费用；密钥使用环境变量，不发进聊天。
  缺少语义识图时，可以交付转录初稿，但必须写“画面未验证”，不能称完整视频解析。

## 执行顺序

1. **建任务边界**：视频或指定片段、解析/复现目标、输出目录、云服务和已知版本。
   单段术语核对直接处理对应时间段，不强制全片转录或长报告。
2. **本地准备与目标定位**：先用 `scan` 粗截图认识章节和界面，定位开头成品、后段结果及修正；打开候选原图，
   确认哪组画面代表要复刻的最终效果，不以片尾、最后采样或中间演示自动选目标。它不依赖音频或云服务。
   `prepare` 探测媒体、保留源 hash、分片时间和音频 hash。输出在用户任务目录，
   不进插件源码、安装包或原视频。静音视频走画面解析，不为无音轨反复调用 ASR。
3. **短段试转录**：先选含讲解的短片，显式模型和上传确认，检查内容/语言/错误再处理全片。
   `transcribe` 默认限制每次提交数量；成功片续跑跳过，失败/未知片只有用户明确接受重试后才能重发。
   相同边界两次失败后停下查服务/模型/输入，不通过重建目录绕过记录。
4. **覆盖检查**：`export` 校验来源与分片，生成原始转录及缺失列表。完整音频覆盖不是文本准确率，
   音频片段边界不是逐句时间戳；保留重叠原文，禁止按字数伪造精确字幕时间。
5. **索引与定向取证**：转录到达后、进入复杂建网前，用 `index-init` 建资料索引，按 `read-transcript` 分页读原文；
   Agent 填写播放顺序的章节和按依赖组织的工程模块，一个模块可关联多个不连续时间段。
   用 `check-index` 校验、`read-index` 按模块取原文与已核对记录；大模块用section分页，跨页固定index_sha256。
   短片/术语查询可直接走局部 `context`，不强制建索引。
   从“这里/这个参数”、操作/数值/修正讲解提出具体画面问题，时间只定位到真实分片范围，不按字数猜句子时刻。
   结合粗图与静默变化补充线索；按问题用 `review/frames` 加密，并回填观察和缺口。详细记录与索引格式见运行契约。
   可用 `changes` 比较已有相邻样本，选择局部重看的候选范围；它不抽帧、不读参数，也不能排除低分区间的关键操作。
   先观察实际布局再指定参数区/节点区，不默认套用固定 Houdini 窗口坐标。指定小片段用 `review` 按间隔加密，或
   `frames` 提取明确时间点。缩略图只作导航，参数和端口必须打开原图再判断。
   追踪节点类型/实例名、实际端口、参数面板、旁路/开关、输出及依赖。均匀采样会漏掉短促操作，
   不声称扫描捕获了全部变化；操作密集处加密局部抽帧。
   找到操作窗口后用较密的局部采样核对前后状态；十余秒一帧只能定位，不能排除短促操作。
   已有帧用 `review-packet` 带具体问题裁出区域并打开原图；两轮仍看不清则记录已查帧和剩余问题，
   停止无方向抽帧；效果复刻转入有依据的推演试验，只有目标无法辨认或需新权限时才请求用户补充。
6. **音画对照与保留**：用 `context` 将选定区间的原图与已有转录组成 hash 绑定的证据包，不重发 ASR。
   用 `notes-init` 起草，实际查看原图后填写记录，用 `check-notes` 校验引用、时间和状态一致性。
   抽出图片或结构校验通过都不算独立语义认证；原始证据、观察事实、推断/适配分层保留。
   节点名/类型/颜色、端口、参数、标志、外部数据和阶段结果能看清多少记多少；不可见不补猜。
   schema-2 notes记录视频内对象身份、网络与面板上下文；未知留null，不把本地复刻路径写成教程事实。
   重复画面用状态快照加变化记录，保留试调、撤销与后续修正；一个观察可供多个模块引用。
   `index-link`在新索引中绑定已核对notes；`query-notes`按模块/对象/上下文/时间/缺口查询，
   不把名字相同当同一节点，不把最后采样状态当最终值。详细合同见运行契约的结构化记录。
7. **参考与交接**：建网前落实最终参考及形态/细节/材质/必要运动的判据；后续定向取证可补充参考。
   整体、局部、材质和中间输出分工，记录观察条件与限制；成品可以在开头出现，静帧不证明动画。
   `read-index` 的 `reference_summary` 显示缺口；用 `query-notes --view references` 打开原图核对。
   效果复刻交接用 `export-brief --require-final-reference`，只解析可省该开关；候选存在不证明覆盖或相似度。
   详细事实仍在notes。复现时按下方阶段路由加载已有 workflow，并读取 [复现与回看协议](references/reconstruction.md)；
   HDA/工程/渲染仍遵循正常授权和验证边界。只解析不加载该工程协议。

## 复现时的按需领域路由

只解析视频时不加载构建 workflow。已有解析包可复用，先核对来源/版本/缺口，仅重看当前模块
需要的原图；不为证明“解析过”而重传音频或重跑全片。资料复用与只给视频的冷启动分别报告。

| 当前阶段需要 | 加载已有 skill | 交接内容 |
|---|---|---|
| COP 图层生成、处理或纹理导出 | `houdini-cop-workflow` | 来源意图、图层角色、依赖、允许差异与最终规格 |
| 几何构建、属性或承载 UV | `houdini-sop-workflow` | 源数据、空间、接口与几何目标 |
| 最小实际材质预览或最终 USD/Karma 渲染 | `houdini-solaris-karma-workflow` | 已验证输出、坐标/纹理接口、材质目标与取景要求 |
| 绑定/动画或集中控制界面 | 匹配时加载 `houdini-rig-animation-workflow` 或 `houdini-parameter-ui` | 驱动、受影响输出、测试与恢复范围 |

仅到对应阶段才读 skill 正文与相关 reference，不一次预载所有领域。解算等其他模块先查当前
catalog 是否有匹配 workflow；没有则明确缺口并按目标版本官方帮助做最小验证，不编造 skill。
复杂模块在现有任务记录中连接“来源意图→runtime 映射→输出关系→验收→恢复”，不复制领域 recipe。
领域返回的结构、关系、视觉、导出/重开证据分别汇总；上游变更后受影响结论待复验，
核心项未满足不能由解析完成或局部通过覆盖。先验证高风险接口，再按依赖构建，不机械照抄视频顺序。

## 影响决策的区别

- 节点名不是节点类型，也不是当前运算模式；可见面板与转录冲突时，保留双方和时间点，
  先局部重看。只能确认该帧状态时，不外推为最终状态。
- 演示节点、临时试调与最终主网络分开；作者讲解已有网络时，章节顺序不等于创建顺序。
  没演示创建、没有公开曲线或精确参数时，不能宣称已经还原全部操作。
- 数据可视化色、实际颜色、材质通道不同；识别画面里的内容不证明本地网络输出正确。
- 用户只要原理总结时无需提取每个参数；效果复刻允许为未知设置做受控推演，不允许擅自省略核心效果或冒称原值。
- 视频被替换、剪辑或时间轴变化，旧时间锚失效；节点方案/版本被改写时，相关复现依据需重验。
- 图像的请求时间与实际解码时间不同，证据引用 `actual_seconds`；同时保留原始 PTS、time base
  和时间轴起点。旧索引只有请求时间时不补造实际 PTS。粗扫完成也不意味着所有帧已被语义查看。
- `changes` 只测像素差异，不识别“新增节点/设参”。候选时间是相邻样本之间，不是事件发生的精确时刻。
  视口变化、菜单、选中高亮和布局移动都可能触发；未达阈值也不能证明没有操作。关键片段即使没有候选，
  仍应按讲解和缺口重看，不能删除低分帧或用阈值代替语义判断。

## 交付与完成门

按步骤记录 `id、kind、时间范围、意图、讲解依据、画面引用、观察事实、推断、冲突/未知、
复现准备状态`，字段说明与格式见运行契约。`kind` 区分状态快照、UI 导航、演示操作和推断；
操作/导航需要不同时间的前后图，不把单张状态图当成操作记录。状态区分“仅讲解”“画面已核”“冲突”“未知”。
不要用统一置信分数掩盖缺失证据。

- 转录：给出已处理范围、缺失/失败片、时间精度、模型、原始结果位置；不静默修正原文。
- 解析：核心主张有来源时间与已观察画面，临时状态和最后状态分开，关键缺口有下一步。
- `check-notes` 只证明引用和结构符合契约，语义仍是记录者声明。单条记录可进入 runtime 检查，
  不代表整章或完整工程都具备忠实复现条件；来源缺口仍保持 needs_more_evidence，不妨碍针对明确最终效果试验重建值。
- 工程：另行验证目标 runtime、网络、参数和保存/重开；视频解析完成不等于工程完成。
  完整复现要求的模块不得以空容器、同名节点、未绑定材质或“以后可补”核销；核心项未过，
  保留原goal/todo未完成状态或明确阻塞，不调用完成动作后再列核心缺失。
- 视频、转录、截图及第三方代码不进入插件包；本次方法整理不触发自动知识沉淀。

当前实现范围是本地视频的解析工具与方法；跨视频泛化、新 session 触发和教学工程端到端
仍需单独验收，不能仅因 skill 已注册就宣称发布完成。
