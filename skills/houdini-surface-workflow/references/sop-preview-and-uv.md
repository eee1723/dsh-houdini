# SOP应用与UV

适用：H21/H22新建SOP表面外观、贴图绑定与视窗观察。精确参数先读当前runtime的node_info/list_parms；旧材质或用户指定方法保持原意。

## 既有材质与预览赋值

已有工程从最终几何的实际材质身份和消费它的网络反查来源：读取相关primitive的`shop_materialpath`，核对指向的节点及下游ROP或Solaris导入/绑定。材质可以来自节点内部或现有LOP材质库，`/mat`为空不等于工程没有材质；颜色属性和材质路径也分别判断。

`coppreviewmaterial`会将选中primitive的`shop_materialpath`写为该SOP内部的预览shader路径，Group外的primitive保留原赋值。它改变了实际几何上的材质身份，已有下游若消费这条属性，可能随之改变渲染绑定。只在需要修改的范围接入；同时保留既有渲染外观时，可在改变处保存原身份并在真实消费边界显式适配，或保留各有用途的输出分支。按现有依赖选择最小方案，不默认另建整套材质和双输出。

H21.0.440/H22.0.368隔离数据链已核对Box原材质路径、局部/全体Preview赋值及上游保持；内部shader节点可定位不等于正式渲染器已正确消费。SOP显示、USD材质绑定和最终shader效果分别观察，不能凭Preview路径存在宣称它们均已通过。

## COP Preview Material的三种输入

选择用SOP预览消费图层时，将`coppreviewmaterial`接在实际几何上，用Group限制相关primitive。Constant、File、COP是它支持的输入方式，不是每个资产都要建立的三层网络。已有外观沿原材质编辑；需要可编辑图像处理时，建立稳定COP输出并引用它。按源组件或语义组共享来源，不按每个面建立节点。
节点卡维护参数易错点；`basecolor`等标签可能是界面标题，不是可写颜色参数。按实际参数类型设置，不猜名字。

| 外观输入 | 应用与编辑 |
|---|---|
| Constant | 直接设置底色／粗糙度等，纯色无需图片、COP或UV |
| File | 引用实际图片文件；需要可移交时使用合适的$HIP相对路径并保留依赖 |
| COP | 指向确切的COP节点／输出；用可辨图案确认采样。编辑时保留网络，文件导出按需加载COP交付资料 |

简单纯色直接使用所需常量；已选择COP图层作为外观来源时可用一层与输出。无空间变化不用UV，不用烘出纯色文件。复杂图案的设计才加载COP workflow，避免把常量设置变成完整纹理工程。其他通道只按意图增加。

某个通道换来源时只改该通道并复验显示，不重建整个材质。H21.0.440/H22.0.368的隔离观察中，首次显示Constant后切换COP可能仍显示旧色，参数回读正确不足以证明刷新；稳定COP颜色输出的纯色→图案路线另行验证。不要清空用户全局缓存或修改内置材质内部来隐藏该现象。校准时核对Tint With Cd，防止上游调试色意外乘到贴图；有意调色则保留。
材料赋值应在最终几何上存在，继续经过Merge/Copy/形变后仍应成立。给源组件做好表面再复用；实例需要变体时显式组织变体，不复制整套相同贴图。

替换旧的几何印字、屏幕内容或贴花时，核对它们已退出最终消费分支，避免新旧图案叠加；有厚度的承载物仍按用途保留。旧源可离线留作设计来源，但内容和布局只保留一个可编辑维护源：由它驱动图层或直接在图层源编辑，不让两套复制值同时被说明为有效入口。检查新图案在最终装配上的位置、遮挡、方向与材质响应；局部COP输出、已存在的surface_id和材质绑定分别只证明自己的范围。

## UV与程序化构造一起设计

UV把二维图案定位到表面，接缝处通常需要vertex UV才能让同一位置有不同坐标。不要默认用point UV表达所有展开。

检查的是要表达图案的实际表面，而非整件属性范围。一个投影可让U/V的全局范围都非零，却把某些朝向的面压成UV线段；例如沿长轴映射侧面，端面仍需独立处理。用有方向的校准图观察代表性正面/侧面/端面，必要时检查对应多边形的UV面积、拉伸与方向。全图层有变化、全物体存在uv或能读到材质路径，都不能替代这一步。
先选择贴合表面的原生UV投影/展开或成形节点的UV；自定义坐标按实际局部轴与表面类别构造，不把同一个世界坐标表达式套到全部朝向。拉伸单位源再复制时，保留0..1 UV意味着纹理会随物体尺寸拉伸；需要物理纹理尺度时，还要让坐标范围/重复次数消费实例尺寸。端面、侧面与切边的表示按可见需要决定，不强制全部用一种映射。

| 表面或编辑目标 | 坐标思路与检查 |
|---|---|
| 面板、标识、局部涂装 | 在对应局部平面投影；限定正面/区域，避免投到背面或相邻部件 |
| 管状、旋转或沿路径表面 | 原生成形的UV或匹配的展开；检查接缝、端盖、路径方向与长度变化 |
| 复杂表面、精确图案定位 | 明确UV缝与岛，按需要展开和布局；检查拉伸、重叠及边界留白 |
| 重复材质与微表面 | 明确每次重复的物理尺度；无方向噪声才考虑合适投影，不能把三平面当作文字定位方案 |
| 复制／变形 | 需要随表面走时在源／静止形态建立UV，保留穿过后续操作；避免直接使用随运动变化的世界坐标 |

仅需要平铺时，重叠UV或超出0..1可以合理；烘焙独有信息时才要求相应不重叠与间距。不要给所有模型强制UDIM或统一展开法。
闭合曲面的坐标跨周期时，要让单个面内保持连续；圆柱角度直接从+π跳到-π并写进共享point UV，会使接缝邻面跨过整张图。可用原生成形UV、明确接缝的展开或连续参数化；仅把属性类型改为vertex不会自动修正已有坐标。闭合一周与固定物理重复周期不一定同时满足：周长不是周期整数倍时，按设计选择调整周期、允许隐蔽接缝或局部过渡，而不是默默改变用户要求的图案尺度。
尺寸控制需要明确：图案跟随比例，还是保持实际大小而改变重复次数；标签可有独立尺度/位置控制。改变长宽、重复数量或形变后检验实际图案，不能用“存在uv属性”核销。
检查按当前性质选择：连续性看相邻面/接缝，物理纹理密度看局部表面距离与UV变化，贴合看实际承载表面。尺寸包围范围可以验证尺寸响应，但不能代替这些局部性质；不必为纯色或无空间变化的通道增加无关检查。
分辨率按观察距离和最小需表达细节选择，具体诊断见[贴图清晰度与观察尺度](#贴图清晰度与观察尺度)。

## 贴图清晰度与观察尺度

从最终画面中需要辨认的部位出发，同时检查原图像素、实际UV覆盖和COP/材质所消费的输出。贴图采样密度是单位表面分到的像素；同一图片、同一UV跨度覆盖的物理长度扩大十倍，沿该方向的采样密度就降到十分之一。相同文件分辨率不代表不同尺度资产有相同精度。需要时从实际UV与表面范围量测，或发现现场可用的Texel Density工具；不默认依赖Labs安装。

| 观察到的差异 | 下一步检查或修改 |
|---|---|
| 原图已经软、特征粗大或绘画化 | 回到[素材内容与来源](generated-textures.md)；分辨率、图案尺度和风格分别调整，放大文件不证明细节恢复 |
| 原图清楚，表面上模糊或像素不足 | 核对实际消费文件/输出、COP分辨率、UV占用与重复范围；纯色转图案时检查中间输出是否仍把空间图案降到小图 |
| 正视清楚，斜面或远处细节丢失 | 检查投影、拉伸、画面中可用像素和纹理过滤；保留必要抗锯齿，增加渲染采样不能补回已丢失的源细节 |
| 图案清楚，整体仍显卡通或塑料 | 对照目标检查形体比例、边缘与结构层级、图案对比、实际材质响应和光照，修改负责差异的部分 |

先用低成本预览定位问题，再只提高影响判断的图层或部位。最终整体与必要近景核对文字、细线、alpha边缘和材质区别；近景清楚不证明总览可读，总览看不见也不能说明近景要求已满足。颜色、粗糙度和微表面可有不同采样需求，不统一强制高分辨率或全套通道。

依据：[SideFX Texel Density](https://www.sidefx.com/docs/houdini/nodes/sop/labs--texel_density-1.0.html)说明表面尺度与纹理采样的关系；[PBRT纹理采样](https://www.pbr-book.org/4ed/Textures_and_Materials/Texture_Sampling_and_Antialiasing)说明纹理频率受画面到表面映射与采样限制。具体节点先按当前版本发现，文档不证明现场已安装或最终外观通过。

## UV分区与拓扑变化

先确定哪些表面共用连续图案、哪些地方允许接缝，再决定UV在哪一步建立。材质区域、局部轴和尺度是维护源；面数、边号和节点先后本身不能决定映射正确性。

| 构造与编辑意图 | 合适的处理位置 | 受影响的检查 |
|---|---|---|
| 已有稳定板件/曲面，切割后保留原纹理 | 在源上建立vertex UV，再由Boolean等操作传递 | 旧表面的方向、密度、切口邻域的插值 |
| Boolean新增切面或内壁 | 利用实际输入来源/输出组识别新表面，继承合适的切割体UV或在之后补映射 | 切割体无UV时不能假定新面已正确覆盖；只在一组输入上加UV不等于完整交付 |
| 后生成的形体仍有明确表面区域与局部坐标 | Boolean后按这些区域做一致投影，避免依赖不稳定的面编号 | 同一UV岛内连续，区域边界与真实边/接缝一致 |
| 复杂形体、独有烘焙或曲面展开 | 按最终形体设置接缝并展开，再布局 | 拉伸、重叠、纹理密度、方向和所需边界留白 |

Boolean会插值point/vertex属性并复制primitive属性；它不负责决定材质区域。先做UV能保留已有参数化，但不是所有任务的固定顺序。新增倒角面也需检查插值与密度，不能因旧表面正常就跳过新面。

同一多边形内的UV顶点应服从同一个连续坐标映射。若按每个顶点的位置在`(x,y)`和`(y,x)`等不同投影轴间硬切换，面内插值会把不相容坐标连起来，产生斜拉/折叠；增加三角面或提高贴图分辨率不会修复这项定义错误。需要换方向时，用构造保留的板件/面组划分UV岛，让边界落在真实边或明确接缝上；一片连续材料开孔则保持其纹理连续。面朝向可辅助选择投影，不能代替所有材质身份，也不能在圆角上忽略投影切换的接缝。

排错先用固定比例、带方向的图案对照原表面与新增面；有疑点时在明确平面或局部三角面比较几何边长与UV变化，区分设计允许的拉伸与意外变形。更换映射位置和更换映射公式是两个独立变量；不把一次“移到Boolean前面变好”升级为全局顺序规定。

来源：[Boolean属性传递与拓扑](https://www.sidefx.com/docs/houdini/nodes/sop/boolean.html)、[UV Flatten](https://www.sidefx.com/docs/houdini/nodes/sop/uvflatten.html)。

## 图像角色与通道

底色是颜色；roughness、metalness、height、mask和normal是数据，不能烘入显示变换。已知颜色/数据校准分别读回，不仅依据后缀判断。
法线还需要编码范围和切线基底一致；源为高度时用明确幅度生成法线，不把RGB照片直接接法线。所选消费端不支持的细节先说明限制，不声称其他通道有颜色即代表法线正确。
透明贴花的颜色混合mask与几何opacity用途不同：前者给基底上色，后者使承载面透明。保留底层表面，检查白边、黑边和错误挖空。

## 预览与继续使用

用显式最终SOP调用render_view，观察贴图本身及所在部件；用户视窗另用viewport_screenshot，必要时临时textures=True并保留原视图状态。材质开关、UV、来源、Cd、高光及缓存分开排错，不默认重置用户全局视窗。
SOP预览验证内容、位置和大体响应；渲染要求另加载Solaris/Karma并核对其真实消费。同一输入不保证不同renderer像素相同。
修改外观控制、换图或改模型尺寸后，检查同一部位；保存网络与依赖后在隔离同版本进程重开，不能以原进程缓存证明交付。
