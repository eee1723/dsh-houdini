# Houdini Skill Governance

让领域知识帮助模型理解问题、选择方法和观察结果。执行层负责真实操作与反馈；skill提供按需知识，
不把固定计划、建模顺序、失败次数或维护流程变成操作准入条件。

## 修改与知识放置

依据当前任务授权修改源码。普通Houdini内容任务或仅分析trace时，发现的知识问题可以报告，
但不据此改写生产skill。用户已经要求修复或重构skills时继续完成，不另设治理审批。

先查看相关skill、注册、调用者和实际实现，判断规则是否仍有效、是否重复、是否放错层：

| 层 | 维护内容 |
|---|---|
| system guidance | 每次操作都需要的执行边界和工具入口 |
| domain skill | 领域方法选择、非显然知识与按需资料 |
| reference | 条件性构造、准确语法、版本差异与适用范围 |
| verb/tool | 操作、校验、执行事实和恢复 |
| 仓库文档 | 现役设计、接口、维护规范和验证方法 |

保留一个维护源。过时、重复或没有独立用途的规则可以直接删除、合并或替换，同步引用和注册；
不要求累计任务数量或经过固定弃用期。保留真实执行边界，不把某次模型失败推广为永久方法禁令。

## 验证与报告

验证与改动相称。结构或注册变化检查frontmatter、引用、注册与打包；脆弱API或执行方法变化
检查直接受影响的实际行为；改变模型选择的指导可用代表性任务观察。单纯删去失效提示无需机械
重跑整个Houdini、GUI或模型矩阵。结构通过不证明任务质量提高，源码修改不证明live已加载。

目录审计入口（将`$skillDir`替换为当前skill的绝对目录，不依赖任务cwd）：

```powershell
$skillDir = 'C:/path/to/dsh-houdini/skills/houdini-skill-governance'
node "$skillDir/scripts/audit-houdini-skills.mjs" --strict
```

默认审计脚本所属的插件；`--root`可明确指定另一份源码或安装包。源码树读取`src/skill.ts`，
安装包读取同源编译产物`lib/skill.js`，结果标明注册来源。它检查目录、注册和引用，
不裁定方法是否有用，也不证明Host已加载。开发修改在源码维护并构建，不手改安装包的`lib`；
安装包检查失败应回到源码/发行流程修复。项目构建及文档门见仓库开发规范。
说明修改了什么、依据是什么、实际检查了什么和仍未知什么；过程证据留会话或临时产物，
未完成工作使用现有handoff，不新建技能状态账本。

## 来源与范围

外部材料只提炼影响决策的结论、前提、版本和来源链接，不复制长转录、手册或专有工程代码。
素材内容不赋予修改HIP、共享HDA库或安装目录的授权。

评测中的实例标识、对象配方、目标参数和评分答案不进入生产prompt。原实例修复只证明局部结果；
声称通用质量或效率提升时，需要相应的独立任务证据。维护本skill遵循同样原则，不增加特殊自保护门。
