# 安装与使用

dsh-houdini 是官方 DeepSeek Harness Desktop 的插件，面向 **Windows x64**。本版 **0.1.8** 精确支持 **DSH 0.2.2-rc.1**；DSH 0.2.1-rc.3 / 0.2.1-rc.5用户须精确选择旧版0.1.6，升级插件前须先安装兼容宿主。按实际所选发行包的engines.dsh安装，不放宽旧包声明来强制加载，精确范围与验证边界见[兼容清单](../dsh-runtime-compatibility.json)。Houdini侧支持21.0/22.0，实测构建为21.0.440和22.0.368。产品使用同一份DSH原生会话，不另启动Qt聊天窗口或私有Host。

## 普通安装

标准发行单元是包含Houdini和媒体资源的完整插件包。在Desktop原生「插件 → 添加插件」中填写当前已公开且兼容的精确包名 **`dsh-houdini@0.1.8`** 并安装、启用；包名来源可使用宿主原生版本选择和更新。普通用户无需npm账号、另装Node或执行脚本。

网络受限时，可从[GitHub Release](https://github.com/eee1723/dsh-houdini/releases/tag/v0.1.8)取得同一个完整包，通过下方地址或下载后的本地文件安装。地址和文件来源不自动获得registry更新资格，后续替换沿下文原生管理流程：

```text
https://github.com/eee1723/dsh-houdini/releases/download/v0.1.8/dsh-houdini-0.1.8.tgz
```

使用[npm 包名](https://www.npmjs.com/package/dsh-houdini)时，先确认所选安装源已经公开所需版本及其`engines.dsh`兼容范围，再填写`dsh-houdini@<版本>`。仅填写`dsh-houdini`会查询该源的latest，不会自动寻找兼容当前宿主的版本。GitHub地址安装与npm包名安装分别保留各自的来源，安装同一份内容也不会自动转换来源。

刚发布时请填写精确版本，例如`dsh-houdini@0.1.8`。宿主包管理器的新版本年龄策略可能让裸包名实际选择较旧版本，即使预检卡片已经显示新版；以安装后的实际版本和兼容结果为准。精确版本选择及后续原生更新由宿主管理，不需要为此放宽旧包兼容范围或修改全局安装策略。

如果镜像缺少npm官方已公开的版本，可在对话框右侧「安装源」切换npm官方源`https://registry.npmjs.org/`。官方源尚未公开该版本时，换源不能解决；使用已公开的GitHub完整地址或下载同一个包后本地安装。具体未完成的渠道见[发行交接](handoff.md#h-01-标准插件发布与用户加载)。

GitHub发布页同时提供SHA256校验文件。仓库首页、历史独立工作台包和GitHub自动生成的Source code ZIP不适用于这条标准插件安装路径；源码push、tag或Draft本身不等于包已公开可用。

1. 安装受支持的官方 DSH Desktop，并确认其 DSH 宿主版本符合上方精确兼容范围。
2. 打开Desktop原生「插件 → 添加插件」，在「包名或地址」填写 **`dsh-houdini@0.1.8`** 并点击「安装」。网络受限时使用上述完整地址或同一个完整`.tgz`的本地绝对路径，无须解压后寻找`Install.cmd`。
3. 安装完成后启用插件。当前宿主的新装插件默认停用，可在安装结果中选择「立即启用」，或在插件列表启用 `dsh-houdini`；安装成功本身不表示 Houdini 模式已经加载。
4. 在 DSH 原生模型设置中完成供应商或账户配置，为当前对话选择可用主模型。插件复用这些设置。
5. 如果要换工作区，先选工作区，再在其中的新对话选择 Houdini 模式。在工程菜单选择 Houdini 安装，新建场景或打开已有 HIP；已经加载兼容组件的工程也可直接选择绑定。

插件启用或更新加载后，会在后台自动安装／更新本端组件，包括登记菜单所需的 Package、检查已确认的旧入口并取得安装回执；新建工程复用同一次准备。运行中的状态检查只读；发现组件缺失时，在工程菜单提供明确的修复入口，不因轮询重新安装用户刚移除的组件。准备失败不会继续新开一个未准备好的窗口。日后普通启动的 Houdini 通过该 Package 加载菜单，并在图形界面就绪后自动启动、登记 Bridge；原对话的工程菜单会自动发现新窗口，选中即可继续，不需要先用 Open Workspace 新建对话。

普通安装反馈只说明安装或更新结果，以及已打开的Houdini是否需要保存并重开；入口迁移、备份和保留项继续写入安装详情，不作为日常使用提示。真正阻止安装的冲突或失败仍显示实际原因。组件已安装不代表当前窗口已加载或工程已连接。

地址安装由官方宿主的插件管理器下载和验证。完整包包含媒体工具及对应源码，下载时需要等待；网络受限时可下载同一版本的完整包后本地安装。失败时保留实际错误，不使用历史独立工作台入口补装。已验证范围和剩余环境差异见[发行交接](handoff.md#h-01-标准插件发布与用户加载)。

已经打开且没有加载组件、或仍加载旧版组件的 Houdini，须先保存，再重新打开对应窗口；磁盘安装不能替换进程内已经加载的 Python 模块。组件准备不关闭其他 Houdini，不重启 Desktop。发现进程或 HIP 路径不证明该窗口已经连接。Desktop 未安装、版本不兼容或插件未启用时，菜单显示实际接入原因。

## 从旧版升级与菜单接入排查

升级前等待当前任务结束，在插件详情确认当前版本与代码来源，再按[连接与维护](#connection--support连接与维护)中的对应入口更新或替换。新版插件加载后自动准备组件；保存并重开需要更新的Houdini，再在原对话工程菜单选择新窗口。保留旧目录、会话和本端组件，不把清空目录或旧独立工作台的更新按钮作为前置步骤。

菜单提示「DSH Desktop 接入结果尚未确认」时，表示在等待时间内未能确认插件通道的结果，不证明场景操作已经失败或需要重发。先打开官方 Desktop，在「插件 → 添加插件」用完整包的本地绝对路径安装，并在安装结果选择「立即启用」；已有条目则核对其来源及启用状态。随后确认新对话能选择 Houdini 模式，等待自动组件准备完成并重开 Houdini；只有准备失败才在工程菜单重试。Houdini 菜单已经出现，只说明该窗口加载过菜单代码，不能代替 Desktop 插件已启用的检查。

早期开发可能只在 `web` profile 登记源码链接；官方 Desktop 的 `desktop` profile 是另一份插件安装配置。旧网页入口可用、源码构建成功或执行 `Install.cmd`，均不表示官方 Desktop 已安装插件。沿其原生管理入口安装，不复制 profile、改会话、搬密钥或手工给官方配置打补丁。两端准备完成后仍无法接入时，保留实际错误及其发生入口，再核对正在使用的 Desktop、插件启用情况和该 Houdini 的已加载版本，避免反复重发场景操作。

选择文件夹时若报 `workspace/create` 的 `active Service "workspaceController" is unavailable`，表示官方工作区服务尚未上线，路径访问检查还没有开始。应检查服务初始化原因，而不是反复换目录或提升管理员权限。旧私有 Host 曾允许会话头的创建目录与日志实际位置不一致；官方持久化读取会拒绝此类记录，进而阻断工作区服务。存量历史恢复须与插件安装分开：先明确异常记录、原始来源和对历史可见性的影响，再在 Desktop 正常退出后执行经用户确认、保留原值且可回滚的处理。安装器不自动改写会话头或搬动日志，不能通过清空历史或重新加入核心补丁来掩盖不一致。

## 旧版入口迁移与数据保留

首次新开 Houdini 或显式更新组件时，安装器检查目标目录中的旧入口。仅对能确认来自历史 dsh-houdini 安装器的 Package、启动桩、菜单和独立工作台快捷方式执行停用，保留原始字节备份和可恢复报告；复制、改名后的纯插件 Package 也在检查范围内。自定义 Shelf、混有其他代码的启动脚本和无法确认的快捷方式保持原样，安装详情提示需要核对的内容。同名 Package 若无法确认归属，准备会停止并给出具体报告，不要求用户盲删目录。

旧运行包、缓存、密钥、会话、附件和 HIP 都保留。入口迁移不合并两套历史，不改写会话头或搬动日志；已有旧记录的处置范围见[宿主与历史交接](handoff.md#h-06-官方dsh共存与插件边界)。不要通过清空旧 runtime、账户目录或历史来解决入口冲突。运行中的旧 Houdini 仍须保存后重开。

安装器只部署自身 helper 和 Package。helper 默认位于 `%LOCALAPPDATA%/DSH-Houdini`，不安装 DSH/Node，不修改官方 Desktop 安装、其他插件、profile、会话或账户。目标优先采用显式 `-PackagesDir` 和已有登记；没有已登记目标时，依次使用 `HOUDINI_PACKAGE_DIR`、`HOUDINI_USER_PREF_DIR` 或系统 Documents 中的 Houdini 21.0/22.0 偏好目录。`HOUDINI_PACKAGE_DIR` 可用分号列出多个绝对目录；已有自定义登记在升级时继续保留。

支持人员可在完整插件资源目录使用[安装器](../installer/install.ps1)的高级预览与恢复入口。预览不写文件；恢复只处理报告记载的入口，校验备份和安装后文件摘要，遇到用户后改的文件就停止并保留它：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File installer/install.ps1 -MigrationPreview
powershell -NoProfile -ExecutionPolicy Bypass -File installer/install.ps1 -RollbackMigration '报告绝对路径' -MigrationPreview
powershell -NoProfile -ExecutionPolicy Bypass -File installer/install.ps1 -RollbackMigration '报告绝对路径'
```

自定义组件根可追加 `-Root`。恢复迁移会重新启用报告中的原入口，应按明确的恢复目的使用；组件版本选择和已加载状态仍以本端版本信息及重开后的实际连接为准。

## 工作区使用

从 Desktop 选择 Houdini 模式，在对话目标控件中选择已登记工程；也可选已发现的 Houdini 安装，新建或打开现有 HIP。打开其他文件默认使用新进程，不隐式清空已有工程。启动成功、HIP 加载完成、Bridge 连接和任务绑定分别以实际回执确认。

已安装当前组件的普通 Houdini GUI 会自动登记；Desktop 中原对话可直接选择它。需要从 Houdini 导航到 Desktop 时，选择 DSH-Houdini → Open Workspace；菜单取得当前工程身份，再唤起同一 Desktop 并定位或创建 Houdini 对话。已有明确目标优先；发生歧义才选择。GUI 主线程不等待网络或进程探测。

未保存场景使用插件专属临时工作目录，不自动保存 HIP。已有对话切换目标保留其原生工作区与历史；Save As 只更新真实 HIP 事实，原项目内的文件目录可由原生 cd 跟随，跨项目文件权限仍沿 DSH 公开机制处理。工程输出锚定实际 $HIP 与明确目的地，不修改会话创建目录来扩大权限。

只有当前选中的 Houdini 对话显示领域交互控件。其他模式没有工程面板；历史执行卡片仍可读取，已经提交的后台执行不因切换界面而取消。多工程、节点修改权限与恢复合同见[工程选择](multi-instance.md)。

在官方Windows Desktop的Houdini模式中可点击「置顶」，便于一边对话一边操作Houdini；空对话显示在输入工具行，已有对话显示在页头。Houdini对话之间切换保留本次使用中的选择，切回其他模式恢复进入前的窗口层级。若无法准确识别本Desktop窗口，按钮会说明原因，不按窗口标题或当前前台窗口猜测。

## Connection & Support（连接与维护）

插件的安装、升级、启停、卸载与失败恢复统一从Desktop原生「插件」页进入。Houdini工程菜单只负责当前现场的选择、工程操作和连接／组件维护，不再提供重复的插件更新入口。组件准备失败重试、安装修复及保存后重开提示仍按当前窗口的实际状态显示。

Houdini 组件提示按当前窗口实际加载与安装情况显示：后台自动准备期间会说明进度，失败或缺失时提供重试或修复，完整失败原因可按需展开；「保存后重开此 Houdini」只在同一安装位置的新组件已经准备好时出现。连接正常但有组件更新时可以继续当前工作。不同安装位置、无法确认的旧组件和连接中断不承诺重开即可解决。

Desktop 的应用和账户更新由官方管理；Node侧插件沿官方插件管理更新。DSH 0.2.2-rc.1按实际安装来源提供不同入口：

| 当前代码来源 | 更新方式 |
|---|---|
| 从npm源按自身包名安装的第三方插件 | 在插件详情的版本区检查已公开版本，选择兼容版本并使用原生更新按钮；宿主管理版本选择、安装及失败恢复。 |
| GitHub完整tgz地址或本地包文件 | 不显示registry版本区和更新按钮，也不会自动改成npm来源。需要换包时使用官方CLI管理入口，或在原生插件页明确卸载该插件后安装指定完整包；保留会话与本端组件。 |

再次在「添加插件」填写已有插件的包名会提示「已安装」，这不是更新入口。填写新的tgz地址可能走另一条安装路径，不能把它当作具有原生更新恢复保证的替代方法。发布到npm也不会让已有URL或文件来源自动获得版本检查。使用旧DSH的用户按该宿主实际入口操作，不把旧版界面限制套用到0.2.2。

更新失败后，按原生管理器的恢复结果操作。如果恢复提示需要重启，正常退出并重新打开 Desktop，然后在原对话确认 Houdini 模式和工程可用。

由旧宿主切换到不兼容的新宿主时，先停用Houdini插件，升级Desktop后再按当前来源安装或更新匹配版本并启用；保留会话和本机组件。匹配包名版本尚未公开时，使用兼容的正式完整地址，或继续原来的宿主／插件组合。

需要通过官方CLI替换依赖或迁移为包名来源时，先核对目标版本已经在所选源公开且兼容当前宿主，再正常退出Desktop，按其自带CLI帮助使用下列参数模板；尖括号内容须替换为实际值：

```text
<Desktop安装目录>/resources/runtime/cli/bin/dsh.cmd plugin --profile desktop add dsh-houdini@<已公开且兼容的版本>
```

CLI由宿主原生管理器写入依赖，不自行编辑profile或依赖目录。完成后重新打开Desktop，在插件详情核对实际代码来源、版本和启用状态；Houdini按实际组件提示保存并重开。CLI接受包名参数不等于当前URL／文件来源迁移已经验收，具体缺口见[发行交接](handoff.md#h-01-标准插件发布与用户加载)。更新插件不需要执行下述「移除本机组件」，包名安装也不表示运行中的Houdini热更新。

Houdini 中手动选择 **DSH-Houdini → Connection & Support...** 才会打开「连接与维护」窗口，正常启动和打开工作区不弹出它。窗口默认提供打开 Desktop 工作区、重新连接和连接诊断；「更多维护选项」中才显示切换已安装组件版本、移除本机组件与当前加载位置。重复打开会复用同一窗口，不阻塞 Houdini 编辑。版本信息与维护只作用于本端 Bridge/helper，不下载 Desktop 插件更新。已加载版本以当次 Bridge 执行合同为准，不能只查看磁盘文件或包版本。

维护窗口的组件版本切换用于临时诊断，保存并重开对应 Houdini 后生效；下次 Desktop 加载插件或从插件新开工程时，仍按当前安装的插件版本准备组件。需要长期回退时，通过 Desktop 原生插件管理选择相应插件发行版，并核对其宿主兼容范围。

修复当前 Bridge 必须等待其执行队列空闲，不终止其他 Houdini、不重启 Desktop、不重放未确认代码。Package/菜单变更按提示重开对应 Houdini；本端更新不改变原 HIP 和节点内容。

Desktop无法连接时，可在此窗口选择「连接诊断…」，生成并查看本端接入报告，或打开已有诊断ZIP；保存位置由用户选择。完整会话报告仍在Desktop标题栏的「报告问题」中导出。两种报告的数据范围和分享方式见[故障报告](support-reports.md)。

## 教程视频与转录设置

普通用户只需先在DSH配好主聊天模型。第一次分析有讲解的教程时，在任意模式的「设置 → 教程视频」选择地址来源、实际接口协议和准确转录模型，确认并发与速率后直接保存，无须先发起一次模型对话。在 Houdini 对话中让 Agent 协助分析时，也可通过 `video_configure` 保存同一份设置；确定性配置不依赖 LLM。ASR与STT是同一语音转文字能力，不需要配两套，TTS也不是解析教程的前置要求。

已有DSH提供方可明确复用其API地址和凭据引用；独立官方、中转或本机服务则保存为教程用途端点，不需要添加一个假聊天模型。协议按实际文件接口选择，不按厂商或模型名称猜测。支持OpenAI兼容文件转录、千问音频Chat与DashScope同步音频；实时流与异步云任务需要专用适配器，不能仅换URL或模型ID。已有本机兼容服务可使用无密钥模式；本机地址不证明它的后端绝不联网。

密钥只在状态页的「安全录入或更换密钥」输入，通过DSH原生凭据接口保存；不要发进聊天、提问答案或脚本。Agent只看到是否已配置。新网络origin不会自动继承旧服务的key；聊天OAuth或订阅也不等于语音API授权。页面展示当前配置与缺项，实际识别能力以获授权的一个短片试转录为准。默认并发2、每秒1次，本机可先1；试段明确只提交1片，这些限制不能替代总费用/上传范围授权。

FFmpeg/ffprobe随完整插件包交付，普通用户不用安装到PATH。普通Python自动来自已选安装的静态信息或发现的Houdini安装；只解析教程不必先连接场景。缺少图片能力时由Agent引导使用DSH原生模型选择，不能把转录文本冒充完整画面分析。若用户需要部署本地推理模型，应在明确硬件和资源下载后使用独立环境，不把CUDA/推理依赖安装进Houdini Python，也不默启宿主的可选听写bundle。

正式插件媒体资源位于 runtime/video，包含FFmpeg/ffprobe、所需运行库、许可及媒体库对应源码；各版随包SOURCE-NOTICE说明附带归档和精确来源引用。构建使用现有受控媒体构建/暂存入口，不从用户系统 PATH 猜测另一套默认工具。源码开发可以显式指定经过验证的 FFmpeg/ffprobe；缺失资源时返回实际依赖原因，不宣称离线功能已就绪。方法与验证见[开发规范](development.md)及[媒体契约](../skills/houdini-video-tutorial/references/video-processing.md)。

## ChatGPT / Codex 订阅（可选）

当前选择社区插件 [dsh-codex-subscription](https://github.com/WSL043/dsh-codex-subscription)，固定版本 **3.1.8**。它由独立作者维护，不随Houdini发行包捆绑，可用于Houdini和其他模式；Houdini连接组件不管理其账户，也不读取或迁移其他订阅插件的授权。

在官方Desktop原生插件管理中添加 **dsh-codex-subscription@3.1.8**，按页面提示安装、启用或重开。随后打开「设置 → Codex 订阅」，由用户亲自完成ChatGPT授权，再从DSH原生模型菜单选择账户实际可用的模型。插件安装、账户连接和模型目录可见分别不代表一次真实推理已经成功；型号、额度和功能以账户及服务端返回为准。

该插件的联网搜索、生图、其他模型扩展和可选工具由它自己的设置控制；只开启实际需要的能力，不把生成图片当作真实Houdini工程验收。订阅OAuth不等于转录API授权。宿主兼容检查和安装由官方插件管理负责，不为它设置版本豁免、修改共享依赖或升级Desktop。未完成的实际账户验收见[交接](handoff.md#h-06-官方dsh共存与插件边界)。

## 网络与代理

当前官方Windows Desktop的Node Host依据启动时的显式代理环境工作；它没有继承Windows系统代理、PAC或WPAD的完整合同。浏览器或Desktop更新器能够联网，不证明模型请求、转录子进程也能使用同一代理。使用代理时，按官方DSH方式在启动前配置HTTP_PROXY/HTTPS_PROXY/NO_PROXY并正常重开Desktop；具体值由所用代理服务提供。PAC地址不能直接充当HTTPS_PROXY。

插件不会读取系统代理后暗中修改整个Host、其他模式或用户环境。系统代理自动接入作为宿主公共网络能力处理，限制与上游方案见[DSH适配](dsh-update-compatibility.md#网络与窗口等宿主能力)。

## 卸载与保留数据

需要完整卸载时，先在已安装 helper 的 Houdini 中打开 **DSH-Houdini → Connection & Support... → 更多维护选项**，选择「移除本机组件…」并确认，再到 Desktop 原生插件管理停用或卸载 `dsh-houdini`。本机组件解除登记后，当前窗口与 Bridge 继续运行，下次启动不再加载菜单；若继续从仍启用插件的 Desktop 新开 Houdini，组件会按正常流程重新准备。无需寻找卸载脚本或清空目录。

高级维护可使用完整插件或已安装 helper 中的 [installer/uninstall.ps1](../installer/uninstall.ps1)，提供只读预览和按报告恢复。卸载不结束正在运行的 Houdini，不删除 HIP、会话、附件、恢复材料或 helper 版本目录，不修改官方 Desktop 安装。保留的旧私有入口不会因卸载新插件而自动重新启用。
