# 工作台、现场选择与工程恢复

本页维护用户选择、当前现场、节点权限和保存点恢复的职责。安装与进程生命周期见[安装合同](setup.md)，代码地图见[架构](architecture.md)，未验证范围只在[交接](handoff.md)维护。

## 独立工作台

同一运行根使用一个独立Qt工作台和一个DSH Host。多个Houdini分别运行Bridge并自行登记，工作台不属于其中任何一个Houdini窗口。关闭Houdini不关闭工作台；退出工作台不结束Houdini。退出前复用DSH原生活动事实核对任务及会话落盘，有活动任务或无法确认时说明原因。

DSH管理对话、模型、原生工作区、文件权限和通用Agent循环。插件不创建第二份任务数据库、不根据聊天语义认领工程，也不复制账户数据。窗口仍使用已安装Houdini的普通Python与Qt，不导入hou。

### 打开与定位

从某个Houdini点击Open Workspace，就是用户明确选择这个窗口当前加载的现场。入口发布主线程捕获的现场快照、唤起工作台并通过DSH原生API创建对话；不串行读取整个目录的聊天历史，不按最近任务、路径相似度或scene ID猜原对话，不为了打开界面恢复节点权限。

重复的同一次请求使用原request ID，不能重复创建对话。正在运行时重复打开只唤起已有当前任务，不改变在途操作目标。用户希望继续旧对话时从DSH侧栏选择，再通过工程组件明确选择当前现场；指定session ID只定位该段对话，不查找替代对话。

已打开但尚未与对话绑定的Houdini仍可出现在候选列表中。工作区相同只影响候选排列，不构成工程身份或修改授权。未保存场景有独立临时目录和明确名称，不要求先保存才能聊天。

### 当前对话与工程组件

当前对话使用一个紧凑工程组件，放在现有页头工具区；空白对话复用输入工具行，不并排保留两份。组件展示当前工程短名、状态文字和图标，完整路径按需查看。用户可以选择已登记的现场、取消绑定，或使用已有打开/新建工程动作，不增加诊断式常驻面板。

| 状态 | 依据与含义 |
|---|---|
| 未绑定 | 当前对话没有选定现场，普通讨论和历史读取可用 |
| 已绑定待命 | 选定目标的进程、Bridge与场景代际可确认，当前对话没有在执行 |
| 当前对话工作中 | DSH原生活动状态或属于本对话的Bridge请求/job表明正在工作 |
| 其他对话占用 | 同一现场的另一作者正在执行；闲置的旧预留不冒充工作中 |
| 已断开 | 原进程已退出或登记端已断开，不自动换成另一个窗口 |
| 工程已变化／待确认 | 当前窗口换了场景、合同不匹配或观察已过期，需要重新选择或等待可靠事实 |

固定操作位于候选区之前，异步候选区保持稳定高度；加载和迟到回执不移动打开/新建的点击位置、不重开已关闭菜单。

状态来自同一会话投影、DSH原生活动状态和共享非HOM在线观察。登记本身不证明在线；隐藏页面、断网、重连及过期观察撤销就绪颜色。颜色不单独表达状态。在线不等于已取得写入资格，更不等于拥有所有节点。

### 选择规则

1. 用户明确选择最高优先；每段对话分别保存当前目标，没有工作区全局可变的“当前Houdini”。
2. 已有选择保持，原目标失效不自动用另一个唯一窗口替代。取消绑定也是明确选择，下一次工具调用不能悄悄重绑。
3. 从未选过目标的新对话，首次需要现场时可使用同工作区唯一可用候选；多个候选使用DSH原生提问。普通聊天和查看历史不弹工程选择。
4. 选择快照包含执行端、运行代际、场景加载代际、实际HIP位置等。选择后窗口切文件，旧准备请求必须失效；同路径重新加载也不是旧场景。
5. 选择允许更换已经执行过操作的对话目标。历史结果保留原身份，不能因切换默认目标而改写历史或认领节点。
6. 正在运行的模型步骤、请求或job不得在中途改目标。用户在空闲时切换；旧进程已经退出的未知结果保留未知，不永久锁住对话，也不重发旧代码。

### 文件与目录

磁盘HIP列表和已打开现场是两类候选：前者可打开，后者可接受现场请求。发现运行窗口使用Bridge登记，不扫描端口、窗口焦点或全盘文件。目录中的备份、递增文件名和修改时间只作选择线索，不证明哪个更适合当前任务。

工作区是DSH文件工具的范围与对话组织；当前目标是Houdini执行位置。选择或取消现场本身不搬会话、不更改cwd、不load/clear HIP，也不移动工程依赖。工程输出继续锚定实际$HIP及明确目的地。

成功Save As继续当前现场并观察实际新路径；只有本对话的成功scene_save_as动词回执授权后续步骤沿DSH原生接口跟随目录，保留session ID和全部历史。读取其他对话保存过的现场不迁目录。原生GUI另存更新工程位置，工作区使用DSH现有目录入口明确选择，避免多对话时猜测迁移对象。该目录功能与选择、只读查看及节点恢复独立，失败应说明实际文件范围，不能回退为历史自动匹配。

### 从工作台打开工程

工程菜单提供打开关联文件、选择其他HIP和新建。默认新进程打开，不清空其他现场；已存在唯一、响应且版本符合选择的窗口时复用。相同文件打开多份时让用户选，超时不能被当作原窗口已死而再开一份。

用户从当前对话明确指定打开结果后，按同一选择协议关联该现场，不扫描目录历史。启动期间对话开始运行、被归档或用户另选目标，迟到启动结果不能覆盖较新的选择。后台打开不强杀Houdini，也不抢回用户正在看的对话。

### 身份与故障边界

| 事实 | 唯一职责 |
|---|---|
| DSH会话与原生选择事件 | 用户意图、当前默认目标、历史执行事实 |
| Bridge登记 | 当前可发现的窗口、进程、版本和现场位置 |
| executor/runtime/scene epoch | 请求具体发给哪个运行实例、哪次加载；与文件名不同 |
| 作者预留 | 修改期间只允许一个活跃作者，不限制其他对话只读查看 |
| ownership | 节点的创建归属和单次明确授权，不由连接选择改写 |
| checkpoint | 实际保存文件与可验证的节点恢复材料，不是聊天或目标数据库 |

所有HOM仍经Bridge主线程队列。目标选择与在线观察不执行模型代码。每个实际请求固定运行身份与场景代际，队列入场再次核对；旧Host、晚到请求和已切换场景不能借同一端口继续操作。

只读查询不领取作者预留、不恢复节点权限。修改前核对当前作者和活动请求，禁止在模型两次工具调用间抢占正在运行的另一对话；节点仍按创建session与单次明确foreign范围检查。Raw Gate和持久render服务边界保持。

## 单实例保存点恢复

连接现场和恢复原节点修改资格分开。选择任何明确现场不要求它先证明是旧工程；没有可信恢复材料时仍可连接、查看和讨论，具体修改按ownership规则判断。

原session重开已保存工程后，可用可信保存点映射原节点。恢复必须核对实际HIP字节、加载基线、唯一节点标记、创建来源和原运行生命周期。节点路径、复制标签、scene ID或用户说“已恢复”均不能代替这些事实。恢复不授予别的对话节点，也不自动接管整场景。

恢复材料由成功保存产生，HIP内保存scene/checkpoint和节点定位标记，本机材料在安装根recovery/checkpoints，源码默认在本机应用数据目录。HIP保存成功但恢复材料提交失败时如实报告；未保存修改不在恢复保证中。只复制HIP到其他机器不携带完整恢复材料。

原生保存钩子与动词保存共用入口，GUI线程不等待大文件哈希。私有forwarder通知插件后继续下一条原生保存脚本，不自动执行所有被遮蔽的第三方脚本，缺少原生成功证据时不伪造恢复点。

需要加载或丢弃未保存内容时必须有明确用户动作；普通聊天、初次连接、只读工具和自动选候选均不触发load/clear。旧工程材料不足、锁定HDA内部重建或节点缺失时保留实际不可恢复范围，用户明确指定的旧节点按单次授权规则操作。

## 工程接续设计

对话保留原始需求和历史，当前选中的现场提供现在的事实。更换目标不自动清空聊天、不复刻旧任务、不重放未知操作。用户可要求在当前工程继续、新建范围复刻，或打开原文件；内容选择由正常对话处理，不建立语义匹配评分或独立分支系统。

### 未完成请求与真实进度

原请求、job、图像和历史回执保留各自的执行端与运行身份。查回从本对话原始回执定位原运行实例，不使用当前默认现场；原目标不可用就报告未知。相同短job ID出现在不同运行实例时不能猜测。

回复丢失不证明操作未执行，HTTP超时不取消HOM，也不授权重放。保存点回退只改变当前HIP，不证明外部缓存、图片、HDA库或文件副作用消失。晚到旧回执可保存为历史，但不能覆盖新的目标选择或当前工程标识。
