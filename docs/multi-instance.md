# 多实例与任务恢复

本页是工作区、工程接续与多Houdini执行端的唯一长期设计/运维说明；代码地图见[架构](architecture.md)，活动缺口只在
[交接](handoff.md)维护。默认启动、发行资格与数据迁移仍遵循[安装合同](setup.md)和[兼容门](dsh-update-compatibility.md)。

## 独立工作台

源码的 Open Workspace 入口启动或唤起独立的 Windows Qt 工作台。同一运行根只持有一个 DSH Host，多个 Houdini 各自保留 Bridge、进程身份与主线程队列。窗口没有 Houdini 父窗口，Host 的 Windows Job 由工作台持有；退出或崩溃一个 Houdini 不关闭工作台，退出工作台不结束 Houdini。关闭前复用DSH原生活动事实核对后台任务并确认会话落盘；有未完成工作或无法确认状态时先询问，不静默隐藏到后台。

工作台复用现有 DSH 网页、账号、会话、文件工作区和 preset，不复制任务数据库。桌面壳使用已安装 Houdini 的普通 Python 与 Qt，不导入 hou、不启动 hython，也不等于已随发行包自带独立 Qt 运行时。受管激活仍校验签名、冻结依赖和版本隔离数据；正式包、安装器与用户实际加载须单独验收，源码通过不等于已经发布。

现有对话顶部工具区提供小图钉按钮，不另占一行，默认关闭；点击后全局置顶，再次点击取消。置顶状态取自Windows实际窗口，由认证桌面接口在GUI线程改变层级，不隐藏/重建窗口、重载网页或切换对话；重开工作台默认恢复为不置顶。最小化和关闭仍使用原生窗口按钮。

### 打开与定位

1. 在任一 Houdini 选择 Open Workspace，主线程采集当前工程与场景身份，worker 登记该执行端并请求同一个工作台。
2. 工作台通过 DSH 认证 RPC 创建或定位对应会话。同目录的两份 HIP 不因目录相同而共用任务绑定；浏览器只消费返回的精确会话 ID，切换界面不改变其他任务的路由。
3. 从现有工作区另建的未绑定对话，只有首次调用现场工具时才使用 DSH 原生工程选择；普通聊天不被选工程打断。不新增常驻连接条、技术登记面板或“检查连接”按钮，查看历史不重开 Houdini。
4. 初始绑定检查登记版本、现场 HIP 与场景代际，成功后通过 DSH 原生不唤醒上下文队列记录并 flush，不在首个系统消息之前插入会话正文。绑定投影读取同一队列事实，随后消费该消息不会重复绑定或覆盖已完成的恢复；现场派发前仍检查持久化。登记不是在线证明，也不是节点修改权。
   尚未记录任何现场调用的对话，可在用户从对应工程明确打开工作台时重新选择初始执行端，保留原对话而不要求虚构的保存点；新旧选择都进入同一原生日志。这不恢复节点归属，已有现场调用或未知PTC执行则仍须走保存点接续。
5. 写入预留只经明确选择或接续认领取得（初始绑定或恢复选窗）；核对与路由本身从不认领、偷占或按空闲自动接管。同工程切换作者对话能否替换预留由 Host 对话状态与 Bridge 共同判定：另一段对话仍在运行（模型或工具步骤中），或登记有活动请求/job 时明确拒绝；只有双方都空闲才接受显式认领的接管。节点仍属于创建它的原 session，不共享作者身份，不因切换对话获得 foreign 修改权。

对话的场景关联统一由绑定投影维护：明确打开、已验证恢复及原生/嵌套现场回执消费同一份`scene_id`，路径是定位信息，`executor_id`是当前连接。`scene_id`随HIP文件userData可复制，因此恢复候选与工程关联同时绑定已记录的`hip_path`（同规范化比较），不按`scene_id`单独认领；观察未带`scene_id`只在HIP路径未变化时沿用原值，路径变化后没有观察到身份即为待核对，不从前一份文件继承。Host能力查询不算现场操作。普通路由、工程标识与恢复候选读取此投影，不分别从打开消息和最近回执重建工程身份。
同路径不作为恢复候选依据；多个已通过保存点核对的窗口由原生对话选择，选择后重新验证并显式认领写入预留。一个工程关联多段对话、又没有当前作者时，用户先从原生侧栏选择对话并打开关联工程，不按历史顺序或操作数量猜测；未执行对话的初始换绑只在消息载荷明确给出该对话时进行，隐含匹配不改绑其他对话。显式打开的目标在后续接续中保持，不再自动选择另一个窗口。选择不豁免文件、场景或节点归属检查。

### 对话标题与工程标识

对话标题描述用户正在做什么，工程标识描述操作对象，两者独立维护。打开工程不调用DSH的用户重命名入口，标题继续使用DSH原生自动生成；用户手动改名仍保持。旧版本写入的文件名标题与真实用户改名不能可靠区分，不批量猜测修改；需要恢复自动标题时，使用该对话菜单的「按对话内容重新命名」。该动作复用原生标题服务，不启动模型工作轮次或访问Houdini现场。

侧栏复用原生对话行的14px关联标记和悬浮详情；运行、待回答等原生状态仍优先占用原有状态位，归档/空白行遵循DSH本身的展示规则。当前对话的页头用同一份投影显示一个有宽度上限的工程短名，悬浮、键盘聚焦或点击查看完整路径。尚未发消息时复用输入框原有工具行，开始对话后只保留页头一处。未绑定对话不显示标记，不增加提示条、连接按钮或第二套工作区列表。

显示值来自原生历史中的明确工程选择、已确认目录跟随、接续记录和原生/嵌套执行回执，由绑定投影统一输出。消费旧排队消息或晚到回执不能覆盖较新的工程。保存文件名恰好为`untitled.hip`也不推断为未保存；新场景使用DSH原生工作区标题分配「未保存工程 1、2…」，不另建场景命名数据库。查看标识不激活其他任务、不轮询HOM。

### 从工作台打开工程

源码根目录的`Open Workspace.cmd`可先打开工作台，不要求已有Houdini进程。受管安装器在安装根生成`DSH-Houdini.lnk`，仍使用已安装Houdini的普通Python/Qt和既有签名运行包，不下载另一套Qt或复制账户数据。

当前工程标识的菜单提供「打开关联工程」「打开 Houdini 工程」「新建 Houdini 工程」；无关联工程时，只在侧栏现有底部动作位提供一个小型工程入口。文件与版本选择使用按需原生对话框，不增加常驻状态面板。打开和新建默认使用新的Houdini进程，不清空、加载覆盖或结束其他工程；同一路径已有唯一响应且版本符合选择的登记端时复用它，不用文件名猜目标，也不忽略用户所选版本。新建保持未保存状态，不提前写HIP。

未绑定的当前对话可在空闲时直接接入所选工程，保留原ID、标题与聊天历史，并沿同一DSH目录迁移接口跟随工程工作区；不为了绑定开启模型轮次。已有绑定的对话不会被「新建/打开」改绑，启动期间原对话被归档、开始运行或改选其他目标也不覆盖其状态。独立冷启动先准备用户数据目录中的工作区，不让文件工具默认获得插件源码或发行目录作为任务目录。

桌面枚举安装目录并读取可执行文件版本，参数使用数组传递，不经过shell拼接。私有Houdini路径只贡献[官方uiready扩展](https://www.sidefx.com/docs/houdini/hom/locations)，保留原有路径与启动脚本；捕获实际现场后，worker提交启动ID、进程创建身份、执行端、登记代际和实际HIP，Host仍走原生会话绑定。原对话重开须继续通过保存点与归属恢复，不因进程启动成功就宣布已接续。临时启动回执不是任务数据库；重复启动、过期工作台和错误文件不能通过回执换绑。

启动前取消不创建进程；启动后「后台打开」不强杀Houdini，也不在完成时抢走当前对话。退出工作台不结束这些Houdini。启动缓慢或等待许可有明确说明，不能据超时猜测崩溃。浏览历史或选择对话本身不启动Houdini，不自动挑选崩溃文件或重放未知操作。

### 在线颜色与另存反馈

离开临时目录或另存迁移后，空的临时工作区登记可自动从侧栏退出。范围仅限插件专用临时目录中的原始临时名称：当前打开目标、已登记现场、任何会话（包括归档及可能带草稿的空白会话）、使用自定义名称的工作区以及含文件的目录均保留。使用DSH原生`deleteEmpty`在同一写入队列再次核对原始会话账户、目录和标题；缺少该能力的旧运行时保留条目，不降级为检查后直接删除。原生保存后的现场登记在保存返回GUI事件循环后采集，避免把保存回调中的旧路径发布为新位置。清理只移除工作区登记，磁盘目录、文件和会话历史始终保留。既有空条目在后续打开或迁移时按同一规则处理，无周期扫描或额外清理面板。

同一小型旋涡标识承载在线颜色，并在悬浮/无障碍文字中给出状态：绿色要求对应执行端进程仍存活、Bridge 响应、执行合同版本匹配且场景代际一致；灰色表示登记已断开或进程已退出；橙色表示未确认、合同版本不匹配或场景已切换。写入预留是否属于当前对话由执行时的租约校验决定，不并入这个在线颜色；忙碌但仍响应的端点保持在线并注明正在操作，不把 HOM 排队当成离线。

工作台页面可见时共用约 5 秒一次的非 HOM 观察；每次重新探测，不缓存短期结果。窗口隐藏、重连、请求失败和超过 12 秒的过期观察不能保留绿色。健康接口只读取 actor 已发布的场景代际，不执行现场脚本、不占用主线程队列，也不授予修改权。

当前对话的目录在已确认工程另存后变化时，沿DSH原生轻提示说明新位置与历史保留；切换对话、首次进入、失败保存和仅更名不产生迁移提示。提示自行消失，不形成常驻横条。图标源图、生成说明及多尺寸ICO位于`assets/`，桌面窗口和安装快捷方式共用同一个图标。

只有工作台持有安装级运行锁；第二个 Houdini 接入既有工作台，不再次激活或复制 DSH 数据。活动版本不同会拒绝混用，不热替换其他工程的运行包。旧内嵌 Host 仍在运行时不得并开同一数据目录的新 Host；保存工作并正常退出旧环境后迁移，不能删锁或按端口杀进程。

### 身份与故障边界

| 事实 | 职责 |
|---|---|
| DSH 会话与原生绑定事件 | 唯一持久任务历史，工具按自己的任务解析目标 |
| scene/checkpoint | 工程与可信保存点；目录、文件名不能代替这些身份 |
| executor/runtime | 当前 Houdini 进程与 Bridge 代际，重开进程不沿用旧身份 |
| registration | 当前发现快照，选择时防过期；不证明进程在线 |
| OS 租约 | 工作台单例、进程生命周期与参与协议的 HIP 写入互斥 |

工作台控制接口只监听 loopback，使用每次启动的随机认证值与代际；先核对进程创建身份，再联络已有工作台。失联但进程未确认结束时不重复启动、不结束外部程序。发现登记和界面选择不能覆盖任务绑定，回执、图片和 job 控制均沿调用级目标路由。

工程观察使用主线程捕获的同源快照和内存有效性标记；worker在登记锁内复核，过期的保存/切换观察不能回写覆盖较新的选择。忙碌工程的重复打开只唤起其原对话，不重新登记或抢占作者。

源码开发的工作台记录位于 DSH_HOME/houdini-workbench；受管运行位于安装根的 workbench。desktop.json 是可失效的本机进程发现记录，含本机启动凭证，不是会话数据库，不能对外分享。诊断包只收集既有允许的日志，不扫描或打包该凭证。

### 保存、修复与恢复

不同 Houdini 通过规范路径与文件身份保护参与协议的写入；默认空白工程按进程分别登记，不强制用户先保存才能聊天。显式 Save As 在写入前取得新目标预留，成功后发布新路径，随后释放旧目标；失败不假装文件副作用已回滚。同进程的节点归属不因此改变。原生 GUI 保存属于已发生的用户操作，后续登记只能观察冲突，不能承诺拦截所有 GUI 或外部写入。

每个 Houdini 的 Bridge 仍独立修复；不能为了修复一个端点而重启整个 Host。活动请求/job 阻止任务作者切换和 Bridge 重载。窗口、Host、Houdini 现场各有独立生命周期；心跳或 HTTP 超时不能证明崩溃，也不授权重放修改。

普通工具只解析已绑定的原执行端。用户新一轮输入或明确打开关联工程需要接续时，查找已登记工程并用原保存点、原进程退出证明和节点身份验证候选；唯一满足条件时复用现有 prepare/flush/activate 流程。没有可信材料、多个候选或原作者仍存活时不换绑。无用户动作的Houdini自动启动、崩溃文件自动挑选、任意文件移动定位和未知操作重放不在此阶段范围。

显式 shared-host.cordis.yml 仍可用于隔离开发组合；未设置 DSH_HOUDINI_WORKBENCH 时保留手动登记/选择行为，不将该开发入口冒充默认工作台体验。

## 单实例保存点恢复

以下保存点协议由固定目标与工作台任务共同复用，名称保留以便既有文档定位。工作台不另建恢复账本，也不降低身份与归属校验。

普通聊天区不显示常驻连接状态条或「检查连接」按钮；正常连接、未开始对话等内部状态不占用输入区，也不因选中对话或窗口获焦额外查询Houdini现场。操作受阻时沿原生对话说明原因与下一步，技术细节按需查看。接续仍须匹配持久任务身份和原工程身份，单个HTTP成功不能证明已接续。

模型与工具失败读取同一份原生接续诊断。工具阶段的身份拦截保留先前核对失败原因；模型后续步骤不能把具体原因覆盖成通用绑定错误，也不能在没有新核对时清除失败。新用户输入核对成功后清除旧提示，同一失败再次发生仍重新记录。该说明不改变Raw Gate、节点归属或Bridge的场景代际边界。

普通用户在原对话发送消息时，系统在DSH允许本步骤进入后自动核对工程接续；不增加检查、恢复或修复按钮。
可信保存点和目标明确时自动执行prepare、追加DSH原生绑定事件、flush、activate，再进入模型步骤；旧进程身份和执行历史保持。
打开页面本身不重开工程或启动Goal，同一轮的模型/工具后续步骤也不重复恢复或提问。被DSH拒绝的步骤不产生恢复副作用。
落盘或激活响应丢失后，下一次用户消息可接续同一操作；工具阶段只核对并幂等激活已记录的绑定，不追加迁移事件。
恢复条件不满足时，系统把实际工程与缺少的证据交给对话，保留普通讨论和历史读取；不能让用户点击修复、口头确认“已恢复”或提供截图代替执行回执。

恢复材料是ownership在成功保存边界产生的快照，不是任务数据库。HIP内保存scene/checkpoint标识及每次保存的节点定位标记；
材料保存在安装根`recovery/checkpoints/`，源码默认使用`%LOCALAPPDATA%/DSH-Houdini/recovery/`，测试使用独立`DSH_HOUDINI_RECOVERY_ROOT`。
worker按保存时文件身份核对字节并提交记录；原进程持有OS生命周期锁，进程退出才释放，失联不能被当成退出。
这些本机材料不在DSH任务目录内；仅复制HIP到其他机器不携带修改归属，尚无可移植恢复包或另一个资产管理系统。

动词保存和随安装提供的`afterscenesave.py`共用成功入口；后者不为普通保存加载插件。独立工作台在本次私有启动目录安装薄转发脚本，调用同一保存通知源，再按findFiles顺序执行下一条脚本；多个私有转发脚本继续向下传递，插件通知按解析路径去重。Houdini原生只执行首个匹配，后续第三方脚本是否继续串联由其自身决定，不自动运行被遮蔽的脚本。各调用使用独立的原生kwargs副本；插件通知失败仍尝试原生脚本并报告失败。不依赖父进程已安装package，不改写用户脚本。
H21的原始Windows反斜线路径可能使厂商保存回调/脚本的kwargs构造失败；缺少成功证据时不提交材料，动词保存使用实际返回结果。
旧bootstrap尚未安装该脚本、其他安装遮蔽脚本或保存后立即崩溃时，不能声称原生保存已有可用恢复点。
恢复点未提交、文件字节改变或来源不符时不自动认领；材料丢失不等于节点可以认领。部分节点缺失只影响这些节点，仍恢复有精确依据的存活节点并报告未恢复项。
保存点只记录可以持久保存的身份；锁定HDA中不可编辑的原生定义成员由Houdini重新实例化，不把其独立身份未验证说成用户模型丢失。
加载后worker核对原保存点。后续保存保留已验证但尚未激活的其他任务创建记录，不因此授予修改权；原作者与保存进程的来源分别保存。
保存时只为精确存活的记录刷新标记，复制品保留旧标记并保持foreign。保存先于后台核验完成时如实报告材料不可用，不能在GUI线程等待或补猜原归属。

可信映射同时要求实际加载的保存文件、加载时的原生节点身份、唯一节点标记及原session的创建记录；加载后同路径重建不认领。
插件若在HIP加载后才启动，首次初始化读取HIP中的工程身份，但不补猜加载基线、不登记节点归属；同进程重载模块不重新采纳后来改写的身份标记。同一可信保存点且GUI明确没有未保存修改时，可在本次接续中自动重开当前文件。
必须重开而存在未保存内容时，仅通过DSH原生对话询问“保留当前修改继续讨论”或“放弃未保存修改从保存点继续”。保留、自由文本、跳过和取消都不授权丢弃。
真实问答留在原会话，选择后重新核对工程、保存点和场景代际；旧答案不适用于切换后的工程。接口只重开当前已核对的路径，不提供任意路径load/clear。
全部HOM仍在Bridge队列，哈希和文件提交在worker；没有可靠dirty观察时不会自行丢弃内容。
Open/New会更新场景代际；已准备的旧请求在实际入场前失效，同进程换工程也不能继续使用旧任务目标。

原生/嵌套历史回执保持原身份，晚到旧回执不改变当前绑定。恢复事件保留此前未决事实，当前上下文停止轮询旧请求/job；
这不证明它们没执行，也不重放代码。恢复后的第一轮需核对实际保存内容及外部输出；聊天中的未保存成功记录不能冒充已恢复。

当前范围是可信保存点下的普通节点归属与连接恢复；Raw Gate、foreign单次豁免和持久render服务边界不变。
当前工程不匹配时，Host使用原对话中的工程身份和执行端来源自动查询既有保存点材料。worker只核对有记录的末端保存点及文件字节，不扫描工程目录或全盘，不用文件名/修改时间猜工程。已被后续保存替代的祖先不被静默选为当前版本；不同保存分支保留为明确候选。文件缺失、被替换或原作者仍在运行时报告原因，不提供虚假的可接续选项。

找到原工程后，DSH原生对话同时给出当前HIP与候选保存点。用户可保留当前工程继续讨论，或明确选择打开某个保存点；有未保存修改时，打开选项明确包含放弃这些修改。回答先落入DSH历史，再由固定恢复入口核对当前场景代际、路径、保存点和脏状态，重新校验原文件并在主线程加载。加载本身不授予ownership，之后仍走prepare/flush/activate；普通文本、路径参数或模型自报成功均不能代替该选择。对话中途切换工程、文件被替换、记录落盘失败均不按旧选择打开文件。

只有GUI确认当前为未命名、无未保存修改、各根网络均无内容的新场景，且只有一个可信可用候选时，普通“继续”直接接续原工程。入场时再核对空场景条件，期间新增内容则拒绝自动切换；已命名的空工程和无法可靠判断脏状态的场景仍需选择。提问将文件路径放在各自选项说明中，不重复列候选编号；“没有未保存修改”不能描述成“已保存”。

受控加载区分`hou.LoadWarning`和真正的加载失败：警告后仍核对实际工程/保存点身份、文件字节与可恢复节点，再决定能否接续。警告进入同一恢复回执和模型上下文，不能由连接恢复推断跨版本几何、参数或依赖兼容。`hou.OperationFailed`、错误工程或文件变化继续拒绝，不自动重放操作。

加载警告的整批首尾预览遵循[结果预算](../houdini/result-detail-policy.json)：默认不超过4096字节的保守JSON/模板转义预算，带原文字符数、省略量和截断标识，不按语言或关键字猜严重程度。完整原文由HTTP worker按既有结果JSON格式保存在恢复根`load-warnings/<sha256>.json`；同内容只存一份，后续现场回执和激活响应只带引用，不再附预览或全文。默认归档上限与Host结果读取共用32MiB，超过预算、存储失败或已有文件损坏时记录unavailable及有限错误，继续保留有界预览；原文不可用不等于没有重要警告，也不将已成功加载改报为加载失败。旧会话原文不回写。

`houdini_resource(kind='result', ref=load_warning_details.sha256, pointer='/result/load_warnings')`复用分页读取，无需Houdini在线。Host只从有效的原生恢复记录取得归档路径并校验hash，不接收模型任意路径；跨目录另存或后续恢复后仍能读取历史引用。分页使用返回的`next_offset`，不是原始警告字符数。没有新工具或警告数据库，诊断文件不写入用户工程的analysis目录。

独立分支入口、旧文件接管、无记录的文件移动/重命名和全部HDA/组件/UI归属恢复仍按完整目标另行交付；跨目录原会话迁移见下文另存规则。
同目录不同文件不会因目录相同获得恢复资格；普通Save As不改变进程内任务连接，跨目录通用文件工具仍受原DSH工作区约束。
升级必须保留同一DSH任务历史和恢复材料并通过当前执行合同握手；不同Houdini版本的复杂资产兼容性不由本恢复机制保证。

验证入口：[跨进程HOM与反例](../tools/tests/dsh-scene-recovery.test.py)、[DSH/浏览器/实际Houdini](../tools/tests/dsh-scene-recovery-e2e.test.py)、
[持久化/晚回包/对话选择反例](../tools/tests/scene-recovery.test.mjs)、[用户输入与步骤拒绝](../tools/tests/executor-binding.test.mjs)。
真实组合测试让浏览器在原任务只发送“继续”，不调用恢复RPC；`--gui`覆盖先开HIP后加载插件，`--dirty-choice keep|discard`覆盖实际对话选择及未保存参数保留/丢弃。
参数见测试帮助，均使用独立偏好、账户数据和自有进程，不替代已加载发行版验证。

## 工程接续设计

本节是完整产品目标；超出上述单实例范围的内容尚未实现，活动缺口见[交接](handoff.md)。
目标是同一任务能跨崩溃重开、HIP递增版本、另存及受支持的软件升级继续工作，并在打开不相关工程时给出可执行的选择。

### 工作区、工程与运行身份

工作区继续复用DSH的目录、文件权限和会话组织；同目录可以容纳完全不同的HIP，也可以容纳同工程的多个版本。
不把目录相同升级成工程相同，不为每个HIP复制一套账号/会话，也不另建插件工作区数据库。
工程身份表达内容的延续关系；保存点表达这一次实际落盘的状态；运行身份只定位当前进程。

| 对象 | 最小事实 | 生命周期与用途 |
|---|---|---|
| DSH工作区 | 原生workspace ID、目录、文件访问范围 | 组织会话与文件；不是工程身份 |
| DSH任务 | 原生session ID及其事件历史 | 保留用户意图、执行回执及接续选择；不是运行进程 |
| 工程分支 | scene ID、branch ID、可选来源分支/保存点 | 新建或无关工程产生新scene ID；显式独立分支产生新branch ID |
| 已提交保存点 | checkpoint ID、父保存点、真实HIP位置/文件摘要、保存时环境、归属清单引用 | 同一路径覆盖也产生新保存点；路径/摘要单独都不证明工程归属 |
| 当前绑定 | session、scene、branch、checkpoint、binding epoch、executor、runtime、scene epoch | 任务本次连接；接续成功递增binding epoch，保留旧绑定历史 |
| 节点恢复记录 | checkpoint范围内的持久node ID、创建session/调用、对应节点及必要校验事实 | 将已确认保存的归属恢复到新HOM identity；不是复制标签即授权 |

scene epoch是同一进程内加载/清空工程的代际；即使executor没有变化，打开另一HIP也必须使旧队列目标失效。
文件改名、复制、符号链接、硬链接和相同字节都不能自行决定继续还是独立分支；复制HIP会复制其中的身份，多个候选存在时要明确选择。
版本号字符串和文件修改时间只帮助展示/寻找，不充当分支或先后关系的证明。

### 单一维护源与保存点

DSH仍保存任务历史、当前绑定和用户接续选择。Bridge在唯一执行状态维护源产生保存/恢复/请求事实，Host和界面消费同一投影。
工程内只保存随HIP移动所需的scene/branch/checkpoint标识及节点恢复定位数据；完整归属与请求记录使用可随工程携带的、带schema的恢复材料。
索引只负责按已记录位置发现材料，可以重建；它不是第二份任务状态或产品完成账本。导入外部材料不能替代本机DSH历史或用户明确接管授权。

保存点必须把三件事关联起来：实际HIP文件、该状态中的节点归属、截至该保存点的执行位置。
保存点不保存另一份聊天摘要，也不声称缓存、HDA库、纹理或外部进程自动随HIP恢复。

1. 主线程在串行执行边界捕获稳定场景与归属快照，为本次保存准备checkpoint ID和父关联。保存前标记只是准备状态。
2. 统一接入动词保存、原生Save/Save As及自动保存；只有保存成功才提交恢复材料。自动保存记录实际副本位置，不将主工程路径改成备份目录。
3. 文件摘要、材料写入与核验放在worker，不在GUI线程做大文件哈希、网络或进程探测。worker核验的必须是捕获的保存版本；文件被后续保存/外部替换时不能把新字节误标为旧保存点。
4. HIP与恢复材料不能假定跨文件原子提交。HIP成功但材料未提交时报告“工程已保存，恢复点未完成”；保留可核对的准备记录，按实际文件和标识补齐或降为证据不足，不能覆盖上一有效恢复点。
5. 保存后产生的新修改不被旧checkpoint覆盖。崩溃只能回到实际保存或可验证自动保存的内容，不能从聊天中的成功回执推断未保存节点仍存在。

只读打开旧工程不为登记身份偷偷保存HIP。旧版无元数据时保持“来源未确认”，首次经授权保存或建立明确恢复基线后才形成完整接续材料。
未保存工程可有临时scene身份与工作目录，但无持久保存点就不能承诺崩溃恢复；找到的crash/backup HIP仍按实际证据评估。

### 接续评估与用户入口

打开工作区或点击旧任务时先做有界的只读接续评估。界面同时显示“当前打开的工程”和“对话对应的工程/最后保存点”，不等模型调用失败才展示英文异常。
评估入口由Host/UI控制，可在旧执行端已失效时读取用户当前明确选择的候选；不通过解除普通工具路由限制来探测任意进程。
没有live响应时仍能展示持久记录及找回入口；超时只是失联，不等于进程已死或请求未执行。

以下是评估结果类别，不是独立存储的一份状态：

| 结果 | 必须成立的事实 | 默认处理 |
|---|---|---|
| 可接续 | 工程/分支和保存点匹配，环境支持，需编辑节点能可信恢复，无未处理的相关请求影响 | 用户正常发送消息后自动接续，给出恢复事实再运行；不要求额外点击或确认技术成功 |
| 可核对后接续 | 同一工程的旧保存点、已知后继、用户改动、自动保存、部分节点缺失或请求影响未知 | 列出与任务最后观察的差异；只读核对后从实际现场继续，必要时局部重做 |
| 当前工程不匹配 | 另一scene/branch、来源冲突，或用户明确打开无关工程 | 优先展示原工程候选；另提供“在当前工程重新开始” |
| 暂不可接续 | 文件/必要依赖缺失、执行合同不兼容、其他作者占用或恢复材料不足 | 展示具体原因及修复、选择其他保存点、手动定位等动作；聊天历史仍可读 |

评估同时给出匹配依据、缺失证据、环境差异、归属可恢复范围和未决请求，不用模糊相似度分数或单个布尔值代替。
“暂不可接续”只限制缺少必要条件的修改，不强制用户重建模型，不把无关缓存缺失当作整任务永久门槛。
来源已确认但网络内容已变化时，工程身份与任务进度分别表达；不因保留scene ID就宣称仍能从旧步骤原样运行。

查找原工程优先使用任务最后成功保存位置、已记录Save As链、保存点材料及工作区内明确候选；路径不存在时允许用户定位。
不扫描全盘、不按“最近修改的HIP”自动开文件。只读定位不需要额外批准；打开/替换当前HIP要保留未保存内容并使用明确的用户动作，不开放raw load/clear。
用户选择在当前无关工程重新开始时，默认建立链接原任务目标的新任务，重新观察现场；原对话仍指向原工程。
“重新开始”不隐含清场、删除或接管当前节点。继续原任务的局部重建，也只针对实际缺失部分和已授权范围。

### 重新连接的提交边界

恢复是一次连接迁移，不是改写旧executor ID。`executor-identity-projection`须按有序绑定代际解释历史：
旧回执保留旧executor/runtime，只有可信接续提交事件才能建立下一代；历史自然出现多个进程不再一律判冲突。
没有对应接续事件的跨目标结果仍视为冲突。新进程永远不会伪装成旧进程。

顺序为：暂停任务的新写入 → 获取当前候选的scene/版本事实 → 评估保存点及请求 → 准备精确归属映射和单作者预留
→ DSH原生事件持久化并flush → Bridge激活新binding epoch → 重新观察现场 → 按用户意图续跑。
准备期间不执行模型修改；提交前再次核对所选session、候选进程/场景代际和评估版本，过期选择返回更新后的事实。
每步用同一恢复操作ID关联，可重入查回；Host在flush前后崩溃时只继续已证实的准备/提交，不重复领权或默默启用半次迁移。
Bridge只接受激活后的新代际请求，拒绝旧Host、旧队列和延迟到达的请求；已入场执行仍按实际回执核对。

旧执行端仅暂时失联时，不自动让另一进程写同一工程。需确认旧写入预留已释放或完成有据可查的交接；不凭心跳杀进程。
当前单实例与共享实例共用这套绑定和工程评估，普通用户无需先启用共享模式。
DSH的Goal、暂停/运行状态和模型循环仍归DSH管理，插件不另建任务调度器，也不在用户仅打开工程时自动重启Goal。

### 节点归属恢复

`hou.Node.sessionId()`只在当前进程内有意义。跨进程恢复必须从已提交保存点的归属记录映射到新HOM identity，写入仍由`dsh_ownership`唯一管理。
最低自动恢复条件是：候选HIP与可信保存点相符、创建归属来自原session执行记录、持久node ID在候选现场唯一且结构定位一致。
节点名称/路径/父网络/userData任意一个都不足以授予归属。旧HIP哈希相同只能证明字节匹配，不能单独证明当前加载后未被修改。

主线程捕获加载基线并校验后才登记映射；其后复制、merge、新建或同路径替换的节点不得从复制标签自动继承旧归属。
重复ID、缺少保存材料、插件未观察的改写及无法证明来源的HDA重建降为待核对/foreign；自动恢复范围不得超过实际证明范围。
对HDA内部重建、Network Box、Sticky Note、控制绑定、组件记录与持久服务分别按其现有维护源恢复，不将根节点归属扩大成所有后代和HDA库权限。
持久render服务保持独立身份和原有禁止豁免规则。

旧版历史没有足够持久身份时，不提供“认领整个工程”补丁。可以读取全工程；修改具体旧节点仍须明确目标的单次allow_foreign，
或从已知可恢复保存点恢复、在新任务/新范围重建。不能把用户一句“继续”解释为任意已有节点的永久所有权。
显式独立分支在创建时记录来源；如由新session维护，只能在用户分支动作授权的精确映射范围内建立独立归属，不能共享作者身份。

### 未完成请求与真实进度

请求接收、开始、完成及job终态由Bridge维护；恢复消费原回执和DSH历史，不另造Host推测账本。
当前不新增逐请求持久日志或任意操作的恰好一次协议：旧进程退出且无终态证据时保留未知，按现场核对。
若将来要求跨崩溃证明“未执行”，必须另有先于HOM入场的可靠持久证据；缺少记录本身不能证明未执行。

| 可获得的证据 | 恢复后的解释 |
|---|---|
| 确认未入场/已取消的原请求 | 保留未执行终态；仍需在新现场重新规划、签发新请求 |
| 旧进程仍可访问的原回执 | 查回原结果，不重发代码 |
| 持久完成回执 | 确认当时执行过；另查结果是否进入当前加载的保存点 |
| 旧进程已结束、请求在途或缺终态 | 标记执行中断且影响未知；不在新进程轮询旧job，也不报告“未执行” |
| 工程恢复到较早保存点 | 区分当时执行成功和当前HIP不含该修改；核对后按需重做 |
| 缓存/文件/外部进程可能留有副作用 | 单独核对输出和进程；不能用HIP回滚推断副作用已消失 |

恢复操作可把旧请求从“仍在活动”归档为“旧运行已终止、影响待核对”，保留原证据和不确定性。
未知项只限制会重复产生其副作用或依赖其结果的动作；只读诊断、无关操作仍可进行，不让一个已死job永久卡住整个对话。
不承诺任意Python/外部副作用的恰好一次执行；不把历史全量重放当作恢复算法。

### 另存、分支与版本升级

- **普通Save As与HIP递增版本**：默认保持scene/branch和当前任务，生成新checkpoint并记录父保存点；当前绑定跟随成功保存的新路径，原文件保留原保存点。保存失败不迁移绑定。自动备份不成为当前任务的默认新路径。
- **侧栏归属**：只迁移当前对话，原目录里的其他对话和原工作区登记保留；即使迁移后没有对话，也不因另存删除工作区。不默认在两处放置同一对话或复制历史，避免旧位置看似独立却仍修改新工程。需要两份方案分别继续时，属于显式独立分支，不把普通Save As自动解释成分支。
- **跨目录Save As**：主线程确认当前HIP保存成功后，下一模型/工具步骤自动通过DSH原生迁移跟随文件目录；原对话ID和历史保持，新目录的文件范围、工程说明、附件搜索与工作区归属同源更新。仅改文件名、保存失败、备份路径或打开无关工程不能触发跟随。崩溃接续则使用已验证并激活的保存点。插件只消费执行事实并调用原生迁移，不私造会话副本；中断提交由DSH自动完成。物理历史位置及依赖文件不搬运，软件回退边界见[DSH适配](dsh-update-compatibility.md)。
- **共享写入预留转移**：受管Save As先取得新目标预留再保存，提交新绑定后释放旧预留；失败保留实际文件/预留事实待核对。原生GUI外部Save As若未经过预留，捕获变化后暂停Agent新写入并核对冲突，不能宣称插件拦住全部GUI保存。
- **显式独立分支**：记录原分支和保存点，产生新branch及独立任务入口；分支归属采用上述精确授权映射。两个副本不默认为两个可同时写的作者，也不复制账户/设置或共用运行身份。
- **加载旧版本/备份**：显示当前保存点落后于对话最近事实；允许回到此处接着做，记录新的接续基线，后续保存保留真实父关系。旧结果保留为历史，不混入当前现场。
- **Houdini升级**：工程ID保持；核对目标版本支持、HDA/插件/节点类型和必要依赖，对实际任务输出做相称的cook/控制检查。加载成功不等于几何或语义相同；没有识图仍写视觉未验证。降级按真实兼容性判断，不猜测可逆。
- **插件/DSH升级**：沿[受管安装](setup.md)与[兼容门](dsh-update-compatibility.md)保存/迁移原生会话及恢复schema，重新握手执行合同。版本号变化本身不创建新工程、不清掉历史绑定、不豁免ownership；不支持的schema/合同显示可用版本或迁移路径。各版本数据和回退能力仍按安装合同验证。

5. 重命名、复制重复node ID、同路径替换、foreign后代、HDA内部重建与持久render服务；精确恢复不扩大授权。
6. 恢复时Host重启、点击重复、场景被切换、旧端晚回包和另一作者占用；最多一个已激活绑定，旧代际不能写入。
7. HIP递增版本、支持的Houdini升级、精确插件/DSH升级和回退；历史原生/嵌套回执及旧节点交付引用保留原身份，新映射必须来自接续事实。
8. 无元数据的旧HIP、未保存场景、材料丢失或实际缺依赖；显示可执行路径，不能将“不能自动恢复”变成对话永久不可用。
