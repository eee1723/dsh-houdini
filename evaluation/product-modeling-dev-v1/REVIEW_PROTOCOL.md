# 程序化产品模型开发测试集 V1

这是公开的开发题，用来定位系统在读图、建模细节、参数修改与验收上的短板。题目已知，**不能用它的进步声称对未见产品的泛化能力**。本目录不接收费模型或 Houdini 自动评分。

## 执行与隔离

- 先运行 `node evaluation/product-modeling-dev-v1/scripts/validate.mjs`。它只检查题目、文件与隔离规则，不评价模型质量。
- 用 `node evaluation/product-modeling-dev-v1/scripts/prepare-run.mjs --case task-lamp-build` 创建单题工作目录。默认位置在系统临时目录，支持 `--out <绝对路径>`。若试跑会使用组件委派，须用 `--out` 指定仓库外且系统临时目录外的新目录；组件执行端会拒绝临时目录。执行 agent 只接收该目录的 `brief.md`、`attachments/` 和 `task.json`，不接触本源目录。准备脚本只负责复制文件，**并不是文件访问沙箱**；运行者还必须把 agent 的可读工作区限制在隔离目录，确认它无法浏览本仓库后再开始，做不到则该次结果不能用于盲评。
- `task-lamp-change` 需要上一步真实保存的 HIP：加 `--baseline-hip <绝对路径>`。准备脚本会复制此 HIP，并在 `task.json` 记录 SHA-256。不要把前一步文字回答冒充工程基线。
- 同一对照实验固定执行模型和版本、工具/运行态、时间与总预算、输入图、评审步骤。保留原始轨迹与失败；不要重试到满意后只留最好的一次。

## 人工独立评审

1. 评审者看对应 `evaluator-only/checklist.json`，**不要**把它或本协议中的评审要求送给执行 agent。先登记源材料、运行信息和 agent 交付物。
2. 建模题必须从最终保存的 HIP **独立重开**，由评审者重新渲染固定整体视角和关键局部；参数题同时独立打开所提供的基线 HIP，保持前后相机、画幅和焦距一致。无法重开或无法取得某张图，记 `unverified`，不能用 agent 自交截图代替。
3. 在副本中扰动公开要求的主要控制，再核对零件、连接、细节是否随动。记录控制值、测量和扰动前后图片。完成后不改动原始交付文件。
4. 先看独立图片与测量，再读 agent 的完成报告。逐项给 `pass`、`fail` 或 `unverified`，附证据位置和一句理由。重要零件断开、局部看不清、证据缺失都不能凭“节点无报错”或“面数很多”判通过。
5. 结果按 `review-result.schema.json` 保存。`agentSubmitted` 与 `reviewerProduced` 分开记；两者冲突时保留原记录，并说明差异。保存后在评审侧运行 `node evaluation/product-modeling-dev-v1/scripts/validate-review.mjs <评审结果.json>`，核对案例、清单项和证据引用。此命令会读取仅供评审看的清单，只能在评审环境运行；不要将脚本、清单或校验输出交给执行 agent。它只验记录完整性，不判断视觉质量。此 V1 只有人工判断，不得标成自动视觉评分或正式 benchmark 分数。

读图诊断题不需要 HIP；评审者直接用原图核对回答。文字仪器箱、旋盖水瓶、桌面台钳与桌面收纳盒题没有参考图，按公开尺寸与结构需求审查。旋盖水瓶的瓶口有意敞开，评审时不要将其误判为破洞；须分别检查内外壁朝向、封底和合盖配合。桌面台钳须在保存的 HIP 副本中独立检查合拢、中间、打开三个状态：分别记录两侧夹爪到测试块的接触或间隙，并看滑动夹爪、导向结构和传动件是否保持关系。桌面收纳盒须独立检查合上、半开、充分打开时前缘的接触或间隙、铰链的同轴连接和内腔表面。贴合距离为零只说明几何接近，不说明已产生夹紧力或锁止力；单一状态或局部部件的检查不能替代运动中的整件检查。检查清单中的措辞是评审辅助，不是给 agent 的额外任务。

`task-lamp-build` 与 `task-lamp-build-guided` 是成对的开发对照：前者只给图和通常的用户要求，后者由用户直接列明可见部件、连接和关键细节。两次固定同一模型、环境、总预算与评审视角，不把评审清单当作给执行 agent 的提示。`task-lamp-elbow-focus` 只测试一个局部关节，运行前单独约定时限；它的局部质量不能直接与整灯总分比较。当前案例都是已知开发题，新的未见题需要另外保管和封存。
